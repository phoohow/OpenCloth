# 文档规范

本篇规定文档的写作规范，表述前加（*）的部分只对开发文档有约束。

## 1. 格式

### 1.1 标题

- 最深四级：`#` 为篇名，`##` 为编号章节，`###` 为小节，`####` 为小节内的并列子主题，编号为 `x.y.z`。
- 四级标题可用于小节内有两三块各自成篇的内容。

### 1.2 列表

- 需要描述三件及以上同类事项时，改为列表。三项以下不设为列表。
- 需要枚举三件以上取值或落点时，改为列表或表格。三项以下不设为列表。
- 一个列表项只承载一个语义单位。多个语义单位的话考虑拆分。

### 1.3 强调与备注

- 易错点、后果、约束与待补项以引用块单独成条。
- 标签只用 `> **注**：…`（提示会出错的地方）与 `> **说明**：…`（中性补充）。
- 不使用 emoji。
- 不将提醒放到正文句子中间。
- 单条引用块不超过两句。

### 1.4 引用

- 引用一律指向编号章节，例如 03 §6.3。
- 修改标题编号时，同步重指所有引用。
- 各篇覆盖范围只在 [README](../README.md) 的文档索引中列出一次。

### 1.5 单位

- 带单位的名称写作 `名称(单位)`：括号半角、紧贴名称，数值跟在其后并空一格，例如 `长度(cm) 12.5`、`旋转(°) 30`。

### 1.6 符号

- 正文标点用全角 `：`、`；`，代码、路径与英文短语内用半角 `:`、`;`。
- 流程指向使用箭头统一写作 `→`，不写 `->`。
- 注释不使用 `——`，若有需要使用 `()` 。
- 界面名称统一用【】，该符号只能用于界面名称。

## 2. 内容

### 2.1 结构

- 每篇文档按总—分结构组织：开头给出系统或模块的整体轮廓与章节顺序，正文按该顺序描述。
- 每个章节的结构组织同文档。

### 2.2 交叉指引

- 跨篇指引直接写在需要它的那句话里。

### 2.3 语义

- 描述简洁。可以用简单词汇或者短语表达清楚的，不使用句子。
- 描述直，用词不生僻。
- 描述仅限于当前的对象概念，功能，流程。
- 描述不涉及审阅意见、修改过程与设计动机的说明。

### 2.4 语域

- 使用专业书面语。
- 使用陈述句与无人称句式。
- 不使用不常见的表述。
- 不使用口语转折。
- （*）不使用比喻描述对象和事件。

### 2.5 （*）与代码同步

- 字段、章节中写到的测试数、快捷键条数、方法数等发生变化时，在同一次改动里更新相应篇目。
- 引用的数字与代码核对。
- 代码注释规范见 [00-开发指南](./dev/00-开发指南.md) §4.4。
