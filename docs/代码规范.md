# 代码规范

本篇约束仓库内的代码：TypeScript、React、WGSL、注释、静态检查与提交信息。

## 1. 设计原则

1. **层依赖单向、无环。** 依赖只沿一个方向跨层，上层可引用下层，下层不得引用上层；任意两层之间不得形成环路。
2. **层封装以入口文件为界。** 每层对外只暴露三类入口：层根门面（`index.ts`，含实现与生命周期）、子目录门面（`<dir>/index.ts`）、公共面（`common`，只含类型、常量、端口接口、不依赖实现的纯函数与能力探测）。跨模块 import 必须命中目标的 `index.ts` 或 `types.ts`，不得指向具体实现文件；`common` 可被其他层引用，但不得依赖本模块的实现代码。
3. **数据流单向、无环。** 数据只沿一个方向跨层传递，不形成回流传导；需要反馈的信息以返回值或状态比较获得，不建立反向通道。
4. **对象由上层持有。** 上层持有其依赖的下层对象，并负责其创建与释放；下层不持有上层对象。

## 2. TypeScript

`tsconfig.json` 配置：

- `strict: true`，并启用 `noUnusedLocals` / `noUnusedParameters` / `noFallthroughCasesInSwitch`。
- `moduleResolution: "bundler"`，`lib` 为 ES2022 + DOM + DOM.Iterable，`types` 为 `vite/client` 与 `@webgpu/types`。
- `include` 覆盖 `src`、`test`、`e2e` 目录，`noEmit` 只做检查。

> **注**：测试与 e2e 代码的类型错误同样阻止 `npm run build`。

- 禁用 `any`（`@typescript-eslint/no-explicit-any` 报错）；跨形态桥接使用具体联合类型或可选字段。
- 对象类型用 `interface`，联合与工具类型用 `type`；对外类型写 `export type` / `export interface`。
- 命名：类型与组件 `PascalCase`，变量与函数 `camelCase`，常量 `UPPER_SNAKE_CASE`，文件与目录一律 `camelCase`。
- `paths` 中的 `@/* → src/*` 与 Vite 的 `@` alias 均已配置；跨模块 import 统一使用 `@/模块/...`，同模块内部可用相对路径。
- 向量只用 `base/math` 的 `Vec2`/`Vec3`/`Vec3Tuple` 表示、运算与 `AXIS_*`/`ZERO*` 常量，不另立 `Point3`/`Triple`/`XYZ`/`UP` 等别名，也不在业务文件里就地展开分量运算。

## 3. 文件结构

本节约束每个 `.ts` / `.tsx` 文件内声明的排列顺序，`npm run style:check` 会逐条检查。

### 3.1 骨架

```
文件头注释（如有）
import type 块
值 import 块
转口（export ... from）
常量
类型（interface / type）
函数 / class
其他语句（如 declare global）
```

- 各块之间空一行，块内相邻声明之间也空一行；import 块内不空行。
- 转口段位于 import 与常量之间，barrel（只做转口、没有声明）除外。
- 空块直接省略，不留占位空行。

### 3.2 import

- 只分两块：`import type` 全部在前，值 import 在后。
- 块内按模块路径字符串升序（ASCII），因此 `@/` 排在外部包之前；同一路径的多条 import 保持原相对顺序。
- `import { a, type B } from '...'` 属于值 import，内联 `type` 不拆成单独的 `import type`。
- 副作用 import（`import './index.css'`）按值 import 参与排序。
- import 区只放 import，不得出现 `export ... from`。

### 3.3 常量

- 常量区只放**数据常量**：初始化表达式是字面量、对象、数组或调用结果的 `const`，保持原有声明顺序。
- 箭头函数与函数表达式的 `const` 属于函数，归函数区，不与数据常量混排。
- 常量标注本文件下方声明的类型属正常写法，依赖 TS 的类型提升，不必为对齐顺序而调换。
- 只在单个函数内使用的字面量不提到模块级。

### 3.4 类型与函数

- 类型区按原声明顺序排列 `interface` 与 `type`。
- 函数区按原声明顺序排列 `function`、`class` 与函数式 `const`；同名重载必须相邻。
- 例外：初始化表达式实例化本文件 `class`、或调用本文件函数式 `const` 的数据常量（如 `const registry = new Registry()`、`const CURSOR = glyph(true)`），放在函数区之后，避免 TDZ。
- 新增的顶层声明按上述分区插入，不追加到文件中部。

### 3.5 导出

- 对外开放的声明直接在声明处写 `export`：`export const` / `export function` / `export class` / `export interface` / `export type`。
- 不使用文件末尾的 `export { ... }` 汇总块：一处声明一处导出，读完声明即知对外面。
- 转口语句（`export ... from`）单独成段，紧跟 import 之后，按模块路径升序；同一路径的命名转口合成一条，纯类型时写 `export type { ... } from '...'`。
- 需要把 import 进来的名字再导出（类型门面、转发工具函数），写 `export { X } from '<原路径>'`，不要写成 `import` 加末尾 `export { X }` 两段。
- 不使用 `export default`。
- `/* wgsl */`、`// eslint-disable-next-line` 等标记随所属声明一起移动，不留在原位置。

### 3.6 barrel

- `index.ts` 只做转口，统一 `export * from '@/x'`，按模块路径升序。
- 仅在跨模块重名需要裁剪时才写显式命名导出，并与 `export *` 一起排序。

## 4. React

函数组件加 Hooks，不使用 class 组件。

一个文件一个主组件，Props 类型写 `interface XxxProps`。状态与副作用的归属：

- 全局状态走 zustand。
- 局部 UI 状态用 `useState`。
- 副作用用 `useEffect`。

`// eslint-disable-next-line react-hooks/exhaustive-deps` 标记的是仅在挂载时建立一次的 effect（WebGPU 视口初始化、画布取景）。

> **注**：补全依赖数组会触发上下文或监听器重建，这些标记要保持有效。

## 5. WGSL

没有独立的 `.wgsl` 文件，全部为 TypeScript 模板字符串常量，命名与位置固定：

- 常量名 `XXX_WGSL`，一个 pass 一个文件，集中在 `src/sim/device/shaders/`。
- `src/sim/device/programs.ts` 只引用这些常量建管线；`src/sim/device/pack.ts` 负责所有写进 shader 的字节布局（uniform 块、约束 16 字节 stride、粒子 vec4），只在自己的注释里说明对齐，不持有 shader 源。
- 常量前保留 `/* wgsl */` 标记供编辑器高亮。

约束：

- `tsc` 不校验 WGSL 语法。非法 WGSL（例如三元表达式，必须写成 `select(c, b, cond)`）不抛错、不进控制台，只使 pipeline 失效并丢弃整次 `submit`，表现为版片在模拟启动后消失；修改 shader 后需在浏览器中确认回读位置非零。
- 结构体字段按 16 字节对齐，隐式 padding 会造成读数错位。
- 每个 pass 只声明并绑定自己用到的数组，没有共享的粒子结构体。

## 6. 静态检查

- `@typescript-eslint/no-unused-vars` 报错：未使用的变量、参数、导入与 catch 绑定；`_` 前缀的除外。
- `no-debugger` 报错；`no-console` 只允许 `warn` / `error`，其余为警告（`src/tools/` 与 `src/runtime/engine/engineTiming.ts` 例外）。
- `react-hooks/rules-of-hooks` 报错、`react-hooks/exhaustive-deps` 警告。
- 文件结构由 `npm run style:check` 校验（`scripts/check-style.mjs`，已并入 `npm run arch:check`）：import 分块与排序、常量/类型/函数顺序、末尾导出、barrel 纯度。
- 同一脚本顺带报告跨文件的常量重名：同名同值视为重复定义并判定失败，同名不同值与同值不同名只作提示。

## 7. Git 提交

只有 `main` 一条分支，提交直接落在其上；提交信息用 Conventional Commits：

```
<type>(<scope>): <subject>

type: feat | fix | docs | style | refactor | perf | test | chore
scope: core | pattern | sim | render | ui | store | io | avatar | docs
```

用简单句或者短语描述一个 scope，内容用中文描述。
多个 scope 用逗号连写，例如 `feat(sim,ui): ...`。
