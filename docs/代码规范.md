# 代码规范

本篇约束 `src/` 下的 TypeScript、React 与 WGSL 代码，以及 ESLint 与提交信息的既有约定。注释规则以 [AGENTS.md](../AGENTS.md) 为准。

## 1. TypeScript

`tsconfig.json` 配置：

- `strict: true`，并启用 `noUnusedLocals` / `noUnusedParameters` / `noFallthroughCasesInSwitch`。
- `moduleResolution: "bundler"`，`lib` 为 ES2022 + DOM + DOM.Iterable，`types` 为 `vite/client` 与 `@webgpu/types`。
- `include` 覆盖 `src`、`test`、`e2e` 三个目录，`noEmit` 只做检查。

> **注**：测试与 e2e 代码的类型错误同样阻止 `npm run build`。

- 禁用 `any`；跨形态桥接使用具体联合类型或可选字段。
- 对象类型用 `interface`，联合与工具类型用 `type`；对外类型写 `export type` / `export interface`。
- 命名：类型与组件 `PascalCase`，变量与函数 `camelCase`，常量 `UPPER_SNAKE_CASE`，文件与目录一律 `camelCase`。
- `paths` 中的 `@/* → src/*` 与 Vite 的 `@` alias 均已配置；跨模块 import 统一使用 `@/模块/...`，同模块内部可用相对路径。

## 2. React

函数组件加 Hooks，不使用 class 组件。

一个文件一个主组件，Props 类型写 `interface XxxProps`。状态与副作用的归属：

- 全局状态走 zustand。
- 局部 UI 状态用 `useState`。
- 副作用用 `useEffect`。

`// eslint-disable-next-line react-hooks/exhaustive-deps` 标记的是仅在挂载时建立一次的 effect（WebGPU 视口初始化、画布取景）。

> **注**：补全依赖数组会触发上下文或监听器重建，这些标记要保持有效。

## 3. WGSL

没有独立的 `.wgsl` 文件，全部为 TypeScript 模板字符串常量，命名与位置固定：

- 常量名 `XXX_WGSL`，集中在 `src/sim/shaders/shaders.ts`。
- `src/sim/gpuPipelines.ts` 只引用这些常量建管线；`src/avatar/collider/avatarCollider.ts` 只在自己的注释里说明结构体对齐，不持有 shader 源。
- 常量前保留 `/* wgsl */` 标记供编辑器高亮。

三条约束：

- `tsc` 不校验 WGSL 语法。非法 WGSL（例如三元表达式，必须写成 `select(c, b, cond)`）不抛错，只使 pipeline 失效并丢弃整次 `submit`，表现为版片在模拟启动后消失。
- 结构体字段按 16 字节对齐，隐式 padding 会造成读数错位。
- 每个 pass 只声明并绑定自己用到的数组，没有共享的粒子结构体。

> **注**：WGSL 语法错误不会出现在 `typecheck` 结果或控制台里；修改 shader 后需在浏览器中确认回读位置非零。

## 4. 注释

以 [AGENTS.md](../AGENTS.md) 为准：

- 注释只用英文。
- 只描述代码在做什么，不记录修改过程、不使用“之前 / 现在”对照、不复述代码。
- 导出的类、函数、接口字段用 1–2 句 `/** ... */`，代码块用一行 `//`。
- WGSL 源码与中文界面字面量属于代码，不翻译也不改写。

## 5. 分层与依赖守卫

### 5.1 分层

依赖只能向下，不能反向；同层模块之间默认不互相 import。

| 层 | 目录 | 允许依赖 |
| --- | --- | --- |
| L0 | `common/` | 标准库与纯第三方工具；不 import 任何业务模块、`three`、React、zustand |
| L1 | `model/`、`pattern/`、`avatar/`、`sim/`、`analysis/` | `common`、本层必要的领域契约 |
| L2 | `render/`、`io/` | L0、L1 |
| L3 | `runtime/`、`commands/` | L0～L2 |
| L4 | `store/`、`ui/` | L0～L3 的公开接口 |
| L5 | `api/`、`tools/`、`main.tsx` | 全部（组合根） |

公共层按子模块提供门面（`common/math`、`common/geom`、`common/platform` 等），不设一把全量 re-export 的总出口。跨模块 import 一律写 `@/模块/子模块` 别名并命中目标的 `index.ts` / `types.ts`；同模块内部文件可以直接引用。

### 5.2 自动化守卫

- `npm run arch:report`：输出依赖矩阵、向上违规边（`upwardEdges`）、文件级环（Tarjan）、深相对导入、`common` 层禁用依赖。
- `npm run arch:baseline`：目录结构调整后重建 `scripts/architecture-baseline.json`；白名单在 `scripts/architecture-allowlist.json`，只减不增。
- `npm run arch:check`：对照基线检查，违规即失败；接入 CI 与 `test/architecture/layers.test.ts`。
- ESLint `no-restricted-imports` 同时匹配 `@/模块` 与相对路径前缀：`model` 禁 `pattern`/`ui`/`render`/`sim`/`io`，`pattern`/`sim` 禁 `ui`，`runtime`/`commands` 禁 `ui`/`store`。规则不豁免 `import type`。

当前门禁目标：`upwardEdges = 0`、文件级环 `0`、深相对导入 `0`、跨域绕过门面 `0`、`commonForbidden = 0`、单文件 ≤ 1000 行。这些数字由 `scripts/check-architecture.mjs` 实测，不靠人工核对。

### 5.3 语言约定

- `@typescript-eslint/no-unused-vars` 报错：未使用的变量、参数、导入与 catch 绑定；`_` 前缀的除外。
- `@typescript-eslint/no-explicit-any` 报错。
- `no-debugger` 报错；`no-console` 只允许 `warn` / `error`，其余为警告（`src/tools/` 与 `src/runtime/engineTiming.ts` 例外）。
- `react-hooks/rules-of-hooks` 报错、`react-hooks/exhaustive-deps` 警告。
- 模板卡片的图标键在 `pattern/template/garmentTemplate.ts` 用字面量联合 `TemplateIcon` 声明，UI 侧按 `IconName` 的子集使用。

## 6. Git 提交

只有 `main` 一条分支，提交直接落在其上；提交信息用 Conventional Commits：

```
<type>(<scope>): <subject>

type: feat | fix | docs | style | refactor | perf | test | chore
scope: core | pattern | sim | render | ui | store | io | avatar | docs
```

多个 scope 用逗号连写，例如 `feat(sim,ui): ...`。
