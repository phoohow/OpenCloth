# 数据模型

这篇是字段手册：每个字段的语义、谁读取它、写入后影响什么，以及旧工程文件如何被归一化回可用状态。类型定义在 `src/core/model/types.ts`，默认值、预设与归一化在 `defaults.ts`，材质槽查询在 `fabric.ts`。

一个工程就是一份 `Project`，装着一件服装的全部 2D 结构、面料、模特与场景设置。实体之间一律用 id 引用而不是对象嵌套，因此一次编辑只替换最小的一层。

章节顺序依次为：实体关系（§1）、单位与 id（§2）、基础几何（§3）、版型（§4）、缝合（§5）、面料（§6）、人体（§7）、场景（§8）、事件（§9）、工程与序列化（§10）。

## 1. 实体关系

`Project` 的顶层是四个集合（版型、面料、人体、场景）加一份文件头，集合内部靠 id 互相指向：

```
Project
├── meta: ProjectMeta                 # 文件头（名字、创建与修改时间）
├── pattern: Pattern                  # 一件服装的全部 2D 结构
│   ├── points:  Record<id, PatternPoint>      ┐
│   ├── edges:   Record<id, PatternEdge>       │ 边引用点，片引用边
│   ├── darts:   Record<id, Dart>              │
│   ├── internalLines: Record<id, InternalLine>│
│   ├── notches: Record<id, Notch>             │
│   ├── annotations: Record<id, Annotation>    │
│   └── measurements: Record<id, Measurement>  ┘
│   ├── panels:  Record<id, Panel>      ── fabricId ──► Fabric
│   │                                   ── drape/placement/transform ──► 初始摆放
│   └── seams:   Record<id, Seam>       ── a/b 区间端 ──► PatternEdge
├── sizes?: SizeDef[]                 # 尺码表（基码 + 顺序）
├── activeSizeId?: string             # 当前几何解析到的码
├── fabrics: Record<id, Fabric>       # 外观 + 物理，可被多片共用
├── avatar: Avatar                    # 单个模特：内置/导入/程序化 + 体型
└── scene: SceneConfig
    ├── lights: LightConfig           # 光源列表 + 环境图
    ├── render: RenderConfig          # 显示模式、色调映射、光追参数
    ├── simulation: SimulationConfig  # 重力、风、步长、迭代、网格、厚度、自碰撞
    ├── referenceObjects?: ReferenceObjectRef[]
    └── cameraName?: string           # 相机行名；机位与视野仍是视口状态
```

引用全部是 id 字符串（`Record` 的键），没有对象嵌套。

> **注**：选中项、播放进度、相机机位等运行时状态不在 `Project` 里，见 [06-UI与状态管理](./06-UI与状态管理.md) §1；它们不进工程文件，也不受撤销历史管辖。

## 2. 单位、坐标与 id

同一份数据里并存两套长度单位与两套角度显示，换算只在明确的边界发生：

| 约定 | 内容 | 换算发生地 |
| --- | --- | --- |
| 制版长度 | 厘米（cm） | 建 3D 位置时 `× 0.01` 转米（`PanelBuilder.to3D()`） |
| 世界长度 | 米（m） | 属性面板按米显示，写入即米 |
| 2D 坐标 | X 向右、Y 向上，原点由取景决定 | `ui/viewport2D/viewMath.ts` |
| 3D 坐标 | 右手系，Y 向上，与 Three.js 一致 | — |
| 旋转 | 弧度、XYZ 顺序存储 | 属性面板显示为度（`ui/panels/properties/constants.ts`） |
| 克重 | g/m² | 换算成逐粒子逆质量（04 §5.4） |
| 时间 | 秒；`dt` 固定 1/60 | 柔度换算按 60 Hz 归一（04 §1.3.2） |

id 形如 `panel_l_1m2k3`：`genId(prefix)`（`defaults.ts:10`）= 前缀 + 自增计数 + 时间戳，不是 UUID。同一会话内自增计数保证唯一，跨会话靠时间戳区分。

- id 写进工程后不再变化：模板「应用」与「追加」直接沿用模板生成的 id（[05-版型系统](./05-版型系统.md) §4.2），只有版片粘贴会重新分配（`PastePanelsCommand`，[06-UI与状态管理](./06-UI与状态管理.md) §3.2）。

## 3. 基础几何类型

向量与变换类型只有四个，其余实体复用它们：

```typescript
/** 制版坐标下的点（cm）。 */
interface Vec2 { x: number; y: number; }
/** 世界坐标（m）。 */
interface Vec3 { x: number; y: number; z: number; }
/** 场景对象摆放：位置（m）、旋转（弧度 XYZ 顺序）、逐轴缩放。 */
interface ObjectTransform { position: Vec3; rotationEuler: Vec3; scale: Vec3; }
/** 版型片的平铺摆放姿势，不含缩放。 */
interface PanelPlacement { position: Vec3; rotationEuler: Vec3; }
```

- `Vec2` / `Vec3` 与 `vec2()` / `vec3()` 构造器定义在 `types.ts`；`pattern/geom/vec2.ts` 是围绕它们的纯函数集合（见 05 §1.1）。
- `transform?: ObjectTransform` 出现在版型片、人体、参考物体三处，缺省即单位变换；`IDENTITY_TRANSFORM` 与 `cloneTransform()` 在 `defaults.ts:15,22`。

曲线与圆弧的控制数据都存储在点上或边的几何参数中（§4.2）：三次曲线由边的两个端点加点上的 `handleOut`、`handleIn` 构成（绝对制版坐标，不是相对偏移）；圆弧存圆心、起止角与走向。求值、分裂与自适应采样见 [05-版型系统](./05-版型系统.md) §1.2。

## 4. 版型（Pattern）

版型层由八个集合组成：点、边、省道、内部线、刀口、注释、尺寸标注、版片，另有缝合列表（§5）。点与边构成轮廓，片按顺序引用闭合的边。

### 4.1 顶点

```typescript
type PointKind = 'corner' | 'smooth';
interface BezierHandle { x: number; y: number; }   // 绝对制版坐标下的控制点
interface PatternPoint {
  id: string;
  name?: string;          // 自定义行名，缺省按种类显示「点」
  pos: Vec2;              // 制版坐标（cm）
  construction?: boolean; // 辅助构造点，不属于裁片轮廓
  kind?: PointKind;       // 缺省按 corner 处理
  handleIn?: BezierHandle;  // 终止于本点的曲线边的控制柄
  handleOut?: BezierHandle; // 起始于本点的曲线边的控制柄
  grading?: Record<sizeId, Vec2>; // 相对基码的放缩量（cm）
}
```

轮廓点由 `Panel.outlineEdgeIds` 间接引用。`construction` 为真的点不属于任何轮廓，只随复制操作一起复制（`panelClipboard.ts:102`），三角化与 2D 视图都不把它当轮廓。

- `smooth` 点的两个控制柄关于 `pos` 互为反向，拖动一侧会镜像另一侧（`SetPointHandleCommand`）；`corner` 点两侧独立，可以只有一侧存在。
- `grading[sizeId]` 只在放码时读取：`resolveSize()` 把它加到 `pos` 上得到目标码的几何，曲线控制柄按两端点档差的平均值平移（05 §7）。

### 4.2 边

```typescript
type EdgeType = 'line' | 'bezier' | 'arc';
interface ArcGeom {            // 三点定弧后解析出的圆心式参数
  center: Vec2; radius: number;
  startAngle: number; endAngle: number; ccw: boolean;
}
interface PatternEdge {
  id: string;
  name?: string;              // 自定义行名，缺省取语义名或类型名
  type: EdgeType;
  startPointId: string;
  endPointId: string;
  arc?: ArcGeom;              // type === 'arc'
  semantic?: EdgeSemantic;    // 边的服装学角色
  seamAllowanceCm?: number;   // 覆盖片级缝份
  cornerStyle?: 'miter' | 'round' | 'bevel'; // 毛边外扩时的角处理
}
type EdgeSemantic =
  | 'hem' | 'neckline' | 'armhole' | 'sideSeam' | 'shoulder'
  | 'sleeveCap' | 'waist' | 'dart' | 'internal' | 'free';
```

一条边同时服务所属片的轮廓（`outlineEdgeIds` 有序引用）与缝合关系（`Seam.a/b` 的 `edgeId`）。

- 曲线形状不在边上：`type: 'bezier'` 的边读取两端点的 `handleOut` / `handleIn`。
- 在边上加点会把它替换成两条同 `semantic` 的新边，曲线用 `splitBezier` 分裂、圆弧按角度切分，缝合区间按弧长比例落到对应子段（`AddPointOnEdgeCommand`）。
- `semantic` 的读取方是模板构造、离线预览的按角色着色与 2D/场景树的中文标签（`tools/clothPreview.ts`、`sceneTree.ts`）。

### 4.3 省道、内部线与生产标记

```typescript
interface Dart {            // 尖端 + 两条边围成的楔形，意图是缝合时闭合出立体曲面
  id: string; name?: string; tipId: string; edge1Id: string; edge2Id: string;
  intakeCm: number;         // 省量（cm）
  closing?: boolean;        // 收省：求解器把两条省边逐点缝上（进入约束签名）
}
interface InternalLine {    // 片内分割/折痕/装饰线
  id: string; name?: string; kind: 'fold' | 'decor' | 'split'; points: Vec2[];
}
/** 边上的刀口/钻孔标记。 */
interface Notch { id: string; name?: string; edgeId: string; t: number; widthMm?: number; style?: 'v' | 't' | 'drill'; }
/** 片上的文字注释；`name` 只覆盖场景树行名，`text` 仍是画布内容。 */
interface Annotation { id: string; name?: string; panelId: string; text: string; pos: Vec2; angleDeg?: number; sizeMm?: number; }
/** 尺寸线：数值不入库，按引用从几何实时量出。 */
interface Measurement { id: string; name?: string; panelId: string; kind: 'distance' | 'edgeLength' | 'angle'; refs: MeasurementRefs; }
```

这三类都进入 2D 绘制、导出与命令层：

- 省道由 `CreateDartCommand` 在轮廓上插入省尖并改写两条省边，`TransferDartCommand` 绕省尖转移省量，`MoveDartTipCommand` 拖动省尖；2D 以虚线楔形绘制，DXF 写在省道层。`closing: true` 时求解器把两条省边逐点缝上（收省）。
- 内部线由 `AddInternalLineCommand` 写入并校验必须完全落在片内，`OutlineSplitCommand` 用切割折线把片一分为二；`kind: 'fold'` 在模拟里表现为折痕。
- `Notch` / `Annotation` / `Measurement` 分别由 `CreateNotchCommand`、`CreateAnnotationCommand`、`CreateMeasurementCommand` 创建，属性面板可编辑并删除，导出 DXF/SVG 时各成一层。
- 尺寸标注的读值统一由 `measurementValue()` 计算（`pattern/geom/edgeSample.ts`），2D 标签与属性面板、各码数值表都调用它，误差即几何误差。

> **注**：复制、移动、删除时这些引用被完整维护（`panelClipboard.ts`、`patternMoveGeometry.ts`、`DeleteElementsCommand`）。`intakeCm` 只参与省道绘制与转移时的几何摆放，闭合成型由省边本身的区间约束完成（`Dart.closing` → `constraintSignature` 的省边缝合对），所以改省量不会自动重算已经画好的两条省边。

### 4.4 版型片

```typescript
interface Panel {
  id: string;
  name: string;                       // 「前片」「左袖」
  outlineEdgeIds: string[];           // 首尾相连的闭合轮廓
  dartIds: string[];                  // §4.3
  internalLineIds: string[];          // §4.3
  holes?: string[][];                 // 镂空环，每环一条有序边 id 列表
  seamAllowanceCm: number;            // 片级缝份量（cm），0 表示无
  fabricId: string;                   // 材质槽；空串或悬空 = 未指定
  meshResolutionCm: number;           // 本片的目标网格边长（cm）
  placement?: PanelPlacement;         // 平铺摆放（与 drape 二选一）
  transform?: ObjectTransform;        // 相对自身中心的场景偏移
  drape?: PanelDrape;                 // 环绕人体摆放（几何含义见 05 §5.2）
  grainAngleDeg?: number;             // 布纹线方向，从版型 X+ 逆时针计
  grainOffset?: Vec2;                 // 布纹线中点相对轮廓包围盒中心的偏移（cm），缺省 0 回正中
  grainLengthCm?: number;             // 布纹线段长度（cm），缺省或 0 按短边 60% 自动
  symmetry?: { axisEdgeId: string; linkedPanelId: string }; // 对称联动
  groupId?: string;                   // 成组编辑
  collisionLayer?: number;            // 自碰撞层，0~9，缺省 0（最内层）
  visible: boolean;                   // 视口可见性
  locked: boolean;                    // 锁定后 2D 不可拖动
}
```

| 字段 | 谁在读 |
| --- | --- |
| `outlineEdgeIds` | `samplePanelOutline()` 生成轮廓折线（05 §3） |
| `holes` | 三角化挖洞与 2D 绘制，毛边外扩时随轮廓一起偏移 |
| `seamAllowanceCm` | `buildPanelMesh()` 外扩轮廓；边的 `seamAllowanceCm` 覆盖它（05 §1.3） |
| `fabricId` | `fabricForPanel()` 取材质；`fabricSlotPlan()` 决定材质槽（§6.2） |
| `meshResolutionCm` | 本片的有效网格边长；引擎按片读取它（归属规则见 05 §3） |
| `placement` / `drape` | `InitialPose.posedPositions3D()` 二选一定初始姿态；`placement` 存在时不脱体、不钉顶边（04 §5.1） |
| `transform` | `objectTransforms.ts` 写回顶点缓冲；改动会重建布料并重置模拟（06 §5.3） |
| `grainAngleDeg` / `grainOffset` / `grainLengthCm` | `panelGrainLine(panel, outline)`（`pattern/panel/panelBuilder.ts`）算出布纹线段：2D 布纹线层、SVG / DXF / PDF 与排料图都读它；属性面板的「布纹线角度 / 位置 / 长度」走 `SetPanelGrainCommand`，位置与长度填 0 即清空覆盖回到默认 |
| `symmetry` | `MirrorPanelCommand` 写入，`SyncMirrorCommand` 按镜像轴重建对侧片 |
| `collisionLayer` | `MergedCloth.build()` 写进 `ClothSimInput.panels[i].collisionLayer`，`computeParticleLayers()` 展开成逐粒子层表；参与 `panelGeometrySignature()`，改动后求解器立刻拿到新层表（04 §2.6.1）；可经 `AutoAssignCollisionLayersCommand` 按缝合连通性自动识别 |
| `visible` | `applyPanelVisibility()` 重挂 geometry 分组：隐藏的片不绘制，粒子照常模拟（03 §3.5） |
| `locked` | 2D 的拖动与方向键微调都跳过锁定的片（`viewport2D/index.tsx`、`useNudgeSession.ts`） |

### 4.5 环绕摆放（PanelDrape）

`drape` 描述平面片如何覆盖到人体表面，几何实现与模板写入见 [05-版型系统](./05-版型系统.md) §5，字段语义如下：

| 字段 | 含义 | 缺省 |
| --- | --- | --- |
| `region` | 覆盖的部位：`torso` / `arm` / `leg` / `neck` | 必填 |
| `anchor` | 顶边所在的人体基准高度 | 该部位的默认 landmark |
| `anchorOffsetCm` | 相对 `anchor` 的上下偏移（cm） | 0 |
| `startDeg` | 起始角：躯干从人体前中量起，四肢从侧面量起 | 躯干 −90，其余 0 |
| `sweepDeg` | 角跨度，负值反向环绕 | 躯干 180，四肢 360 |
| `side` | 四肢覆盖左右侧；颈部用人体中线 | `right` |
| `easeCm` | 环绕半径加量（cm） | 按部位松量（05 §5.1） |
| `rowWrap` | 逐行按该行自身宽度铺开角度与半径，使收口片的侧缝闭合 | false |
| `plumb` | 保持环宽不小于该高度以上最宽截面，使宽松服装垂直下垂 | false |
| `pinTop` | 是否假缝顶边带；袖子靠袖山悬吊故为 false | `region !== 'arm'` |

> **注**：未声明 `drape` 的片按片名推断（含「袖」→ 手臂、含「左」→ 左侧、含「后」→ 后半圈），规则在 `drape/drapeInfer.ts` 的 `inferDrape()`；改名会改变推断结果。

## 5. 缝合（Seam）

缝合关系是一条边到另一条边的配对记录，`Seam` 只描述配对与显示，不描述物理过程。

### 5.1 字段定义

```typescript
type SeamType = 'normal' | 'gather' | 'free';
/** 缝合的一侧：一条边上的一个区间，可选一个对位锚点。 */
interface SeamEnd {
  edgeId: string;
  t0: number;              // 弧长参数区间起点，0~1
  t1: number;              // 终点，必须 > t0
  anchorT?: number;        // 对位点：区间内强制对齐的参数
}
interface Seam {
  id: string;
  name?: string;           // 自定义行名，缺省是「甲片 ⇄ 乙片」
  type: SeamType;
  a: SeamEnd;
  b: SeamEnd;
  flip: boolean;           // 配对前反向 b 边的顶点顺序
  gatherRatio?: number;    // 缩缝比例：b 边的静止长度 ÷ a 边区间长度
  strength: number;        // 0~1
  threadColor: string;     // 缝线颜色（hex）
  stitchVisible: boolean;  // 2D 缝合指示线与 3D 缝线画不画
}
```

### 5.2 字段行为

| 字段 | 实际行为 |
| --- | --- |
| `a` / `b` | 整边配对写 `{t0: 0, t1: 1}`；子段配对只取拖动出来的区间，区间外不受约束。求解器按 `n = max(lenA, lenB)` 采样粒子对，长的一侧被均摊 |
| `flip` | 走向相反的两条边必须反向，否则布料扭转；配对算法见 04 §1.3.3 |
| `anchorT` | 两侧各给一个参数时，约束把这两个点对齐，褶皱按锚点两侧分布 |
| `gatherRatio` | 存在时用它换算静止长度（默认按实际长度差），`SetSeamGatherCommand` 写入 |
| `strength` | 柔度换算 `1 / (max(strength, 0.01) × 3600)`，同时决定断裂阈值：初始开敞距离乘 `seamBreakStretch(strength)`；超过即断开（开启 `seamTearing` 时，见 §8.2.2） |
| `type` | `free` 不生成缝合约束，两侧保持分开（长度与配对提示也跳过）；`normal` 与 `gather` 都建立约束，`gather` 配合 `gatherRatio` 决定乙边的静止长度 |
| `threadColor` | 三处共用：2D 缝合指示线、3D 缝线叠画、离线预览着色 |
| `stitchVisible` | 纯显示开关，由场景树「缝纫线」行的眼睛与对象标签 · 对象 · 「可见性」写入；关闭后缝合约束照旧建立、模拟照旧进行（04 §5.3） |

### 5.5 尺码表与放码（SizeDef / grading）

```typescript
/** 尺码表里的一档。 */
interface SizeDef {
  id: string;
  label: string;          // 「S」「M」「L」
  seq: number;            // 排列顺序，决定放码方向
  isBase: boolean;        // 基码：库里存的几何就是它
}
```

- `Project.sizes` 与 `Project.activeSizeId` 都在工程文件里；`activeSizeId` 表示当前 `pattern` 几何已经解析到的码，缺省表示就是基码。
- 点级档差写在 `PatternPoint.grading[sizeId]`，单位 cm，含义是「相对基码的位移」，所以基码自己没有 `grading` 项。
- `resolveSize(pattern, fromSizeId, toSizeId)`（`core/command/gradingCommands.ts`）把几何从 `fromSizeId` 换算到 `toSizeId`：每个点减去来源码的档差、加上目标码的档差；曲线控制柄按两端点档差的平均值平移，圆弧边按两点档差的均值移动其中点后重解三点弧（重解不出圆时退回平移圆心），`id` 全部保持不变。
- `ApplySizeCommand(sizeId)` 用它改写几何并更新 `activeSizeId`，撤销回到切换前的状态；属性面板的「用此码」还额外重置模拟，让新尺寸重新垂坠。
- `validateGrading(pattern, sizes)` 逐个码检查边长是否单调递增、轮廓是否自交，问题带着 `targetId` 返回，2D 工具条「检查」菜单点一条就选中那一处。
- 齐码套叠是显示层开关（`displayOptions.gradingOverlay`）：`sizeOutlines()` 给出各码轮廓叠在当前码后面，当前码高亮。

## 6. 面料（Fabric）

一条面料记录同时承载外观与物理，两者分别由不同路径读取。

### 6.1 记录结构

- 版型片通过 `fabricId` 指向记录，多条片指向同一条即为共用，改一次全部生效。
- `fabricId` 为空或指向不存在的记录时，该片使用灰色回退外观与棉的默认物理（`clothConstants.ts`）。
- `FabricMaps` 的 `albedo` / `normal` / `roughness` / `metallic` 各存一张图片的 data URL，`null` 与缺省都表示空槽；`fileNames` 记录界面上显示的文件名，没有记录时界面按「已设置」显示。
- `uvTiling` 是花纹重复次数（界面最小 0.01），`uvOffset` 是花纹起点；两者都按布料 UV 生效。
- 工程文件原样保存上述字段（data URL 在 JSON 里）；旧工程缺 `maps` / `uvTiling` / `uvOffset` 时由 `projectCodec.decode()` 的 `normalizeFabrics()` 补 `{}` / `(1, 1)` / `(0, 0)`，不做 `dataVersion` 迁移。

```typescript
interface FabricAppearance {         // 渲染侧
  baseColor: string; metallic: number; roughness: number; normalScale: number;
  sheenColor: string; sheenIntensity: number;
  maps: FabricMaps;                 // 四张可选贴图，槽位存 data URL
  uvTiling: Vec2; uvOffset: Vec2;   // 贴图在布料 UV 上的平铺与偏移
}
interface FabricPhysics {            // 模拟侧
  stretchStiffness: number; bendingStiffness: number; shearStiffness: number;
  massPerArea: number;              // g/m²
  damping: number;
}
interface Fabric {
  id: string; name: string;
  presetKey?: FabricPresetKey;       // 由哪个预设新建
  appearance: FabricAppearance; physics: FabricPhysics;
}
```

### 6.2 读取路径

消费方式按侧分开的三件事：

- 渲染：`fabricSlotPlan(project, panelIds)`（`core/model/fabric.ts:47`）把面板序列映射为「每条不同记录一个材质 + 每片一个 geometry group」；外观改动就地写进现有 `MeshPhysicalMaterial`，不重建网格（03 §3.3）。
- 贴图：`maps` 的 data URL 由 `render/material/fabricTextures.ts` 异步解码成 `Texture`，按 data URL 缓存已解码的图像、按材质各持一张纹理，释放见 03 §3.6；没有贴图的通道回落到 `baseColor` / `metallic` / `roughness`。
- 模拟：`ClothSimInput.panels` 逐片携带 `physics`，刚度换算成逐约束柔度、克重换算成逐粒子逆质量。

> **注**：阻尼是全局值，只取工程里的第一条面料记录（`primaryPhysics()`，04 §5.4）；改第二条及以后材质的阻尼不产生任何效果。

### 6.3 预设

物理与外观预设是同键的两张表，`createFabric(preset)` 用 `structuredClone` 复制，因此改一条不影响其他（`defaults.ts:33,41,60`）。`FABRIC_PRESET_KEYS` / `FABRIC_PRESET_LABELS` 决定界面顺序与名称。

| 预设 | 中文名 | stretch | bending | shear | 克重 g/m² | damping |
| --- | --- | --- | --- | --- | --- | --- |
| `cotton` | 棉 | 0.90 | 0.40 | 0.80 | 180 | 0.02 |
| `silk` | 丝绸 | 0.95 | 0.15 | 0.85 | 80 | 0.015 |
| `denim` | 牛仔 | 0.80 | 0.75 | 0.70 | 400 | 0.03 |
| `knit` | 针织 | 0.50 | 0.25 | 0.40 | 250 | 0.02 |

## 7. 人体（Avatar）

人体只有一个，来源分内置模型、导入模型与程序化生成三种，体型参数同时驱动碰撞体与版片摆放。

### 7.1 字段定义

```typescript
type AvatarSource = 'procedural' | 'glb';
type AvatarDisplay = 'visible' | 'hidden' | 'translucent';
interface AvatarParams {
  heightCm: number; chestCm: number; waistCm: number; hipCm: number;
  poseArmAngleRad?: number;    // 手臂外展角（弧度），默认 0.12；UI 预设 7° / 25° / 90°
  poseLegSpreadRad?: number;   // 腿部开合角（弧度，0–1.2），默认 0；绕髋关节向外张开
  poseTorsoLeanRad?: number;   // 躯干侧倾角（弧度，±0.78），默认 0；髋部以上随高度线性平移
}
interface Avatar {
  id: string; source: AvatarSource; params: AvatarParams; display: AvatarDisplay;
  name?: string;               // 场景树行名；缺省按来源与模型名显示
  glbUrl?: string;             // 内置模型标识或 URL（source = 'glb' 时）
  glbObjectKey?: string;       // 导入模型在本地对象库中的 blob key
  heightCm?: number;           // 导入模型的目标身高（m），缺省用 params.heightCm
  modelName?: string;          // 导入模型的文件名（导出与「自定义」下拉读它）
  transform?: ObjectTransform; // 场景摆放
}
```

### 7.2 尺寸与显示

- `params` 驱动 `avatar/landmarks.ts` 的测量点，进而决定碰撞胶囊与环绕摆放的基准高度；`source: 'procedural'` 时网格由 `generator/` 现场生成。
- 姿态参数（手臂外展、腿部开合、躯干侧倾）同时作用于可见网格、碰撞胶囊与环绕摆放；`avatarBodySignature` 变化会重建人体并重新初始化模拟器。
- `display` 控制外观，半透明用于观察服装与身体的关系；场景树行首的眼睛图标写 `visible` / `hidden` 两态（06 §6.2）。

> **注**：工程只有一个 `avatar`，多选与多人体不在数据模型里；`BUNDLED_AVATARS`（`defaults.ts:98`）列出内置三种人体及其体型三围，「模特」下拉换人时一并套用 `params`。

## 8. 场景（SceneConfig）

场景配置是纯数据：灯光与环境图、渲染与光线追踪、求解参数，加一份参考物体清单；读取时统一过归一化函数（§8.3）。

### 8.1 灯光

灯光是列表而不是固定三盏，字段按类型各取所需、与类型无关的一律保留：

```typescript
type LightType = 'directional' | 'point' | 'spot' | 'area';
interface SceneLight {
  id: string; name: string; type: LightType;
  enabled: boolean;             // 关掉只是不进渲染场景，灯仍留在列表里
  intensity: number;            // 方向光 0~10 量级；点/聚光/面积光按平方反比，量级大得多
  color: string;
  position: Vec3;               // 方向光只用它决定入射方向
  target: Vec3;                 // 点光源不读
  distance: number;             // 0 表示不限
  coneAngleDeg: number;         // 聚光灯锥角（度）
  penumbra: number;             // 聚光灯边缘柔化 0~1
  width: number; height: number;// 面积光发射面（m）
}
interface LightConfig {
  lights: SceneLight[];         // 顺序即场景树顺序
  iblLabel?: string;            // 环境光在场景树里的行名；缺省「环境光」
  iblUrl?: string;              // 缺省用内置 HDR；保存工程时可能是内嵌 data URL
  iblObjectKey?: string; iblName?: string;  // iblName 是导入图的文件名，不随行名变化
  iblEnabled: boolean; iblIntensity: number;
}
```

- 切换类型不丢已填的值。
- `iblStrength(lights)`（`defaults.ts:263`）是环境光实际贡献的唯一出口，关闭时为 0；渲染器与 `EnvironmentStage` 都读它（03 §4.3）。

> **注**：阴影没有数据入口——渲染器 `shadowMap.enabled = false`，`SceneLight` 也没有 `castShadow` 字段；光追下的遮挡由路径追踪器计算（03 §4.4）。

### 8.2 渲染、求解与参考物体

#### 8.2.1 渲染与光线追踪

```typescript
interface RenderConfig {
  mode: RenderMode;             // 见下；建布料网格时读一次
  toneMapping: ToneMappingMode; // 默认 'aces'
  rayTracing?: RayTracingConfig;// 缺省或越界由 normalizeRayTracing() 补齐
}
type RenderMode = 'shaded' | 'raytraced' | 'wireframe' | 'shadedWireframe' | 'uvCheck' | 'normalVis';
// shadedWireframe 与 shaded 返回同一份材质，也不在界面下拉里：线框叠加待完成（03 §5.2）

interface RayTracingConfig {
  maxBounces: number;     // 默认 8，1~16
  frameBudget: number;    // 默认 500000，5万~100万；每帧路径条数
  maxSamples: number;     // 默认 256，8~1024；收敛上限，也是降噪触发点
  renderScale: number;    // 默认 1，0.5~1
  denoise: boolean;       // 默认 true
  denoiseModel: 'small' | 'base';  // 默认 'base'
  filterGlossyFactor: number;      // 默认 1，0~1
  clampDirect: number;    // 默认 0（不钳制），0~10
  clampIndirect: number;  // 默认 8，0~20

```

> **注**：运行时的实际显示模式由 `uiStore.renderMode` 决定；`RenderConfig.mode` 只在首次建布料网格时被读一次，界面切换不写回工程（03 §5.1）。

#### 8.2.2 求解

```typescript
interface WindConfig { direction: Vec3; speed: number; }
interface SimulationConfig {
  gravity: Vec3;                // 默认 {0, -9.8, 0}，界面只调 y
  wind: WindConfig;             // 方向默认 +X 并被着色器读取，界面只给速度滑块
  dt: number;                   // 固定 1/60，界面无滑块
  substeps: number;             // 默认 4，界面无滑块
  constraintIterations: number; // 默认 5，滑块 1~15
  avatarCollision: boolean;     // 物理标签的唯一开关
  meshResolutionCm?: number;    // 最近一次批量设置的网格边长（SetGlobalMeshResolutionCommand 同步写入全部版片）
  clothThicknessCm?: number;    // 布料厚度，默认 0.2，滑块 0~1；同时抬高人体与地面碰撞距离
  selfCollision?: boolean;      // 布料自碰撞，默认 true；为 false 时整段 CPU 后处理跳过
  layerSpacingCm?: number;      // 碰撞层间距，默认 0.4，滑块 0~2
  seamTearing?: boolean;        // 缝合断裂，实验开关，默认 false；开启后超出断裂阈值的缝合会断开
}
```

- `dt` 与 `substeps` 被求解器读取但界面没有滑块，暴露前需要同时评估性能（04 §6.1）。
- `WindConfig.direction` 被着色器读取，界面只给风速滑块，风向调节待完成。
- `clothThicknessCm`、`selfCollision`、`layerSpacingCm`、`seamTearing` 每帧由 `step()` 抄进求解器；前三者都在场景标签实时生效，`seamTearing` 暂无界面入口（04 §1.3.3）。旧工程缺字段时按默认值处理（0.2 / true / 0.4 / false），键名留给序列化。自碰撞与层公式见 04 §2.6。

### 8.3 归一化函数

| 函数 | 作用 |
| --- | --- |
| `normalizeLights()` | 逐盏 `normalizeLight()` 夹取值、未知类型退回方向光、缺 id 补 `genId`；没有 `lights` 数组时 `createDefaultLights()` |
| `normalizeRayTracing()` | 九个字段各自限制到合法区间，`denoise` 需 boolean，`denoiseModel` 取白名单中的值 |

这两个函数是读取时的归一化：缺字段补默认，值越界夹回。它们不做旧格式兼容——当前工程结构就是唯一标准。

## 9. 状态变化如何扩散

工程数据的变更由 projectStore 统一提交：命令在 `structuredClone` 出的草稿上就地改动，提交时生成新的不可变 `project` 并重算 `clothSignature`（版型内容 + 成型人体字段 + 全局网格边长，`display` / `transform` / `visible` / `stitchVisible` / `name` 这类绘制字段不计入）。

界面与引擎全部经 zustand 订阅同步。订阅结构与通道归类见 [06-UI与状态管理](./06-UI与状态管理.md) §2；`ProjectContext` 与 `CommandHistory` 的接口定义在 `core/command/command.ts`。

## 10. 工程（Project）与序列化

一个工程文件由文件头、编解码契约与三条互不相干的持久化通道组成。

### 10.1 文件头

```typescript
interface ProjectMeta {
  name: string;
  createdAt: string;   // ISO 时间
  modifiedAt: string;  // 每次 executeCommand 刷新
}
```

`executeCommand()` 每执行一条命令刷新一次 `modifiedAt`；`undo` / `redo` / `loadProject` 替换工程对象但不刷时间。

### 10.2 `.ocproj.json`

#### 10.2.1 编解码

`projectCodec`（`io/codec.ts`）是一个对象字面量，没有 interface：

```typescript
encode(project) → JSON.stringify(JSON.parse(JSON.stringify(project)), null, 2)
decode(json) → 校验顶层字段 → normalizePattern(pattern) → as Project
```

`decode` 只做一类校验：

- `meta` / `pattern` / `fabrics` / `avatar` / `scene` 缺任一抛「无效的工程文件：缺少必要字段」。

`normalizePattern`（同一函数也供 DXF/JSON 导入复用）只补当前结构下可能缺失的可选集合：`notches` / `annotations` / `measurements` 补空对象，每片 `holes` 补空数组。

> **注**：没有 schema 校验库，也没有逐字段类型验证——顶层之外的一切不合法内容都要靠归一化函数在读取时夹回（§8.3）。

#### 10.2.2 三条持久化通道

| 通道 | 位置 | 内容 |
| --- | --- | --- |
| 工程文件 | 浏览器下载 `.ocproj.json` | 完整 `Project`；保存前 `embedProjectAssets()` 把导入的模特、参考物体与环境图转成 data URL 写入 `glbUrl` / `objectUrl` / `iblUrl`，并删掉对应的对象库键 |
| 最近工程 + 自动保存 | IndexedDB 库 `oc-projects`（`io/projectArchive.ts`）：store `recent`（keyPath `id`，上限 `RECENT_LIMIT = 8`）与 `autosave`（key 为快照写入时间，上限 `AUTOSAVE_LIMIT = 5`，超出后删除最旧的一份） | 序列化后的完整工程 JSON |
| 导入的模型与环境图 | IndexedDB 库 `oc-objects`、store `blobs`（`io/objectStore.ts`） | 文件 Blob；工程只记 `glbObjectKey` / `iblObjectKey` / `objectKey` |

界面偏好是第四份独立存储，落在 localStorage，见 06 §8。

> **注**：保存、最近工程与自动保存三条通道都先经 `embedProjectAssets()` 把导入的模特、参考物与环境图转成 data URL，换机器可直接打开；剩余对象库键只在本地 blob 仍存在时快速取回。文件里的 data URL 是文本，不是二进制块。

#### 10.2.3 悬空引用与不合法文件

- `fabricId` 指向不存在的记录时得到灰色外观加棉的默认物理。
- 缺失的点或边引用在几何构建时由 `?? []` / `filter(Boolean)` 跳过。

> **注**：损坏文件在解码期抛错；字段齐全但值不合法的文件不会报错，会静默进入运行时并被归一化函数限制到合法区间（§8.3）。
