# 架构总览

这篇给出仓库的地图：代码分成哪几层、层与层之间允许怎样的 import、一份 `Project` 如何变成 2D 网格、GPU 缓冲与画面，以及几处影响全局的取舍。修改任何模块前先看这篇，它回答"这段代码应该放在哪、谁可以 import 谁"。

整个应用是一条单向链：界面把操作变成命令，命令修改 `Project`，`Project` 派生出 2D 网格、GPU 缓冲与渲染场景；模拟结果每帧回读一次写回渲染网格。`core/model` 是唯一被所有层共用的基础，`core/engine` 把其余各层组装成一次模拟输入并驱动画面。

章节顺序依次为：分层与目录（§1）、技术栈（§2）、数据流（§3）、执行流程（§4）、线程与构建模式（§5）、关键设计决策（§6）、扩展点（§7）。

> **说明**：各篇覆盖范围见 [README](../../README.md) 的文档索引。

## 1. 分层与目录

`src/` 下每个顶层目录是一层，层内按职责再分文件；目录本身不表达依赖，允许的方向由 §1.1 约束，编排职责的拆分见 §1.2。

```
src/
├── core/                  # 编排层 + 各层共用的数据定义
│   ├── model/             #   types.ts（全部类型）· defaults.ts（默认值/预设/归一化）· fabric.ts（材质槽查询）· validatePattern.ts（提交前拓扑校验）
│   ├── command/           #   Command 接口、CommandHistory、快照式命令基类、各编辑命令（移动/创建/编辑/结构/进阶/生产/缝合/放码）、版片剪贴板
│   ├── engine/            #   GarmentEngine 及其协作模块（§1.2）
│   └── assets/            #   bundledAssetUrls.ts：内置资源走站内路径还是站点 Storage
├── pattern/               # 版型层：2D 几何内核与网格生成
│   ├── geom/              #   Vec2 运算、贝塞尔、圆弧、圆角、多边形与折线偏移、布尔、曲线重拟
│   ├── triangulate/       #   earcut 封装 + 保形细化 + 边界边/邻接边提取
│   ├── panel/             #   轮廓采样 → 逐边缝份 → 三角化 → 细化 → UV → 缝合边映射、布纹线
│   ├── seam/              #   接角圆顺与缝合告警
│   ├── grading/           #   档差复制与粘贴目标
│   ├── marker/            #   排料：片装箱与版面
│   ├── auto/              #   自动排位与缝合建议
│   ├── drape/             #   环绕模特落片、脱体展开、缝合目标折叠
│   └── template/          #   五套参数化模板与模板命令
├── avatar/                # 模特层：landmarks（体型→测量点）、generator（程序化模特）、sdf（胶囊拟合与打包）
├── sim/                   # 模拟层：clothSimulator（编排）· gpuPipelines（管线与缓冲）· simUniforms · constraintBatches · simTypes · picking · buffers/constraintBuilder · shaders/shaders
├── render/                # 渲染层：renderer/（上下文、光源、环境、舞台地面、光追）· material/（织物材质与布料网格管理）
├── io/                    # 导入导出：codec · modelLoader · projectArchive · objectStore · exporter（GLB / OBJ / PNG）· dxf/（AAMA/ASTM 读写）· svgPattern · pdfPattern
├── ui/                    # 界面层：app.tsx、视口、面板、菜单、控件（见 06）
├── store/                 # 状态层：projectStore · uiStore · simStore · perfStore · prefs · stores
├── tools/                 # Node 侧产出工具：软渲染、平铺位形、PNG 编码、离线预览 CLI
├── main.tsx               # 入口，挂载 src/ui/app.tsx
└── index.css              # 全局样式
```

`test/` 只镜像保留下来的核心层（几何内核、命令层、拓扑校验、存档与 DXF、求解器），清单与挑选门槛见 [00-开发指南](./00-开发指南.md) §6.1。

### 1.1 依赖规则

实际允许的方向（箭头 = "import"）：

```
ui ──► store ──► core/model ──►（无）
 │                 ▲   ▲
 ├──► core/engine ─┘   │
 │       │             │
 │       ├─► pattern ──┤   pattern ─► avatar/landmarks
 │       ├─► sim ──────┤   sim ─► pattern/triangulate、avatar/sdf
 │       ├─► render ───┤
 │       ├─► io ───────┘
 │       └─► avatar
render ─► core/model、core/assets      io ─► core/model、core/assets
tools  ─► pattern、avatar、core/model   store ─► core/model、core/command
```

- `core/model` 是唯一被所有层共用的基础；`core/engine` 是编排层，把 `pattern`、`sim`、`render`、`io`、`avatar` 组装成一次模拟输入并驱动画面。
- `ui` 除了 `store` 与 `core/engine`，还直接以只读方式调用 `pattern`（2D 工作台的采样、缝份、布纹线、命中与排料）、`io`（保存、导入与导出对话框）、`render`（显示模式与画面抓取）与 `core/model` 的纯函数；这些调用不反向驱动上层状态。
- 下层之间的三条边是数据依赖而非控制依赖：`sim` 需要三角形拓扑（`pattern/triangulate` 的 `TriangleMesh` / `buildAdjacency`）与胶囊布局（`avatar/sdf` 的 `packCapsules`），`pattern/drape` 需要模特测量点（`avatar/landmarks`）。
- `render`、`io`、`tools` 之间没有互相依赖；`tools` 只被离线脚本使用。
- `store` 不 import `ui`：界面选项表在 `ui/optionTables.ts`，偏好校验需要的白名单在 `store/prefs.ts` 各自声明，联合类型保证两者保持一致。
- `ui → core/engine` 只经由视口组件持有引擎实例这一条路径（`GarmentEngine` 由 `Viewport3D` 创建，通过 `onEngineReady` 交给 App 与工具条）。
- 没有循环依赖；`core/model`、`pattern`、`sim` 的越层 import 由 ESLint 的 `no-restricted-imports` 拦截（[00-开发指南](./00-开发指南.md) §4.5），循环依赖仍由 `tsc -b` 与测试间接把关。

> **注**：跨层边只允许数据依赖（类型、拓扑、几何），不允许反向调用上层模块；新增跨层 import 前先确认它属于同一类。

### 1.2 core/engine 的分工

`garmentEngine.ts` 只做编排（建布料、驱动模拟、维护选择状态），其余每块各管一件事：

| 模块 | 负责 |
| --- | --- |
| `mergedCloth.ts` | 合并所有版片：模拟输入、缝合对、三角与粒子索引映射 |
| `initialPose.ts` | 片的初始姿态：环绕/平铺位置、脱体位移、顶部锚点带、模特测量缓存 |
| `dressingStages.ts` | 着装三阶段的帧数、迭代次数与零重力配置 |
| `dressingController.ts` | 着装动画的播放状态机：sew/glide/settle 三帧推进与已着装标记 |
| `avatarStage.ts` | 模特分组、碰撞胶囊、选中覆盖层 |
| `referenceStage.ts` | 参考物体的导入、显隐、透明度、变换与场景网格同步 |
| `environmentStage.ts` | 环境贴图的对象 URL 生命周期（数据变更走界面层命令） |
| `selectionOverlay.ts` | 选中版片的半透明三角形覆盖层 |
| `clothPicker.ts` | 屏幕↔世界投影、粒子与片的拾取、相机预设与取景 |
| `cameraFit.ts` | 视角方向的共享定义（十个预设的朝向与 up 向量）与按场景 AABB 算取景距离 |
| `seamThreads.ts` | 缝合线叠画：逐段取所属缝口的线色，随缝合闭合淡出，可按缝口隐藏 |
| `pinMarkers.ts` | 固定点标记球 |
| `clothSignatures.ts` | 几何 / 粒子布局 / 约束 / 物理四类比较签名，决定增量重建走到哪一层（04 §5.1.3） |
| `objectTransforms.ts` | 工程变换写回场景分组与顶点缓冲 |
| `clothConstants.ts` | 覆盖层命名与材质/物理回退值 |
| `engineTiming.ts` | 开发模式下的重建耗时计时 |

材质绑定、可见性分组与布料网格管理在 `render/material/fabricMaterial.ts` 的 `ClothMeshManager`；求解器本身在 `sim/`。

## 2. 技术栈

选型按"渲染—模拟—界面—构建"四段排列，每段的约束列在其后：

| 层次 | 选型 | 约束 |
| --- | --- | --- |
| 渲染 | Three.js `WebGPURenderer`（`three@^0.185.1`） | 光栅化用标准材质后端；应用不写 TSL 节点图 |
| 光线追踪 | `three-gpu-pathtracer/webgpu` + `three-mesh-bvh` | 复用同一个 Scene/Camera 做 BVH 路径追踪与渐进采样，只在首次选择该模式时动态加载 |
| 降噪 | `oidn-webgpu` | 权重随 `assets/weights` 打包；加载失败时摘掉降噪器继续出图，并记住失败的模型以便关闭再开启降噪时重试 |
| 布料模拟 | 自研 WGSL compute（XPBD） | 粒子与约束存 StorageBuffer；着色器是 TS 模板字符串常量 |
| UI | React 18 + TypeScript 严格模式 | Canvas2D 画 2D 制版，无 SVG 叠加层 |
| 状态 | zustand + 命令模式 | 撤销/重做上限 100 步 |
| 几何 | earcut + 自研曲线库 | 贝塞尔、缝份偏移、保形细化 |
| 构建/测试 | Vite 6 / vitest 5（Node 环境） | 见 [00-开发指南](./00-开发指南.md) §2、§7 |

`vite.config.ts` 把裸导入 `three` 精确别名到 `three/webgpu`，使 `examples/jsm` 插件与主包共用同一份构建；`three/webgpu` 与 `three/examples/*` 不受别名影响。两类导入混用的后果见 [00-开发指南](./00-开发指南.md) §1.1。

## 3. 数据流

单向：UI 通过命令改状态，状态驱动派生几何、模拟与画面。

```
用户操作（ui/）
    │ executeCommand
    ▼
Command + CommandHistory（core/command/）
    │ 原地修改
    ▼
Project（store/projectStore 持有）
    ├──► pattern：轮廓采样 → 缝份 → 三角化 → 细化 → PanelMesh（粒子网格）
    │           ▼
    ├──► core/engine/mergedCloth：逐片网格合并成一份模拟输入 + 缝合约束
    │           ▼
    ├──► sim：StorageBuffer → 每个子步一次 submit → 位置/法线回读为 Float32Array
    │           ▼
    ├──► render：写进 ClothMeshManager 的 BufferAttribute → WebGPU 出图
    │
    └──► ui/viewport2D：几何变化即整帧重绘（无动画循环）
```

四条关键链路的落点：

1. 制版 → 模拟：`PanelBuilder` 出网格，`MergedCloth.build()` 合并并给出粒子偏移映射，`buildPanelConstraints()` 逐片生成约束后图着色分批（[04-布料模拟](./04-布料模拟.md) §1.2、§1.3.1，[05-版型系统](./05-版型系统.md) §3）。
2. 模拟 → 渲染：最后一个子步之后执行法线三段，再把位置与法线 `copyBufferToBuffer` 到 `MAP_READ` 缓冲，主线程 `mapAsync` 回读后写进渲染网格（[03-渲染管线](./03-渲染管线.md) §2）。
3. 缝合：缝合关系存在工程数据里，`MergedCloth.buildSeamConstraints()` 把它变成跨片的距离约束，静止长度取脱体后的开口距离（[04-布料模拟](./04-布料模拟.md) §1.3.3）。
4. 碰撞：模特是解析胶囊碰撞体（拟合与数量限制见 04 §2.3.1），模拟阶段逐粒子做胶囊/平面距离投影；布料之间的自碰撞是回读后的 CPU 近邻投影（04 §2.6）。

## 4. 执行流程

启动只建立一次上下文与引擎，循环体每帧执行一次，着装是编辑态与播放态之间的中间过程。

### 4.1 启动

```
main.tsx → 挂载 <App />（store 在导入时创建，界面偏好从 localStorage 读回）
  → Viewport3D 初始化 effect（顺序固定，见 03 §1.1）
    detectWebGPU → createRendererContext(canvas)
    → ctx.rayConfig = normalizeRayTracing(...) → applyLightConfig
    → new GarmentEngine → applyEnvironment → buildFromProject → initSimulator
    → setProjection → setCameraPreset('front') → syncSelectionOverlay → bumpPins
    → setRendererMode（懒建光追实例，建好后先画几帧验证这台设备的内核能否正常运行；任一步失败则切回光栅化）→ onEngineReady(engine)
    → new EngineSync(engine, ctx)：接管 store 订阅与 rAF 循环
```

`detectWebGPU()` 不通过时提前结束，由 `index.html` 的 `#webgpu-error` 整屏提示接管；应用没有第二套渲染后端（[00-开发指南](./00-开发指南.md) §1.2）。

### 4.2 渲染循环

循环在 `src/ui/viewport3D/engineSync.ts` 的 `EngineSync.loop`（循环末尾重挂下一帧），用一条 `await` 链保证一个模拟步不会与下一步重叠（细节见 [03-渲染管线](./03-渲染管线.md) §1.3）：

```
requestAnimationFrame(loop)
  loop:
    if (cancelled) return
    try:
      isPlaying → stepAccumulator += speed；steps = floor(stepAccumulator)；stepAccumulator -= steps
                 连续 await engine.stepFrame(project) steps 次，每步 incrementFrame()
      把引擎的 isDraping / isDressed 镜像回 simStore        // 界面文案与引擎一致
      controls.update()
      容器尺寸 > 0 时 renderScene(ctx)                      // 窗格隐藏时物理继续，只是不画
      上报本帧绘制与光追采样数给 perfStore
    finally:
      if (!cancelled) requestAnimationFrame(loop)            // 本帧抛错也不会停循环
```

- `stepAccumulator` 跨帧累加 `speed`，取整后余数留到下一帧，因此 0.25x 每四帧推进一步、0.5x 每两帧一步、2x 每帧两步；`resetToken` 变化时归零。
- 2D 视口没有动画循环，`render` 回调依赖变化时由 `useEffect` 立即重绘；3D 侧的着装与模拟进度不驱动 2D 刷新，2D 只画制版几何。
- 窗格隐藏时模拟继续推进，只是不绘制；本帧抛错也不会中断循环。

### 4.3 从版型到着装

```
1. 2D 编辑 → PatternCommand 改草稿 → projectStore 提交新工程并重算 clothSignature
2. Store 变化 → EngineSync 比对签名，命中重建档则引擎重建派生几何（06 §2）
3. 自动着装（Ctrl+D / 空格 / 单步）→ 环绕摆放并脱体，随后走三阶段动画（帧数与配置见 04 §5.2）
4. 播放 → 常规物理帧
```

## 5. 线程与构建模式

主线程承担界面与编排，GPU 承担并行计算，重资源加载走异步；构建期按静态资源的位置分成两种模式。

### 5.1 线程

主线程承担 React UI、命令处理、Three.js 提交、模拟帧编排与回读后的数据搬运。其余分工：

- 布料求解全部并行在 GPU compute，主线程只提交 compute pass、同步缓冲、回读结果。
- GLB 与 HDR 加载、IndexedDB 读写、光追模块与 OIDN 权重的动态导入是异步的。
- 没有 Web Worker：序列化、截图、模型解析都在主线程。

> **注**：把大工程导出与逐帧渲染移出主线程仍在待完成清单里。

### 5.2 两种构建模式

开关只有 `vite.config.ts` 里的 `mode === 'site'`：

| | `npm run build` | `npm run build:site` |
| --- | --- | --- |
| `publicDir` | `assets/` 原样拷进 `dist/` | 关闭，包内只剩 HTML/JS/CSS |
| 内置资源来源 | 站内根路径 `/models/…` | `core/assets/bundledAssetUrls.ts` 改写成 `/functions/v1/app/assets/…?v=1` |
| 服务端 | `npm run preview` / 静态托管 | `functions/` 的 Function 从站点私有 Storage 流式返回 |
| 产物 | `dist/` | `dist/site/`，随后 `scripts/check-site-bundle.mjs` 校验产物确实指向 Function 路由 |

拆成两条的原因是站点单次 PUT 上传有 45 秒上限：GLB 与权重这类大文件进包会让构建失败，因此存放在 Storage 中，由 `functions/handler.ts` 的 allowlist 提供并带 `immutable` 缓存头。新增、改名或替换内置资源的同步要求见 [00-开发指南](./00-开发指南.md) §3。

## 6. 关键设计决策

| 决策 | 选择 | 代价与理由 |
| --- | --- | --- |
| 渲染器 | Three.js WebGPURenderer，光追作为同一场景的另一条出图路径 | 避免维护第二套场景数据；代价是路径追踪只接受 Standard/Physical 材质，辅助对象需在同步期间临时隐藏（03 §6.3） |
| 模拟位置 | GPU compute | 数千粒子实时；代价是 WGSL 不受 `tsc` 校验，调试要回读缓冲（00 §4.3） |
| 求解算法 | PBD/XPBD + 图着色分批 | 无条件稳定、参数直观；同批内无写冲突，代价是约束迭代按批次串行 |
| 顶点回传 | 每帧一次 CPU 回读 | 同一份位置供非有限值检查、拾取与缝纫线可视化；GPU-to-GPU 共享缓冲待完成（03 §2.2、§8） |
| 碰撞 | 模特解析胶囊碰撞体 + 地面平面 | 距离可在着色器里直接算、随体型重建；近似代价是褶皱细节与体形贴合度有限（04 §2.3） |
| 状态 | zustand + 命令模式 | 撤销/重做天然成对；代价是"引用是否换新"决定视图与材质是否重建，规则见 06 §6.5 |
| 序列化 | 明文 JSON | 可读易调试；保存前把导入的模特、参考物体与环境图转成 data URL 内嵌，同时保留本地对象库以便快速取回（02 §10.2.2） |
| 2D 制版 | Canvas2D 整帧重绘 | 与 3D 视口完全解耦，代价是没有保留模式下的局部重绘 |

## 7. 扩展点

新增一类东西通常要同时动数据定义、编排与界面三处。

> **注**：只改其中一处会留下不一致——类型能过 `tsc`，界面或编排却读不到新条目。

| 要做的事 | 动哪里 |
| --- | --- |
| 加一套服装模板 | 在 `pattern/template/` 写一个参数接口 + `generate` 函数，用 `defineTemplate()` 注册进 `index.ts` 的清单；界面自动出现卡片 |
| 加一类光源 | `core/model/types.ts` 的 `LightType` → `defaults.ts` 的量程与默认 → `rendererContext.ts` 的 `lightToObject()` → `ui/optionTables.ts` 与 `sceneTree.ts` 的显示名 |
