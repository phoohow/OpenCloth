# 渲染管线

这篇讲画面如何产生：渲染上下文里持有什么、一份布料网格如何挂上多个材质、灯光与环境如何进场景、显示模式怎么选，以及切到 WebGPU 路径追踪的条件与代价。代码在 `src/render/`，视口侧的循环与监听在 `src/ui/viewport3D/`。

同一份场景有两条出图路径：光栅化负责交互中的即时帧，WebGPU 路径追踪负责静止时的收敛图像，两者共用 `THREE.Scene`、相机与灯光。场景内容由布料网格、织物材质、灯光与环境组成，显示模式决定这份场景套哪套材质。

章节顺序依次为：渲染上下文（§1）、布料网格与顶点同步（§2）、织物材质（§3）、灯光与环境（§4）、显示模式（§5）、光线追踪（§6）、相机与拾取（§7）、性能策略（§8）。

## 1. 渲染上下文

上下文是两条渲染路径的共同底座：一次建立 renderer、场景、两台相机与控制器，尺寸变化时三者一起同步，出图只有一个入口。

### 1.1 建立与释放

`createRendererContext(canvas)`（`render/renderer/rendererContext.ts:63`）一次建齐两条渲染路径共用的对象：

```typescript
interface RendererContext {
  renderer: THREE.WebGPURenderer;          // antialias、alpha:false、pixelRatio ≤ 2
  scene: THREE.Scene;                      // background = FALLBACK_BACKGROUND，含舞台地面
  camera: ViewportCamera;                  // 当前生效的相机（下面两台之一）
  perspectiveCamera: THREE.PerspectiveCamera;   // 45° fov，near 0.1 / far 100
  orthographicCamera: THREE.OrthographicCamera; // 半深度 ORTHO_CLIP_RANGE = 100
  projection: CameraProjection;
  orthoViewHeight: number;                 // zoom = 1 时正交视野的世界高度
  controls: OrbitControls;                 // enableDamping，target = (0, 0.9, 0)
  canvas: HTMLCanvasElement;
  renderMode: RenderMode;
  rayConfig: RayTracingConfig;
  lightConfig?: LightConfig;               // 灯光上次是从哪套设置建的
  renderConfig?: RenderConfig;             // 色调映射同上
  rayTracer: RayTracingRenderer | null;    // 懒创建
  rayTracerLoading: Promise<RayTracingRenderer | null> | null;
  resizeObserver?: ResizeObserver;         // 由 Viewport3D 挂上，dispose 时断开
  disposed: boolean;
}
```

#### 1.1.1 建立顺序

1. 视口被布局隐藏时 `clientWidth/Height` 为 0，宽高各取 `Math.max(1, …)`，绘图缓冲因此保持有效值。
2. `new THREE.WebGPURenderer({ canvas, antialias: true, alpha: false })` → `await renderer.init()` → `setPixelRatio(Math.min(devicePixelRatio, 2))` → `setSize(w, h, false)`。
3. 色调映射先设成 `ACESFilmicToneMapping`、`toneMappingExposure = 1.0`；映射方式随后由 `applyLightConfig()` 按工程写回（§4.5），曝光固定 1.0、没有界面入口。
4. `renderer.shadowMap.enabled = false`：光栅化路径不产生投影阴影（§4.4）。
5. 场景背景设为 `FALLBACK_BACKGROUND`，紧接着 `addStageFloor(scene)`（20m 地面 + 参考网格，`renderer/stageFloor.ts`）。
6. 建两台相机与 `OrbitControls`（§7.1），`orthoViewHeight` 取初值 1 后调 `syncOrthoFrustum()` 对齐视锥。

`detectWebGPU()` 是 `navigator.gpu.requestAdapter()` 的封装；不通过时 `Viewport3D` 显示 `#webgpu-error` 并提前结束。

#### 1.1.2 释放与重复挂载

StrictMode 与 Fast Refresh 会在同一个 canvas 上再挂一套上下文，因此：

- 初始化 effect 里每个 `await` 之后都要判 `cancelled`，并对已建好的 `RendererContext` 与 `GarmentEngine` 就地释放。
- `disposeRendererContext()` 以 `ctx.disposed` 兜底，重复调用不会二次释放。
- 释放时同时断开 `resizeObserver` 并释放光追实例，包括仍在加载的那个 Promise。

### 1.2 尺寸同步

`resizeRenderer(ctx, w, h)`（`rendererContext.ts:319`）在三件事上做同一件事：宽高比、绘图缓冲、正交视锥。

- 尺寸为 0（窗格被隐藏）时直接返回，保留上一次的有效缓冲。
- `Viewport3D` 用一个挂在容器上的 `ResizeObserver` 转交新尺寸，并把观察器存进 `ctx.resizeObserver`，释放上下文时一并断开。

### 1.3 出图入口

`renderScene(ctx)` 是循环唯一调用的出图函数：

```typescript
export function renderScene(ctx: RendererContext): void {
  // 画面在动时 rayTracer.render() 返回 false，这一帧交给光栅管线显示。
  if (ctx.renderMode === 'raytraced' && ctx.rayTracer?.render(ctx.scene, ctx.camera)) return;
  ctx.renderer.render(ctx.scene, ctx.camera);
}
```

主循环本体（帧序、`await` 链、镜像到 store、隐藏窗格跳过绘制）见 [01-架构总览](./01-架构总览.md) §4.2。

## 2. 布料网格与顶点同步

渲染侧只有一份布料网格挂多个材质槽，顶点每帧由 CPU 回读刷新，正面朝向取决于制版阶段的绕序。

### 2.1 一份网格、多个材质槽

所有版型片合成一个 `THREE.Mesh`（`ClothMeshManager`，`render/material/fabricMaterial.ts:62`）：

| 属性 | 处理 |
| --- | --- |
| `position` / `normal` | `DynamicDrawUsage`，每帧由模拟写入 |
| `uv` / `index` | 静态缓冲，制版阶段确定 |
| `frustumCulled` | `false`：布料形变大，避免误剔除 |
| BVH | 表面拾取走 three 内置的 `Raycaster`；`three-mesh-bvh` 的包围树只在光追侧挂到 `BufferGeometry.boundsTree` 上（§6.3.2） |
| geometry groups | 每片一条 `{ start, count, materialIndex }` |

多材质靠 group 而不是多网格：`fabricSlotPlan()` 按 `Panel.fabricId` 去重出材质数组，悬空引用统一落到同一个灰色回退槽；`addGroups()` 逐片写区间（§3.4）。

### 2.2 每帧的同步链路

模拟在 GPU compute 里完成，渲染网格是 three 的 `BufferGeometry`，两者之间每帧走一次 CPU 往返：

```
最后一个子步之后，同一个 encoder：
  法线三段（清零 → 按三角形累加 → 归一化，见 04 §2.5）
  copyBufferToBuffer(位置缓冲 → readbackBuf)
  copyBufferToBuffer(法线缓冲 → readbackNormalsBuf)
主线程：
  ClothSimulator.readback() 用 mapAsync 取回 { positions, normals }
  GarmentEngine.stepSimulation() 先扫非有限值，发现 NaN/Inf 就保留上一帧
  ClothMeshManager.updateFromSim(positions, normals) 写进 BufferAttribute、置 needsUpdate、刷新 boundingSphere
```

> **注**：选择回读而不是 GPU-to-GPU 共享缓冲，是因为同一份位置数组还要给非有限值检查、缝线叠画、PIN 标记和拾取网格使用（04 §3.3、§3.4）；共享缓冲改造列为待完成（§8）。

### 2.3 顶点数据与显示朝向

- 三角形绕序在制版阶段由轮廓逆时针保证，正面朝外；所有布料材质一律 `side: THREE.DoubleSide`，背面法线由 three 内部翻转，零厚度曲面从两侧都亮。
- 求解器写回的是逐粒子面积加权法线（04 §2.5），褶皱的高光因此随模拟每帧变化。
- UV 由 2D 制版坐标按包围盒归一化生成（05 §3.2），当前只影响 UV 检查模式的棋盘格与导出 GLB 的 `uv_0`。

## 3. 织物材质

织物外观由 PBR 加 Sheen 参数表达；一条记录可被多片共用，改动按三种签名决定就地更新还是重建，可见性靠 geometry group 重挂。

### 3.1 创建与就地更新

外观由 PBR 参数叠加 Sheen（绒毛光泽）表达，全部使用 three 标准材质，不写自定义 TSL 节点图：

```typescript
// render/material/fabricMaterial.ts
export function createFabricMaterial(app: FabricAppearance): THREE.MeshPhysicalMaterial;
/** 就地改写现有实例，材质编辑因此不重建网格。 */
export function applyFabricAppearance(mat: THREE.MeshPhysicalMaterial, app: FabricAppearance): void;
```

- `applyFabricAppearance()` 写 `color` / `metalness` / `roughness` / `sheen` / `sheenColor` / `sheenRoughness(0.4)` / `normalScale` 后置 `needsUpdate`。
- `FabricAppearance.maps`、`uvTiling`、`uvOffset` 没有加载器，当前不进材质（02 §6）。
- Sheen 采用 Charlie 分布加 Fresnel 近似，与 glTF `KHR_materials_sheen` 一致：掠射角叠加一层柔和光泽模拟纤维散射，`sheenColor` 通常取比底色略亮的同色系。

### 3.2 一份记录、多个使用者

`fabricSlotPlan(project, panelIds)` 决定材质数组与每片的槽位，共用同一条记录的多片天然同材质。

> **注**：改一条记录会同时作用在所有穿着它的片上；单片的改动必须先把它复制为独立记录（引用次数与「复制为独立记录」见 06 §6.6）。

### 3.3 三签名决定重建还是就地改

`GarmentEngine.applyFabrics(project, mode?)` 每次工程变更都被视口调用（撤销与重做同样走这条路），它按 `clothSignatures.ts` 的三种签名逐级判断：

| 签名 | 变了会怎样 |
| --- | --- |
| 可见性签名 | `applyPanelVisibility()` 重挂 geometry 分组（§3.5） |
| 材质槽签名 | `bindClothMaterials()` 重新绑定槽位与分组 |
| 逐片外观签名 | 槽位不变时 `applyFabricAppearance()` 就地改写；传入的 `mode` 与当前材质模式不同则先重建材质 |

三份签名一致时函数直接落到物理签名分支且不做事，因此视口在每次工程变更后调用它都是安全的。

### 3.4 一片一材质如何生效

`ClothMeshManager.addGroups()` 给每片写 `{ start, count, materialIndex }`，`setMaterials()` 换整份材质数组。

- 材质数量变化（指定、新增、拆分）才走重绑。
- 改颜色与光泽只走 §3.1 的就地更新。

### 3.5 可见性分组

绑定时记下每片的索引区间（`clothGroupRanges`，`garmentEngine.ts:212`），`applyPanelVisibility()` 据此重挂分组：

- 隐藏的片没有 group，那段索引不会被绘制；`Mesh.raycast` 按 group 遍历，因此也点不到。
- 粒子仍在模拟，片子再次显示时回到原槽位。
- 隐藏的版型片同时不进选中高亮（`syncSelectionOverlay` 过滤）。

## 4. 灯光与环境

一盏工程灯对应一个 three 灯光对象，面积光需要额外装载 LTC 近似贴图，环境图有独立的强度出口与生命周期；阴影只在光追里出现，色调映射直接设在渲染器上。

### 4.1 一盏灯对应一个 three 灯光对象

```typescript
export function applyLightConfig(ctx: RendererContext, cfg: LightConfig, render: RenderConfig): void {
  const group = ensureLightGroup(ctx.scene);      // scene.getObjectByName('sceneLights')
  clearGroup(group);
  group.add(new THREE.AmbientLight(0xffffff, iblStrength(cfg) * 0.15));
  ctx.scene.environmentIntensity = iblStrength(cfg);
  for (const light of normalizeLights(cfg)) {
    const object = lightToObject(light);          // null = 该类型暂不支持（面积光等 LTC）
    object.name = light.name;
    object.visible = light.enabled;               // 关掉的灯留在场景里，只是不进 traverseVisible
    group.add(object);
    if (object.target) group.add(object.target);   // 目标点也入场景，矩阵才会更新
  }
  // renderer.toneMapping ← aces / reinhard / linear / none
  ctx.rayTracer?.invalidateLights();
  ctx.rayTracer?.invalidateEnvironment();
}
```

| `SceneLight.type` | three 灯光 | 读取的字段 |
| --- | --- | --- |
| `directional` | `DirectionalLight` | `position` 定入射方向、`target` 定朝向 |
| `point` | `PointLight(color, intensity, distance, decay 2)` | `position`、`distance` |
| `spot` | `SpotLight(…, coneAngleDeg→弧度, penumbra, decay 2)` | `position`、`target`、`distance`、锥角、边缘 |
| `area` | `RectAreaLight(color, intensity, width, height)` + `lookAt(target)` | `position`、`target`、`width`、`height` |

- 灯光列表来自工程数据，场景树的「灯光」集合是同一份列表，因此树里列出的灯与渲染场景里生效的灯一一对应。
- `EngineSync` 按整份灯光列表的签名变化调用本函数；新增、删除、改名、开关都只改列表，一次操作都可撤销。

### 4.2 面积光的 LTC 支持

`RectAreaLight` 需要三层的 LTC 近似贴图：

- 列表里第一次出现面积光时 `installAreaLightSupport()` 异步 `import('three/examples/jsm/lights/RectAreaLightTexturesLib.js')` 并 `RectAreaLightNode.setLTC(...)`，装好后重跑一次 `applyLightConfig`。
- 这张数据模块不进主包，未使用面积光时不加载。
- 装载失败只记一条警告；装载完成前，面积光被 `lightToObject` 跳过。

### 4.3 环境贴图

```typescript
// render/renderer/sceneEnvironment.ts
export const DEFAULT_ENV_URL = '/env/royal_esplanade_1k.hdr';
export const FALLBACK_BACKGROUND = new THREE.Color(0x2a2a2e);
/** 按扩展名选 RGBELoader / EXRLoader / TextureLoader；同一 url 只保留一张贴图。 */
export async function applySceneEnvironment(scene, url, filename = url): Promise<boolean>;
/** 释放不再选中的环境贴图；若正是当前环境，同时退回 FALLBACK_BACKGROUND。 */
export function releaseSceneEnvironment(scene, url): void;
```

- 内置环境图只有一张（CC0 室外全景，署名见 `assets/env/ATTRIBUTION.md`），工程未指定环境时使用它。用户可导入 `.hdr` / `.exr` / `.png` / `.jpg` / `.webp`，导入件存进 IndexedDB 后由 object url 提供；非 hdr/exr 走 `TextureLoader` 并标 `SRGBColorSpace`。
- 环境光的有效强度只有一个来源：`iblStrength(lights)`，关闭时为 0。它写进 `scene.environmentIntensity`，并按 `iblStrength × 0.15` 叠一盏 `AmbientLight` 补足环境图照不到的区域；`EnvironmentStage.apply()` 与 `applyLightConfig()` 读的是同一个函数。
- object url 与贴图的生灭由 `core/engine/environmentStage.ts` 管理（`apply` / `release`）；环境图数据与导入记录在工程命令层（06 §5.4），换图的撤销重做走工程历史。`EngineSync` 只在换了哪一张环境图时重新加载贴图，改强度或开关只走灯光重建。

### 4.4 阴影

光栅化路径没有阴影：`shadowMap.enabled = false`，`SceneLight` 没有 `castShadow` 字段；布料网格设了 `castShadow = receiveShadow = true`，两边不匹配的结果是没有任何投影。

> **注**：光线追踪不复用这套设置——路径追踪器重新收集场景灯光（`getLights` 走 `traverseVisible`）并通过次级光线计算遮挡，因此关掉的灯不参与，软阴影只在光追画面里出现。

### 4.5 色调映射

没有独立的后处理节点管线，色调映射直接设在渲染器上，由 `applyLightConfig()` 按 `render.toneMapping` 选择：

| 工程取值 | 渲染器设置 |
| --- | --- |
| `aces` | `ACESFilmicToneMapping` |
| `reinhard` | `ReinhardToneMapping` |
| `linear` | `LinearToneMapping` |
| `none` | `NoToneMapping` |

SSAO、Bloom 之类屏幕空间效果未接入（§8 待完成清单）。

## 5. 显示模式

显示模式的生效值只有一个来源，它决定同一份场景套哪套材质；切到光追是懒加载，运行期失败则复位成光栅化。

### 5.1 两个来源，一个生效值

| 来源 | 何时读 | 是否随工程保存 |
| --- | --- | --- |
| `project.scene.render.mode` | 建布料网格时读一次（`GarmentEngine.createRenderMesh()`） | 是 |
| `uiStore.renderMode` | 每次变化都调 `engine.applyFabrics(project, renderMode)` | 存进偏好，不写回工程 |

两者取值集合相同（`prefs.ts` 的白名单含全部六个 `RenderMode`），运行时的实际显示模式只由 UI store 决定；工程字段与界面偏好的分工见 [02-数据模型](./02-数据模型.md) §8.2.1。

### 5.2 模式与材质的对应

`createMaterialForMode(app, mode)`（`fabricMaterial.ts:24`）：

| mode | 实现 |
| --- | --- |
| `shaded` | `createFabricMaterial()`：`MeshPhysicalMaterial` + sheen + `DoubleSide` |
| `raytraced` | 同一份织物材质，随后由 BVH 路径追踪器读取并渐进采样 |
| `wireframe` | `MeshBasicMaterial({ color: 0x66ccff, wireframe: true, side: DoubleSide })` |
| `uvCheck` | 16×16 棋盘写进 `DataTexture`，由 `MeshBasicMaterial`（`DoubleSide`）采样 |
| `normalVis` | `MeshNormalMaterial({ side: DoubleSide })` |
| `shadedWireframe` | `switch` 落到 `shaded` 分支，返回同一份织物材质 |

界面的两项入口共用同一份状态：

- 「渲染模式」下拉（`ui/optionTables.ts` 的 `RENDER_MODES`）提供 光栅化 / 光线追踪 / 线框 / UV 检查 / 法线可视化五项；`shadedWireframe` 在白名单里但不在下拉里，线框叠加未实现。
- 3D 工具条的「显示」下拉与渲染标签的「显示模式」是同一个 `uiStore.renderMode`，不存在第二份状态（06 §5.1）。

### 5.3 模式切换

```typescript
export async function setRendererMode(ctx: RendererContext, mode: RenderMode): Promise<void> {
  ctx.renderMode = mode;
  if (mode !== 'raytraced' || ctx.rayTracer || ctx.disposed) return;
  // 首次选择时动态 import('./rayTracingRenderer')；加载期间光栅化继续可用。
}
```

- 懒创建的 Promise 存在 `ctx.rayTracerLoading`，两个调用方共享同一次创建。
- 如果期间 `ctx.rayTracerLoading` 被换掉（恢复逻辑或重试），刚建好的实例归发起方释放，不会被装回上下文。

### 5.4 光追失败的处理

运行期异常统一走 `ui/viewport3D/engineSync.ts` 的 `recoverWithRaster()`（`Viewport3D` 初始化失败也调用它），四个触发点：初始化时的 `setRendererMode`、渲染循环里的 `renderScene`、显示模式订阅、光追配置订阅。

- 它销毁光追实例，把 `ctx.renderMode` 与 UI store 复位成光栅化，并显示视口提示「光线追踪运行失败，已切回光栅化模式。」
- 非光追模式的异常继续向外抛。

## 6. 光线追踪

`render/renderer/rayTracingRenderer.ts` 把 `three-gpu-pathtracer/webgpu` 的 wavefront 路径追踪器接到现有场景上。

> **说明**：它不克隆第二套布料或人体网格，以当前 `Scene` 为唯一数据源；光栅化与光追共用同一份场景、相机与材质。

光追按帧累积样本：累积分辨率与每帧路径数决定铺开速度，场景与相机的变动决定何时重启累积，累积初期由光栅帧垫底，收敛到上限后降噪。

### 6.1 构造时的四个开关

```typescript
tracer.synchronizeRenderSize = false;   // 尺寸由 syncRenderSize() 自己管（§6.2）
tracer.renderDelay = 0;                 // 关掉自带的低分辨率预览
tracer.minSamples = 0;
tracer.fadeDuration = 0;                // 首帧即全不透明，不退到未清除的绘制缓冲
```

这四行的作用：

- 低分辨率预览会在低分辨率与全分辨率之间调 `setSize()`，而 `PathTracerBackend.setSize()` 连带清空累积缓冲，因此关掉预览。
- `minSamples = 0` 让淡入状态不必等一次异步回测量就到位，`autoClear` 因此始终为真——`alpha: false` 且没有 `preserveDrawingBuffer`，那块缓冲的内容是不确定的。
- 结果是只有一个累积分辨率，且它总是全分辨率。

### 6.2 尺寸与路径预算

`syncRenderSize()` 每帧按 `renderer.getSize()`（CSS 尺寸，不含 devicePixelRatio）乘 `renderScale` 调 `tracer.setSize()`，并把 `frameBudget` 抬到至少宽×高。依据是库内部的槽位数学：

- wavefront 的路径槽池等于 `min(frameBudget, 像素数, MAX_RAY_DATA_COUNT)`，而 `MAX_RAY_DATA_COUNT` 由写死的 128MB 缓冲上限算出，约 59.9 万条。
- 若按 DPR=2 的绘制缓冲累积，1600×1000 的窗格是 640 万像素，槽位只够 9% 的像素；`PopulatePixelIndicesKernel` 按像素序号发放，先照亮的是顶部区域——表现为黑块随进度上下跳动。
- 按 CSS 尺寸并把预算兜到像素数后，铺满一次只需个位数帧；更大的窗格仍可能超过槽池上限，用「渲染比例」把像素数压到 60 万以内即可一帧铺满。

### 6.3 静止判定与签名同步

`render()` 返回布尔值：`false` 表示这一帧没有光追画面，由 `renderScene()` 立刻画一帧光栅顶上去。

#### 6.3.1 场景签名与静止判定

```
每帧比较三个场景签名 + 相机漂移：
  topologyKey  受支持 Mesh 的 uuid、几何 attribute version、material 集合、有效可见性
  materialKey  uuid 与 version
  transformKey 受支持 Mesh 的世界矩阵
  cameraDistance(cameraValues, lastCameraValues)

双阈值滞回决定 viewMoving：
  正在光追 → 漂移超过 VIEW_SETTLE_TOLERANCE(1e-4) 算「又开始动」
  正在光栅 → 漂移超过 VIEW_MOVE_TOLERANCE(2e-3) 才算「在动」

在动的帧只记账，不同步也不采样；静止的下一帧一次性交给追踪器
（setScene / updateCamera / updateMaterials / updateTransforms / updateLights / updateEnvironment）
并当场 renderSample()，不设任何静止计时。

累积重启另有阈值：与上次同步相机位置的最大逐元素差超过 CAMERA_RESTART_TOLERANCE(2e-3)
才调 updateCamera()，否则保持累积。
```

滞回加重启阈值是为轨道阻尼的收尾服务的：那串逐帧递减的位移若按单阈值判定，会在阈值上下反复横跳，每帧一次 `reset()`，画面持续闪烁。

#### 6.3.2 BVH 与同步窗口的临时替换

- 拓扑同步时若布料位置或法线 version 改变，先对路径追踪器挂在 `BufferGeometry.boundsTree` 上的 BVH 调 `refit()`；索引缓冲被替换则删掉旧 BVH，让 `setScene()` 重建。
- `withPathTracingScene()` 在同步窗口里做两件临时事：舞台地面换成 `MeshStandardMaterial` 替身；选中高亮、PIN 小球等 Basic/Normal 辅助网格临时隐藏——`three-gpu-pathtracer` 只接受 Standard/Physical 材质，回调结束后恢复原状态。
- 投影在透视与正交之间切换时 `rebindCamera()` 把拓扑键置为 `CAMERA_SWAP_KEY`，触发一次完整重采集。

> **注**：布料每帧变形都会刷新 BVH 并重启渐进采样，动态模拟因此明显比静态预览贵。被临时隐藏的辅助对象只在过渡的光栅帧里出现，光追画面上看不到选中高亮与 PIN 小球。

### 6.4 早期样本的光栅垫底

一个刚开始的光追 pass 前几十个样本既噪又暗（路径还没铺开、降噪也不会跑），直接呈现累积缓冲会先跳变甚至发黑。`drawRasterOverlay()` 在 `blendWeight < 1` 的这些帧里多做一次离屏绘制：

- 把当前 Scene 用光栅管线画进 `blendTarget`（半浮点、绘制缓冲尺寸、不含 tone mapping 的线性 HDR）。
- 以 `1 - blendWeight` 的不透明度把这块全屏四边形叠在刚呈现的光追图之上，得到 `mix(光栅, 光追, blendWeight)`。

#### 6.4.1 四边形的 UV 翻转

四边形不用 `map` 而是 `colorNode = texture(base, uv().flipY())`：

- WebGPU 上渲染目标的第一行在顶部，而全屏四边形顶边的 `uv().y` 是 1，不翻 v 会上下颠倒（three 自己的 `NodeManager` 处理背景时同样如此）。
- `TextureNode` 的自动翻转要等 `builder.isFlipY()`，那在 WebGPU 后端恒为 false。

#### 6.4.2 混合权重与中断

- `blendWeight = 实测每像素样本数 / min(RASTER_BLEND_SAMPLES = 32, maxSamples)`，达到后覆盖层不再绘制，画面是纯光追结果。
- 权重来自 `measuredSamples`，因此中断时（`restartSampling()`）会一并归零、从光栅重新开始。

### 6.5 采样读数

`render()` 末尾的 `readSampleCount(now)` 做节流回读：

- 混合未完成时间隔 `BLEND_READBACK_MS`（60ms）让过渡平滑，之后按 `SAMPLE_READBACK_MS`（250ms）调 `WebGPUPathTracer.getSampleCountsAsync()`，取每像素平均采样数存进 `measuredSamples`；`sampleCount` 读它并夹到 `maxSamples`。
- 每次中断都递增 `sampleGeneration`，回包时代际不符就丢弃，避免把旧图的数字贴到新图上。

> **注**：帧数与样本数不同量级——wavefront 后端一次 `renderSample()` 只推进一个 bounce，`frameBudget` 又限制每帧活跃路径数，一个像素攒满一个样本要跨若干帧；累积到 `maxSamples` 后 GPU 停止取样，读数也随之停止。时间轴左端 `SPP:` / `Cost:` 读数显示的就是这个值与攒到它用的时间（分母为「最大采样数」，06 §5.4）。

### 6.6 参数链路

工程字段 `scene.render.rayTracing` 是唯一来源，缺省或越界由 `normalizeRayTracing()` 收敛。链路分四层：

```
1 渲染标签滑条 → ui/sceneCommands.ts 的 setRayTracingConfig(label, patch)
                 （patchValue 命令：可撤销、标记工程已修改、写进 scene.render.rayTracing）
2 EngineSync 订阅：比较 JSON.stringify(normalizeRayTracing(...)) 签名；renderMode 变化也会重新下发
                 → 更新 ctx.rayConfig，再调 rendererContext.ts 的 setRayTracingConfig(ctx, config)
3 该函数只在 renderMode === 'raytraced' 且 ctx.rayTracer 已就绪时转发，否则只留在 ctx.rayConfig 等懒初始化
4 RayTracingRenderer.setConfig()：六个数值直接映射到 WebGPUPathTracer 同名属性
                 （maxBounces / maxSamples / renderScale / filterGlossyFactor /
                   clampDirect / clampIndirect）→ 处理降噪 → tracer.reset()
                 frameBudget 不在这里赋值：由 syncRenderSize() 每帧取
                 max(配置值, 累积分辨率像素数) 写入（§6.2）
```

- `ctx.rayConfig` 的额外一份是为了在光追实例首次创建时就把工程参数灌进去，避免先按默认值跑一轮。
- 参数一改就从零重新累积。
- 透明层数（`maxTransparentBounces`）与低分辨率预览参数（`lowResScale` 等，§6.1 已关掉预览）没有界面入口；火噪没有专项控制，能调的只有 `clampDirect` / `clampIndirect` 两个钳制值。

> **注**：光追参数是累积的重新开始，不是渐进调整——拖动任一滑条都会把已攒的样本清零。

### 6.7 降噪

走 `three-gpu-pathtracer` 的 `OIDNDenoiser` 加 `oidn-webgpu`：

- 权重打包在 `assets/weights`（Apache-2.0，署名见 `assets/weights/ATTRIBUTION.md`），运行期不联网下载。
- 首次需要时按 `denoiseModel` 经 `bundledAssetUrl()` 取 `/weights/rt_hdr_alb_nrm[_small].tza`（引导模型）与 `/weights/rt_hdr.tza`（颜色模型）；本地开发走站内路径，站点构建走 Function。每个模型只创建一次，缓存在 `denoisers` 表里。
- 路径追踪器只在累积到 `maxSamples`、渲染停止之后才跑降噪，因此「最大采样数」就是降噪的触发点；界面与 `normalizeRayTracing()` 都把它夹在 8~1024，`maxSamples = 0`（无限累积、永不降噪）在本应用不可达。
- `guardDenoiser()` 用 Proxy 包住 `update` / `denoise`：读取、编译或运行期报错都只记一条 console 警告，摘掉 denoiser 并置 `denoiserFailed`，光追继续输出未降噪画面。
- `setConfig()` 是异步的而渲染循环是同步的：等待权重期间 `render()` 照常累积，denoiser 挂上后由下一次 `reset()` 生效。
- 换权重文件只能从上游的 LFS 原始地址取：`https://media.githubusercontent.com/media/RenderKit/oidn-weights/master/<file>`。

> **注**：`denoiserFailed` 在同一光追实例上不会复位——重新开关降噪、切走再切回都不会重试，要再试得刷新页面或让实例销毁重建（例如报错走 `recoverWithRaster()` 之后再切回光追）；界面上没有降噪状态提示。GitHub 的 RAW 视图与 jsDelivr 返回的是 132 字节的 LFS 指针而不是二进制，`initUNetFromURL` 会因此失败。

## 7. 相机与拾取

相机没有 CameraRig 抽象：两台相机与投影直接挂在上下文上，预设与取景共享一份方向表，拾取以表面射线优先。

### 7.1 双相机与投影

`OrbitControls` 在 `createRendererContext()` 内直接创建。

- 透视与正交是同一视口上的两台相机，`ctx.camera` 指向生效的那台：`setCameraProjection(ctx, projection)` 交接位置、朝向与 `controls.object`，并按当前朝向重取景。
- 正交视野高度存 `ctx.orthoViewHeight`，滚轮缩放走相机 `zoom`。
- 投影选择记在界面偏好里，工程文件不存相机状态。

```typescript
const camera = new THREE.PerspectiveCamera(45, width / height, 0.1, 100);
camera.position.set(0, 1.4, 3.2);
controls.enableDamping = true;
controls.dampingFactor = 0.08;
controls.target.set(0, 0.9, 0);   // 对准人体中心
```

### 7.2 视角预设与取景

`ClothPicker.applyPreset()`（`core/engine/clothPicker.ts`）走 `cameraFit.ts` 的 `CAMERA_VIEW_FRAMES`：

- 六个正位（正视/后视/左视/右视/仰视/俯视）加四个 45° 侧位（正左/正右/后左/后右），快捷键是小键盘 `2 8 4 6 0 5` 与 `1 3 7 9`。
- 取景范围取「布料 + 模特 + 可见参考物」的合并 AABB，按当前视口宽高比与视野角算出刚好框住全部对象的距离（`fitCameraToBox()`）；首次加载停在正视。
- 俯视与仰视改用 ±Z 作为 up 向量，避免视线与默认的 +Y 共线时朝向翻转。
- `frameScene()` 只改距离不改朝向，所以滚轮缩放后再取景不会把视角拧回去。

> **注**：双击 3D 空白处是选中版型片或清空选择，相机本身不参与「适应视图」；`F` 只作用于 2D 制版视图。

### 7.3 粒子拾取

`pickClothParticleAtScreen()` 三步，顺序不可交换：

```
1 对合并布料网格做一次表面射线检测（three 的 `Raycaster`）
2 命中 → 命中点转局部坐标，由 trianglePanelIds 求出所属片 → pickNearestAtPoint(point, radius, panelSlot)
         在该点周围做球形查询并限定同片，取三维距离最近的粒子
         球形查询无结果 → 退回命中三角形的角点最近者
3 表面完全没命中 → pickNearestParticle() 的屏幕容差垂距搜索
```

> **注**：单靠垂距搜索不看深度也不看遮挡，射线穿过前片会打到内侧或后片的粒子，因此第 3 步只是兜底；隐藏的版型片不进几何 group，同样点不到。

拾取的 `pointerdown` 监听挂在容器上并以捕获阶段注册，先于 `OrbitControls` 的 canvas 监听，从而只在打 PIN 的点击上 `stopPropagation()`（`ui/viewport3D/useClothPicking.ts`）。修饰键规则见 06 §5.2。
