# UI 与状态管理

这篇讲界面层：状态分成哪几份、每份由谁读写，改动如何经命令进入工程数据并可撤销，两个视口各自怎么刷新，以及菜单、快捷键与本地偏好。代码在 `src/ui/` 与 `src/store/`。

界面是工程状态的订阅者，不是拥有者：可序列化、受撤销历史管辖的是 `Project`；选择、播放、布局与焦点只在运行期存在；偏好与工程档案落在浏览器里。对 `Project` 的任何改动都要走命令，视口、面板、菜单与快捷键只读 store、只派发命令。

章节顺序依次为：状态划分（§1）、事件与订阅（§2）、命令系统（§3）、2D 制版视口（§4）、3D 视口（§5）、场景树与属性面板（§6）、菜单与快捷键（§7）、偏好与本地存储（§8）、一次完整交互的路径（§9）。

## 1. 状态划分

划分依据是四条原则，五个 store 与两份本地存储都由它们推出：

- 单一数据源：`Project` 是工程状态的唯一真相；派生结果（三角化网格、GPU 缓冲、胶囊）不进 store，由工程变化触发重算。
- 命令驱动修改：对 `Project` 的改动必须经 `Command`（§3），不做散落各处的 mutate。
- 运行时状态独立：选择、播放、焦点、视图布局都不进 `Project`，因此不会被序列化。
- 同步通道规则：视图、材质与模拟是否重建，取决于被改字段进的是哪个比较键（§2、§6.5）。

### 1.1 五个 store

| store | 装什么 | 谁写 | 谁读 |
| --- | --- | --- | --- |
| `projectStore` | `project`（提交后不可变）、`clothSignature`（重建档签名）、`history`（`CommandHistory`）、`clipboard`（版片剪贴板）、`recent`（最近工程摘要） | 菜单动作、面板编辑、工程导入 | 几乎所有组件与 `EngineSync` 的引擎副作用 |
| `uiStore` | 布局、分屏比例、焦点窗格、当前工具、选择集、属性页签、面板开关、栏宽、显示模式、相机投影、自动保存间隔 | 面板与工具条、快捷键 | App 布局、菜单模型、两个视口 |
| `simStore` | `isPlaying`、`currentFrame`、`speed`、`isDraping`、`isDraped`、`stepToken`、`resetToken`、`pinsVersion` | 时间轴、快捷键、渲染循环 | 时间轴、3D 视口循环 |
| `perfStore` | `fps`（逐窗格）、`samples3D` | 绘制路径加 500ms 采样 | 时间轴左端读数 |

跨帧的请求用令牌计数器而不是回调：

- `stepToken` / `resetToken` 自增后由 `EngineSync` 的 simStore 订阅消费（`viewport3D/engineSync.ts:108`）。
- `fitToken` 自增触发 2D 适应视图，`pinsVersion` 自增让工具条重读固定点，`refObjectsVersion` 自增刷新场景树与属性面板的参考物列表。

> **注**：发起方（菜单、快捷键、面板）因此不需要持有引擎引用；新增一类跨帧请求时沿用它，而不是把引擎传进界面层。

### 1.2 门面与偏好

- `store/stores.ts` 不含状态，只把四个 store、`computeClothSignature`、`FPS_SAMPLE_MS`、`noteDrawnFrame`、`noteRayTracingSamples`，以及 `uiStore` 的 helper（`is2DFocus` / `is3DFocus` / `isSplitLayout` / `isRightPanelShown` / `leftPaneOf` / `toolPane`）和 `PaneId` / `PropTab` / `ToolType` / `ViewLayout` 类型再导出一次。
- `store/prefs.ts` 是唯一读写 localStorage 的地方（§8）。
- 渲染运行时状态没有独立 store：显示模式选择记在 `uiStore.renderMode`，真正的管线状态（光追实例、加载 Promise、模式分派）挂在 `RendererContext` 上，相机由 `Viewport3D` 持有的 `OrbitControls` 管理，不进入 React 状态。

> **注**：zustand 没有接 devtools 中间件，状态变化不进 Redux DevTools，读快照用 `useProjectStore.getState()` 一类导出（00 §7.3）。UI 统一从 `../store` 引入，新增界面代码不再写更深的 store 路径。

## 2. 状态变化如何扩散

状态同步只有两条通道：界面刷新经 zustand 选择器订阅，引擎更新经 `EngineSync` 的签名比较。一次编辑的扩散路径：

- `projectStore.executeCommand / undo / redo` 先把当前工程 `structuredClone` 成草稿，命令在草稿上就地改动，`commit()` 把草稿连同新的 `meta` 提交为不可变的 `project`，同时重算 `clothSignature`（`projectStore.ts:36` 的 `computeClothSignature`：版型内容 + 成型人体字段 + 全局网格边长；`display` / `transform` / `visible` / `stitchVisible` 这类绘制字段不计入）。
- `ui/viewport3D/engineSync.ts` 的 `EngineSync` 订阅三个 store，对「重建 / 环境图 / 灯光 / 光追 / 参考物列表」五个关注点分别比较各自的键，仅当对应键变化时调用引擎；绘制类关注点在每次提交后整体重读，引擎按内容签名跳过未变化的更新（§5.1）。

> **说明**：工程字段按消费方归入三类通道——重建档（计入 `computeClothSignature`）、绘制档（提交后整体重读、签名去重）、即时直改档（命令执行时直接调用引擎方法，如人体变换与显示效果）。归类判据是子系统重建是否依赖该字段：被依赖而未计入的字段会让画面落后于数据，不被依赖却计入的字段会无谓重置模拟。

## 3. 命令系统

命令是最小可撤销单位：一条命令对应一次可回退的改动，连续小修改靠预览加松手提交避免历史栈爆炸。

### 3.1 接口与历史栈

```typescript
// core/command/command.ts —— Command / ProjectContext / CommandHistory 三者同文件
interface Command { readonly label: string; execute(ctx: ProjectContext): void; undo(ctx: ProjectContext): void; }
interface ProjectContext { project: Project; }   // project 是本次提交的草稿

class CommandHistory {
  private undoStack: Command[]; private redoStack: Command[]; private limit = 100;
  execute(cmd, ctx)   // 执行 → 压入 undoStack（超 100 条丢最早）→ 清空 redoStack
  undo(ctx) / redo(ctx): boolean    // 栈空返回 false
  clear(); canUndo; canRedo; lastLabel; nextLabel
}
```

`projectStore.executeCommand()`（`projectStore.ts:61`）先 `structuredClone` 出草稿，命令在草稿上就地改动，`commit()` 提交为新的不可变工程并刷新 `meta.modifiedAt` 与 `clothSignature`；`undo` / `redo` 同样克隆草稿执行，但保留原修改时间。

> **注**：`undo` / `redo` / `loadProject` 只替换工程对象，不刷新 `modifiedAt`（02 §10.1）。

### 3.2 命令清单

| 命令 | 文件 | 说明 |
| --- | --- | --- |
| `MovePanelsCommand` / `MovePointsCommand` | `patternMoveCommands.ts` | 按总偏移移动一组版型片或选中的点，拖动与方向键共用 |
| `AddPointOnEdgeCommand` | `patternEditCommands.ts` | 在边上加点，原边替换为两条同 `semantic` 的新边 |
| `DeleteSelectionCommand` | `patternEditCommands.ts` | 删除选中的点/边/片，undo 还原被删记录 |
| `PastePanelsCommand` | `panelClipboard.ts` | 粘贴复制的版片：重新分配 id、命名「X 副本」、带着片间缝合关系 |
| `AssignFabricCommand` | `fabricCommands.ts` | 把版型片的材质槽指向另一条记录；传空串即解除指定 |
| `AddFabricCommand` | `fabricCommands.ts` | 按预设新建材质记录（自动唯一命名）并赋给版型片 |
| `DetachFabricCommand` | `fabricCommands.ts` | 为选中版型片复制一份共用中的材质（「引用次数」行的入口） |
| `ApplyTemplateCommand` / `AppendTemplateCommand` | `pattern/template/templateCommands.ts` | 替换或追加一套模板版型（05 §4.2） |
| 内联命令 | `ui/sceneCommands.ts` 的 `patchValue()` | 单值编辑：先读旧值，`Object.is` 相同直接返回，否则执行一条 `execute: 写新值 / undo: 写回旧值` |

`patternCommands.ts` 只做再导出；命令在草稿上改完数据后，由 store 提交与签名重算触发重建（§2）。

### 3.3 一次拖拽对应一个命令

没有合并命令类。连续小修改靠预览加松手提交避免撤销栈爆炸：

| 场景 | 预览 | 提交 |
| --- | --- | --- |
| 2D 拖动 | 偏移只画进 `preview` 覆盖层，工程数据不动（`patternMoveGeometry.previewMove()`） | 松手时先冲掉方向键会话，再用总位移执行一个 `MovePanelsCommand` / `MovePointsCommand` |
| 方向键微调 | `useNudgeSession` 把按键累加进 `NudgeSession.total` 并刷新预览 | 500 ms 无按键、或选中另一组版型片时提交一条命令；提交前后用 `selfPatternChangeRef` 标记，避免自己的工程变化把会话清掉 |
| 3D 变换 | `previewTransform()` 只改引擎里的活对象（人体、参考物） | `commitTransform()` 写回工程并记成一条可撤销命令，因此撤销记录的是编辑前的值 |

## 4. 2D 制版视口

代码在 `ui/viewport2D/`，是 Canvas2D 整帧重绘：没有保留模式，也没有 rAF 循环——`render()` 的依赖（工程、选择、视图、悬停、预览）变化时由 `useEffect` 立刻重绘一次。绘制、取景与输入分派三者互不依赖，工具条的取值多于实际实现的分支。

### 4.1 绘制

```typescript
// render.ts
export interface PreviewDrag { pattern: Pattern; ghost: Vec2 | null; }   // 一次拖动的 dry-run 副本
export interface SceneState {
  pattern: Pattern; view: ViewTransform; selection: string[];
  hoverPointId: string | null; preview: PreviewDrag | null;
  rect: { a: Vec2; b: Vec2 } | null;   // 世界坐标下的框选矩形
  showSeams: boolean;                  // 缝合工具激活或选中边时为真
}
/** 整帧：背景、网格、版型片、点手柄、缝合连线、悬停、ghost 与橡皮筋。 */
export function drawScene(ctx, w, h, scene: SceneState): void;
```

- 画布的 DPR 缩放写在 `index.tsx` 的 `render()` 里，每次重绘都按 `container.clientWidth/Height × devicePixelRatio` 重置；尺寸为 0（窗格隐藏）时直接跳过。
- 缝合连线只在 `showSeams` 时画；拖动期间画的是 `preview.pattern` 副本，工程数据不动。

### 4.2 取景

- `viewMath.ts` 是纯数学：`toScreen` / `toWorld` / `zoomAround` / `fitView` / `snapToGrid`，常量 `MIN_SCALE = 0.5`、`MAX_SCALE = 50`、`SNAP_STEP_CM = 0.5`。
- `useCanvasView.ts` 负责取景与事件：`getCanvasSize` / `eventWorld`（屏幕→世界）/ `fitToPattern`（`uiStore.fitToken` 递增即触发）、滚轮以光标为锚点缩放，以及一个只在尺寸变化时重绘一次的 `ResizeObserver`（不改取景）。
- 与 3D 视口的取景互不相干。

### 4.3 指针与键盘

没有工具类与 `ITool` 接口：输入集中在 `index.tsx` 的三个 handler 里，按 `activeTool` 分支，一次拖动是可判别联合：

```typescript
type Drag =
  | { kind: 'pan'; startX; startY; ox; oy }                                        // 中键 / 空格 / pan 工具
  | { kind: 'move'; target: MoveTarget; geom; anchor; startWorld; offset }          // 拖点或拖整片
  | { kind: 'rect'; startWorld };                                                   // 空白处框选
const HIT_RADIUS_PX = 8;   // 命中半径按 view.scale 换算成世界单位
```

#### 4.3.1 指针分派

`pointerdown` 的分派顺序（不可调换）：

1. 先冲掉方向键会话。
2. 判定平移。
3. 点工具：`nearestEdgeSegment` 命中已选中片的轮廓边就执行 `AddPointOnEdgeCommand`。
4. 选择工具下先找最近点（命中后按归属决定拖点还是拖整片）。
5. 再找片（`visiblePanelUnderPoint`，Ctrl/Shift 加选）。
6. 都没有则开始框选。

`pointermove` 无拖动时只更新 `hoverPointId`；`pointerup` 位移非零才提交一个移动命令并清预览。

#### 4.3.2 吸附与键位

- 位移类操作吸附到 0.5 cm 网格（`snapToGrid`），按住 Alt 自由移动；吸附目标点作为 `ghost` 画进预览。
- 「吸附到已有顶点」没有独立函数，靠近顶点的选择由 `hitTest.ts` 的命中半径承担。
- 空格平移与方向键微调在 `useNudgeSession.ts`（它先查 `is2DFocus(layout, focus)` 才响应）。
- `F` / `Delete` 由全局快捷键表处理（§7），不在 `useNudgeSession.ts` 内。

### 4.4 工具的真实实现度

- `uiStore.ToolType` 有十个取值，`toolPane(tool)` 决定它属于哪个窗格的工具条（`pin` / `unpin` 属 3D，其余属 2D），`setTool()` 在切工具的同时把焦点移到对应窗格。
- 2D 里真正响应画布的只有三个：`select`、`point`（线上加点）、`pan`。
- `seam` 只切换 `showSeams`（缝合连线的可见性），`line` / `curve` / `internalLine` / `dart` 在工具条上有按钮但没有分支实现，绘制工具待完成。
- 新建缝合同样没有入口，缝合关系只由模板写入（05 §4.1），现阶段的工作方式是模板生成版型再用选择与加点调整。

> **注**：工具条上的直线、曲线、内部线、省道按钮当前没有对应实现，选中它们画布不会响应。

## 5. 3D 视口

视口持有引擎实例并把它接进 React：初始化 effect 建立上下文，`EngineSync` 建立后接管全部 store 订阅与帧循环；编辑是否触发重建，由 `clothSignature` 等内容签名决定。

### 5.1 引擎生命周期与订阅

`Viewport3D` 的初始化 effect 建立上下文与引擎（顺序见 01 §4.1、03 §1.1），把引擎实例通过 `onEngineReady` 交给 App 与工具条，然后 `new EngineSync(...)`（`viewport3D/engineSync.ts:53`）。之后全部同步都是它的 store 订阅：

| 订阅（比较键） | 做什么 |
| --- | --- |
| projectStore · `clothSignature` 变化 | 清空选择高亮 → `buildFromProject` → `initSimulator` → 同步选择覆盖层 → `simStore.reset()` 加 `setDraped(false)` 加 `bumpPins()`；进行中的重建由序号令牌作废（`engineSync.ts:127`） |
| projectStore · 每次提交 | `applyFabrics` → `applyPanelVisibility` → `applySeamStitchVisibility` → 同步选择覆盖层（引擎按内容签名跳过未变化的更新） |
| projectStore · 环境图键（`iblObjectKey/iblUrl/iblName` 拼成）变化 | 只在换了哪一张环境图时 `applyEnvironment`；改强度或开关走灯光键 |
| projectStore · 灯光键（规范化灯光列表加 `iblEnabled` 加 `iblIntensity` 加 `toneMapping` 的 JSON）变化 | `applyLightConfig()` |
| projectStore · 光追键（`JSON(normalizeRayTracing(...))`）变化 | 更新 `ctx.rayConfig` 并 `setRayTracingConfig()`（03 §6.6） |
| projectStore · 参考物列表键（`referenceObjects` 的 JSON）变化 | `engine.reconcileReferences()` 同步场景网格，完成后 `bumpRefObjects()` 刷新场景树与面板 |
| uiStore · `renderMode` 变化 | `setRendererMode()`，失败走 `recoverWithRaster`；随后重跑绘制档 |
| uiStore · `cameraProjection` 变化 | `engine.setProjection()` 换相机并重取景 |
| uiStore · `selection` 变化 | `syncSelectionOverlay()` |
| simStore · `stepToken` / `resetToken` | 单步推进一帧（并镜像引擎状态、增帧号）/ `resetSimulation()` |

> **注**：哪些字段变化会重建布料由 `computeClothSignature` 决定——版型、人体尺寸与来源、全局网格边长会重建并回到未着装；其余只重算材质、灯光或画面。

### 5.2 拾取与 PIN

`useClothPicking(canvasRef, containerRef, engineRef)` 在容器上以捕获阶段注册 `pointerdown`，早于 `OrbitControls` 的 canvas 监听，从而只在需要拦截的点击上 `stopPropagation()`。规则：

| 输入 | 行为 |
| --- | --- |
| 左键（`altKey` 或工具为 `pin` / `unpin` 时） | 走粒子拾取：`unpin` 工具或 `Alt+Shift` 拔单点，否则打点 |
| 双击（非 Alt） | `pickPanelAtScreen` 命中片 → `select([id])`；未命中则清空选择 |
| 其他左键 | 不拦截，交给 `OrbitControls` |

- 点落在被点击那片布料上、离点击处最近的网格粒子（球形查询限定同片，见 03 §7.3）；已经假缝住的粒子也会落下小黄点（04 §4.3）。
- 求解器侧的批量 PIN 语义在 [04-布料模拟](./04-布料模拟.md) §4。

### 5.3 变换与重建的分界

`ui/sceneCommands.ts` 是场景对象编辑的统一入口：

| 编辑 | 路径 | 是否重建布料 |
| --- | --- | --- |
| 版型片变换 | `commitTransform()` 改版型内容 → `clothSignature` 变化 | 重建网格并重置模拟 |
| 人体 / 参考物变换 | `previewTransform` 加 `commitTransform`；人体的 `transform` 不计入签名 | 只移动场景对象（命令执行时直接调用引擎方法） |
| 可见性、名称、透明度 | `patchValue` 就地改值；`visible` 等绘制字段被签名排除 | 不重建（可见性走分组重挂，03 §3.5） |
| 材质外观 | `patchValue` 改 `project.fabrics[id]` 记录 | 不重建，就地改材质（03 §3.3） |
| 人体身体参数 | 走 `clothSignature`（成型字段计入） | 重建人体、布料与模拟 |
| 场景设置 | 灯光 / 环境图 / 光追各走 §5.1 比较键 | 只重算对应子系统 |
| 导入（模特 / 参考物 / 环境图） | `ui/modelImport.ts` 把 blob 写入 `oc-objects`，再经 `sceneCommands.ts` 的 `commit*` 命令记录 key | 模特重建布料；参考物走 `reconcileReferences`；环境图只换贴图 |

> **注**：人体变换与显示效果不计入 `clothSignature`，计入后任何一次人体移动都会重建整副布料；新增字段的通道归类见 §2 的说明。

### 5.4 时间轴与性能读数

`panels/timeline.tsx` 的排布分三段：

- 居中一排：重置 / 播放暂停 / 单步三个按钮、帧读数、速度档位（0.25x / 0.5x / 1x / 2x；每帧步数由 01 §4.2 的 `steps` 公式决定，前三档都是每帧一步）。
- 右端：`isDraping` / `isDraped` / `isPlaying` 组合出的状态提示。
- 左端：`perfStore` 读数——光栅化显示 `FPS(3D): n`（每秒实际绘制次数，隐藏窗格为 0），光追显示 `SPP: n/maxSamples` + `Cost: x.xs`（每像素累计采样数 / 最大采样数，以及这一轮采样攒到现在用了多久，03 §6.5）。

`perfStore` 的计数刻意留在模块级变量里而不是 store state：绘制路径每帧只调 `noteDrawnFrame(pane, now)` 与 `noteRayTracingSamples(count, isAccumulating, now)`（`now` 与 `sampleFps` 同为 `performance.now()` 域），App 挂载时开一个 `FPS_SAMPLE_MS = 500` 的 `setInterval` 调 `sampleFps()`，窗口不足或四个值都没变时不 `set`。因此停止绘制的窗格会自己回落到 0，而 store 更新频率被压到 2 Hz。耗时在采样期间随发布时刻增长，`isAccumulating` 转假（攒满 `maxSamples`）的那一帧就冻结，之后的空闲帧不再计入。

## 6. 场景树与属性面板

右栏是上下两段：上段场景树（§6.2），下段属性编辑器（§6.3–§6.6），高度比例由 §6.1 决定。哪些编辑走哪个同步通道，由 §6.5 统一约束。

### 6.1 布局

`RightPanel` 是上下两段的列（Blender 的 Outliner/Properties 结构），段高由 `uiStore.sceneRatio`（0.18–0.6）决定，中间是 `PaneDivider axis="y"`。

### 6.2 场景树

`ui/sceneTree.ts` 的 `buildSceneTree(project)` 产出层级树：

```
@scene 工程名
├── @collection:garment  服装 (n)      每个版型片一行，行 id = pattern.panels 的键
├── @collection:seam     缝纫线 (n)    每个缝口一行，id = `@seam:<seamId>`，行名是它连接的两张片
├── @avatar              模特
├── @collection:reference 参考物 (n)   id = `@ref:<id>`
├── @collection:light    灯光          每盏灯一行 id = `@light:<genId>`，末尾挂 @env 环境光
└── @camera              相机
```

#### 6.2.1 层级与 id

- 前缀 id 的规则保证「按选中项找版型片」的代码不会误命中：所有消费方都先查 `pattern.panels[id]`，带 `@` 的 id 自然落空。
- 有子节点的行点击切换折叠（`uiStore.collapsedOutliner`），标题栏可一键折叠或展开全部。
- 灯光集合行内联「类型下拉 + ＋」，`addLight(type)` 加一盏并立刻选中。

#### 6.2.2 眼睛写入的字段

集合行右端的眼睛由子节点聚合（`isCollectionVisible`），叶子行的眼睛按类型分派到不同字段：

| 行 | 眼睛写什么 |
| --- | --- |
| 版型片 | `Panel.visible` |
| 模特 | `Avatar.display`（`visible` 与 `hidden` 互换） |
| 参考物 | 引擎显隐加 `ReferenceObjectRef.visible` |
| 光源 | `SceneLight.enabled`（`setLightsEnabled`） |
| 环境光 | `LightConfig.iblEnabled`（`setEnvironmentEnabled`） |
| 缝纫线 | `Seam.stitchVisible`（`setSeamsStitchVisible`，纯显示，04 §5.3） |

### 6.3 属性标签与可用性

左缘一条竖排图标标签（只显示图标，名称走 tooltip 与 `aria-label`），可用性由选中对象决定（`panels/properties/constants.ts` 的 `tabsForKind`）：

| 标签 | 内容 | 适用对象 |
| --- | --- | --- |
| 对象 | 名称、可见性、类型与该类型的数据分区 | 除场景与集合外的所有行 |
| 材质 | 材质槽三行加外观参数 | 版型片 |
| 物理 | 面料五项，或模特的碰撞开关 | 版型片、模特 |
| 场景 | 工程统计加全局模拟四项 | 恒可用 |
| 渲染 | 显示模式与色调映射；光追时追加三组 | 恒可用 |

- `propTab` 存上次用的标签，若对新选中对象不适用则当帧回落到第一个可用标签（不需要额外 effect）。
- 未选中或多选时只有场景与渲染可用。

### 6.4 对象标签

`objectTab.tsx` 先渲染所有对象共有的身份块（名称 / 可见性勾选 / 类型注记），再按 kind 分派到 `objectDataSections.tsx` 的数据分区：

| kind | 数据分区 |
| --- | --- |
| 版型片 | 轮廓尺寸、轮廓边数、省道数、内部线数、缝份量、网格边长、着装方式（网格边长读数容易误判，归属规则见 05 §3） |
| 模特 | 显示效果（实体 / 半透明）、身体参数、模型来源（内置下拉 / 导入 / 归一化身高） |
| 参考物 | 透明度、删除参考物体 |
| 光源 | 名称、类型（四种切换并保留已填值）、启用、强度（量程随类型）、颜色、删除光源，再加该类型用得上的位置/目标/距离/锥角/边缘/宽高 |
| 缝纫线 | 两端版片读数、显示缝线、缝型、缝合强度、乙边反向、线色 |
| 环境光 | 启用、强度、导入环境图、恢复内置环境 |
| 相机 | 类型（透视 / 正交）、位置、目标、视野角或视野高度 |

三轴拖拽单元与「复位变换」在 `widgets/numberField.tsx`（`NumberField` 与 `Vec3Field`），数值走 §5.3 的 preview/commit 路径。

### 6.5 编辑到同步通道的纪律

| 编辑类别 | 走哪个通道 | 原因 |
| --- | --- | --- |
| 片几何（变换、缝份量、网格边长） | 重建档：`clothSignature` | 网格要重建，模拟回到初始 |
| 名称、可见性 | 绘制档：每次提交整体重读 | 模拟继续跑，3D 只重挂分组 |
| 面料外观与物理 | 绘制档内的签名分支 | 材质签名与物理签名要变（03 §3.3） |
| 场景设置 | 灯光 / 环境图 / 光追比较键 | 值变了才重算对应子系统 |
| 人体变换与显示效果 | 即时直改档：命令执行时调用引擎方法 | 不计入重建档，否则整副布料重建 |
| 人体身体参数 | 重建档 | 胶囊与环绕基准要重算 |

> **注**：`patchValue(label, read, write, value)` 是唯一的写入口，每条编辑因此都可撤销、都会刷新 `meta.modifiedAt`（02 §10.1）。绕过它直接修改已提交工程不会产生新提交：状态引用未变，组件与订阅收不到通知，也没有撤销路径。

### 6.6 材质标签

按 Blender 的材质槽交互组织三行（`materialTab.tsx`）：

| 行 / 控件 | 作用 |
| --- | --- |
| 名称 | `InlineText` 就地改名（`uniqueFabricName` 防撞名）；改的是记录本身，共用者一起变名。下拉用 `PopupSelect` 在记录之间换槽位，减号按钮解除指定（`fabricId = ''`） |
| 引用次数 | `ValueButton`：无框文本读数；引用者多于一个时它同时是 Make Single User 的入口（`DetachFabricCommand`） |
| 材质模型 | 面料预设下拉加 `IconButton`「＋」：点「＋」才触发 `AddFabricCommand`，所以下拉只是记住用哪种面料、可以连续建 |

- 预设只作为新建起点，已有材质的参数不会被预设覆盖。
- 记录 ID 与说明文字不显示，共用影响由数字的悬停提示说明。
- 所有头部操作都过 `run()`：`executeCommand` 之后调 `applyFabrics()`，由签名决定就地改材质还是重绑槽位。

## 7. 菜单与快捷键

菜单是数据驱动的，渲染层不含业务分支：下拉结构、快捷键与交互导航都由同一份声明产生。`ui/menu/`：

| 文件 | 职责 |
| --- | --- |
| `menuTypes.ts` | `TopMenu` / `MenuLeaf` / `MenuSep` 声明式结构；叶子可带 `accel` / `checked` / `disabled` / `children` / `run` |
| `menuModel.ts` | `buildMenus(state, actions)`：唯一产出下拉结构的地方。`MenuState` 是 stores 的一次快照，勾选、置灰与动态标签由它一次算出。测试锁住两条不变量：启用项必有 `run` 或 `children`，`id` 不重复 |
| `nav.ts` | `{open, sub, active}` 的纯 reducer，鼠标悬停与方向键共用，因此两种输入不可能走出不同状态 |
| `menuStore.ts` | 菜单高亮与模态框状态；`menuOwnsKeyboard()` 决定按键归属 |
| `actions.ts` | `MenuActions` 47 个方法，是菜单项与快捷键共享的实现体；`shortcutActions(actions)` 把注册表 id 映射到同一批方法。菜单项不直接写 store |
| `shortcuts.ts` | 快捷键的单一来源：`comboOf`（菜单右列）、`shortcutsByScope`（帮助 ▸ 总览）、`matchShortcut`（App 按键） |
| `menuDialogs.tsx` | 快捷键总览与关于两个模态框 |

五个顶级菜单：文件、编辑、视图、窗口、帮助。

> **注**：菜单里没有「模拟」与「渲染」下拉——播放与重置在时间轴，PIN、重建、视角、投影、显示在 3D 工具条，材质、物理、场景与光追参数在属性编辑器。

### 7.1 快捷键注册表

`SHORTCUTS` 共 37 条，作用域取值 `'全局' | '3D 视口' | '2D 制版' | '菜单栏'`：

- 分布为全局 19、3D 视口 13、菜单栏 5、`2D 制版` 0 条——2D 的空格平移与方向键在 `useNudgeSession` 里就地处理。
- 别名只有两个：重做的 `Ctrl+Y`、删除的 `Backspace`，别名不进总览。

`app.tsx` 的全局 `keydown` 依次做七道判断：

```
1 事件目标是 INPUT / TEXTAREA / SELECT → 返回
2 menuOwnsKeyboard() → 返回（模态框或展开中的菜单自己处理）
3 matchShortcut(e) 无 id → 返回
4 scope === '菜单栏' → 返回（由菜单自己处理）
5 scope === '3D 视口' 要求 is3DFocus(layout, focus)；scope === '2D 制版' 要求 layout !== '3d'
6 shortcutActions[id] 不存在 → 返回
7 preventDefault() 后执行
```

### 7.2 布局、工具条与焦点

四种主页布局（`ViewLayout`）与窗格顺序：

- `split3d2d`（3 键，默认）、`split2d3d`（4 键）、`2d`（2 键）、`3d`（1 键）。
- `leftPaneOf(layout)` 决定哪一格占左半，两种分屏共用同一组 DOM，只把容器改成 `row-reverse`。
- `viewportLayout.ts` 是纯函数层：`paneFlex` / `isPaneShown` / `splitRatioFromPointer` / `sceneRatioFromPointer` / `leftPanelWidthFromPointer` / `rightPanelWidthFromPointer`，常量 `MIN_PANEL_WIDTH = 160`、`MAX_PANEL_WIDTH = 560`、`MAX_PANEL_SHARE = 0.4`；拖动与份额在任何窗格顺序下共用同一套数学。

窗格状态与分隔条：

- 两个视口始终挂载，切换布局只改 flex 与 `display`：WebGPU 上下文与布料网格都不重建（隐藏期间物理继续推进的规则见 01 §4.2）。
- 四类分隔条共用 `PaneDivider`（`axis: 'x' | 'y'`）：分屏中缝限 0.15–0.85、右侧上下限 0.18–0.6、左右两栏外侧限 160–560 px 且不超过窗口宽度的 40%。
- 焦点窗格有 1px 蓝色描边；App 用捕获阶段的 `pointerdown` 监听抢在视口内部可能 `stopPropagation` 的监听器之前设焦点。空格在 3D 窗格是播放与暂停、在 2D 窗格是平移，靠 `is3DFocus` / `is2DFocus` 区分。
- 窗格被隐藏时 `clientWidth/Height` 为 0：`resizeRenderer` 直接返回，2D 跳过绘制，3D 跳过出图；重新可见时 2D 自动适应版型范围。

### 7.3 菜单交互细节

- 悬停即切换到相邻菜单；菜单外 `pointerdown`（捕获阶段）关闭；方向键、回车、Esc 逐层导航；`Alt+助记符` 打开。
- 子菜单渲染在父项右侧（`left: 100%`），`useLayoutEffect` 量到超出屏幕右缘时改 `right: 100%`；末两个下拉用 `dropdownFlipped` 向右对齐避免溢出。
- 菜单栏右端显示自动保存间隔与最近快照时间，当前工程名绝对居中且不响应指针事件。

## 8. 偏好与本地存储

两份存储互不相干：界面偏好落 localStorage（§8.1），工程档案落 IndexedDB（§8.2），都不进工程文件也不受撤销管辖。

### 8.1 界面偏好（localStorage）

`store/prefs.ts`，键 `oc-ui-prefs-v2`。持久化 14 项：`layout / splitRatio / focus / propTab / renderMode / cameraProjection / sceneRatio / leftPanelWidth / rightPanelWidth / showTemplatePanel / showScenePanel / showPropertiesPanel / showTimeline / autoSaveSeconds`。

不持久化：选择集、当前工具、折叠状态、`fitToken` / `refObjectsVersion` / `lastAutosaveAt` 等一次性状态。相机机位、`renderMode`、`cameraProjection` 都不写进工程文件：前者是运行时状态，后两者是界面偏好。

读取时逐项消毒：

- 枚举走白名单（`shadedWireframe` 在白名单里但不在下拉里，见 03 §5.2）。
- `splitRatio` 夹 0.15–0.85、`sceneRatio` 夹 0.18–0.6、栏宽夹 160–560，`autoSaveSeconds` 只接受 0 / 30 / 60 / 300，坏值退回默认。
- 写入由 `useUIStore.subscribe` 触发，`pickPrefs` 决定落盘字段；存储不可用（隐私模式、禁用 DOM）时读写都静默降级。

### 8.2 工程档案（IndexedDB）

`io/projectArchive.ts` 用库 `oc-projects`，两个 store：`recent`（keyPath `id`，上限 8 条，`sortRecents` 加 `pruneRecents` 保证同 id 覆盖、按时间倒序）与 `autosave`（固定 key，只留最近一份）。库与 store 的划分见 02 §10.2.2。

- 模型二进制在另一个库 `oc-objects`（`io/objectStore.ts`，store `blobs`），工程只记 key（02 §10.2）。
- 所有入口先过 `storageAvailable()` 再 `try/catch`：浏览器拒绝存储时保存与自动保存照常工作，只是不留档。

## 9. 一次交互走过的路径

以「在 2D 里拖动一张已选中的版片」为例：

1. `pointerdown` 命中选中的版片或其轮廓顶点 → `ui/viewport2D/index.tsx` 建立 `move` 拖动状态，工程数据不动（§4.3）。
2. 每次 `pointermove` 更新预览偏移，画布重绘的是 `patternMoveGeometry.previewMove()` 生成的 dry-run 副本（§4.1）。
3. `pointerup` 用总位移提交一条 `MovePanelsCommand`，`projectStore.executeCommand()` 克隆草稿、提交新的不可变工程，刷新 `meta.modifiedAt` 与 `clothSignature`（§3.1、§3.3）。
4. `clothSignature` 命中 `EngineSync` 的重建订阅：引擎重建派生网格与求解器，模拟回到未着装（§5.1；通道划分规则见 §6.5）。
5. 2D 视口的 `render` 依赖变化，整帧重绘新轮廓（§4.1）。
6. `Ctrl+Z` 走 `CommandHistory.undo()`，同一批订阅再跑一次，画面回到编辑前的位形（§3.1）。

同一条路径换个起点就是其它交互：3D 里打 PIN 是 §5.2 → 04 §4.2，属性面板拖滑条是 §6.4 → `patchValue()`，模板「应用」是 §7 → 05 §4.2。
