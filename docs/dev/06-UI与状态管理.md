# UI 与状态管理

这篇讲界面层，代码在 `src/ui/` 与 `src/store/`。界面是工程状态的订阅者，不是拥有者：可序列化、受撤销历史管辖的是 `Project`；选择、播放、布局与焦点只在运行期存在；偏好与工程档案落在浏览器里。对 `Project` 的任何改动都要走命令，视口、面板、菜单与快捷键只读 store、只派发命令。

章节顺序依次为：状态划分（§1）、事件与订阅（§2）、命令系统（§3）、2D 制版视口（§4）、3D 视口（§5）、场景树与属性面板（§6）、菜单与快捷键（§7）、偏好与本地存储（§8）、一次完整交互的路径（§9）。

## 1. 状态划分

划分依据是四条原则，四个 store 与两份本地存储都由它们推出：

- 单一数据源：`Project` 是工程状态的唯一真相；派生结果（三角化网格、GPU 缓冲、胶囊）不进 store，由工程变化触发重算。
- 命令驱动修改：对 `Project` 的改动必须经 `Command`（§3），不做散落各处的 mutate。
- 运行时状态独立：选择、播放、焦点、视图布局都不进 `Project`，因此不会被序列化。
- 同步通道规则：视图、材质与模拟是否重建，取决于被改字段进的是哪个比较键（§2、§6.5）。

### 1.1 四个 store

| store | 装什么 | 谁写 | 谁读 |
| --- | --- | --- | --- |
| `projectStore` | `project`（提交后不可变）、`clothSignature`（重建档签名）、`history`（`CommandHistory`）、`clipboard`（版片剪贴板）、`recent`（最近工程摘要） | 菜单动作、面板编辑、工程导入 | 几乎所有组件与 `EngineSync` 的引擎副作用 |
| `uiStore` | 布局、分屏比例、焦点窗格、当前工具、选择集（异质的 `@kind:id` 行）、属性页签、面板开关、栏宽、显示模式、相机投影、制版显示图层 `displayOptions`、自动保存间隔、瞬时提示 `toast` | 面板与工具条、快捷键 | App 布局、菜单模型、两个视口 |
| `simStore` | `isPlaying`、`currentFrame`、`speed`、`isDressing`、`isDressed`、`stepToken`、`resetToken`、`pinsVersion` | 时间轴、快捷键、渲染循环 | 时间轴、3D 视口循环 |
| `perfStore` | `fps`（逐窗格）、`samples3D`、`costMs3D`、`rayState3D`、`rayUnsupported3D` | 绘制路径加 500 ms 采样 | 时间轴左端读数、3D 工具条的显示下拉 |

跨帧请求用令牌计数器。`stepToken` / `resetToken` 自增后由 `EngineSync` 的 simStore 订阅消费（`viewport3D/engineSync.ts` 构造函数里的第三条订阅）。

`fitToken` 自增触发 2D 适应视图，`pinsVersion` 自增让工具条重读固定点，`refObjectsVersion` 自增刷新场景树与属性面板的参考物列表。

> **注**：发起方（菜单、快捷键、面板）不需要持有引擎引用。

`uiStore.toast` 承载视口下方的瞬时提示：`widgets/toast.tsx` 的 `ToastHost` 订阅它，3.2 秒后自动消失；操作失败统一走 `reportActionError(err)`（console 警告 + `showToast`），结构、制版与降噪失败都用这条通道。

### 1.2 门面与偏好

- `store/stores.ts` 不含状态，只把四个 store 与 `computeClothSignature`、`FPS_SAMPLE_MS`、`noteDrawnFrame`、`noteRayTracingSamples`、`noteRayTraceState`、`noteRayTracingUnsupported` 再导出一次。
- 同一文件还导出 `uiStore` 的 helper（`displayModeOf` / `is2DFocus` / `is3DFocus` / `isSplitLayout` / `isRightPanelShown` / `leftPaneOf` / `toolPane`）与 `DisplayMode` / `PaneId` / `PropTab` / `ToolType` / `ViewLayout` 类型。
- `store/prefs.ts` 是唯一读写 localStorage 的地方（§8）。
- 渲染运行时状态没有独立 store：显示模式选择记在 `uiStore.renderMode`，合身热图与应变热图另记 `fitCheck` / `strainCheck`，三者由 `displayModeOf()` 合成一个显示模式值；管线状态（光追实例、加载 Promise、模式分派）挂在 `RendererContext` 上，相机由 `Viewport3D` 的 `OrbitControls` 管理，不进 React 状态。

> **注**：zustand 没有接 devtools 中间件，状态变化不进 Redux DevTools，读快照用 `useProjectStore.getState()` 一类导出（00 §6.3）。UI 统一从 `../store` 引入。

### 1.3 异质选中行

`uiStore.selection` 是一串 `string`，两种形态混在一起。普通 id 取 `pattern.panels` 的键或场景对象的 `@` 前缀伪 id（§6.2）。

元素行由 `elementNodeId(kind, id)` 生成 `@kind:id`，`kind` 的取值是 `PatternElementKind` 的十二个：`panel` / `point` / `edge` / `internal` / `dart` / `seam` / `notch` / `annotation` / `measurement` / `print` / `topstitch` / `trim`。

实现集中在 `core/model/elementRef.ts`，UI 一侧统一从再导出的 `ui/elementSelection.ts` 引入：

```typescript
export const elementNodeId = (kind: PatternElementKind, id: string): string;  // `@${kind}:${id}`
export function parseElementNodeId(nodeId: string): { kind: PatternElementKind; id: string } | null;
export function isElementNodeId(nodeId: string): boolean;
export function isKind(nodeId: string, kind: PatternElementKind): boolean;
/** 选中行里某一类的对象 id；panel 类还兼容没有 @ 前缀的普通行。 */
export function idsOfKind(selection: readonly string[], kind: PatternElementKind): string[];
/** 选中项牵涉到的版片：直接选中的片，加上选中点/边/内部线/省道/缝合的所属片。 */
export function affectedPanelIds(pattern: Pattern, selection: readonly string[]): string[];
```

- 生产这套行的有三处：场景树的元素子行（§6.2）、2D 拾取（§4.3.1）与【检查】菜单的问题定位（§4.4）；消费它的是属性面板的单行解析（§6.3）、`idsOfKind` 的各个调用方与 `DeleteElementsCommand`。
- `affectedPanelIds()`、`isElementNodeId()`、`isKind()` 三个辅助函数只有 `ui/elementSelection.ts` 的再导出，界面与测试尚无调用方；选片判断直接用 `idsOfKind(selection, 'panel')` 或 `pattern.panels[id]`。
- 删除路径按行形态分岔：片行走 `DeleteSelectionCommand`，其余元素行走 `DeleteElementsCommand`，两者同时存在时由菜单动作 `deleteSelection` 用 `CompositeCommand('删除选中')` 合成一次撤销（§3.2、§7）。
- 3D 的选择覆盖层只认片：`syncSelectionOverlay()` 过滤 `pattern.panels[id]` 且未隐藏的行，元素行自然落空（§5.1）。

## 2. 状态变化如何扩散

状态同步只有两条通道：界面刷新经 zustand 选择器订阅，引擎更新经 `EngineSync` 的签名比较。一次编辑的扩散路径：

- `projectStore` 的执行、撤销、重做都克隆草稿，命令就地改动后提交为不可变工程并重算 `clothSignature`（§3.1.2）。
- `computeClothSignature`（`projectStore.ts`）在 `JSON(pattern)` 序列化时跳过键名 `display` / `visible` / `stitchVisible` / `name` / `locked` / `threadColor`，以及整组生产标记 `notches` / `annotations` / `measurements` / `prints` / `topstitches` / `trims`。
- 模特部分再排除 `name`、`display` 与 `transform`，最后拼上网格边长与内部点采样方式。
- 片级 `transform` 计入重建档，模特变换与各种显隐开关不计入（§6.5）。
- `ui/viewport3D/engineSync.ts` 的 `EngineSync` 订阅三个 store，对【重建 / 环境图 / 光源 / 光追 / 参考物列表】五个关注点比较各自的键，键变才调用引擎；绘制类关注点每次提交后整体重读，按内容签名去重（§5.1）。

> **注**：工程字段按消费方归入重建档、绘制档与即时直改档：重建档计入 `computeClothSignature`，绘制档提交后整体重读并按签名去重，即时直改档在命令执行时直接调用引擎方法（模特变换与外观）。

| 类别 | 典型字段 | 变化后的通道 |
| --- | --- | --- |
| 重建档 | 版型几何（点坐标与手柄、边类型/弧、缝纫线区间/锚点/缝型/强度、片轮廓与孔、逐片 `meshResolutionCm`、片 `transform`、片 `fabricId`、`drape` 等）；模特 `params`、`source`、`glbUrl`；全局 `simulation.meshResolutionCm` | 计入 `computeClothSignature`，触发重建并回到未着装 |
| 绘制档 | 任意层级的 `display` / `visible` / `stitchVisible` / `name`；材质外观与物理；光源与环境光；渲染模式、色调映射、光追参数；工程 `meta` | 不进签名，提交后由 `EngineSync` 整体重读，材质、可见性与缝纫线显隐按各自签名去重 |
| 其他子系统 | 求解运行参数（`gravity`、`wind`、`dt`、`substeps`、`constraintIterations`、`avatarCollision`）、参考物列表、模特 `transform` | 不进签名，按各自通道应用（模特变换走即时直改） |

归类规则是字段被布料网格或约束满足读取则进重建档，键名命中跳过名单或只影响画面则进绘制档；新增字段默认进重建档，要进绘制档需显式加入 `computeClothSignature` 的跳过名单。

## 3. 命令系统

命令是最小可撤销单位：一条命令对应一次可回退的改动。

### 3.1 接口与历史栈

#### 3.1.1 命令接口

```typescript
// core/command/command.ts: Command / ProjectContext / CommandHistory 三者同文件
interface Command { readonly label: string; execute(ctx: ProjectContext): void; undo(ctx: ProjectContext): void; }
interface ProjectContext { project: Project; }   // project 是本次提交的草稿

class CommandHistory {
  private undoStack: Command[]; private redoStack: Command[]; private limit = 100;
  execute(cmd, ctx)   // 执行 → 压入 undoStack（超 100 条丢最早）→ 清空 redoStack
  undo(ctx) / redo(ctx): boolean    // 栈空返回 false
  clear(); canUndo; canRedo; lastLabel; nextLabel
}
```

#### 3.1.2 提交与撤销

`projectStore.executeCommand()` 先 `structuredClone` 出草稿，命令就地改动，`commit()` 提交为新的不可变工程并刷新 `meta.modifiedAt` 与 `clothSignature`；`undo` / `redo` 同样克隆草稿执行，但保留原修改时间。

> **注**：`undo` / `redo` / `loadProject` 只替换工程对象，不刷新 `modifiedAt`（02 §10.1）。

#### 3.1.3 两类命令

两类命令的差别在回滚方式：

```typescript
// core/command/patternSnapshot.ts
/** 编辑前深拷贝整份 `Pattern`（全部集合），restore 就地换回。 */
export class PatternSnapshot { constructor(pattern: Pattern); restore(pattern: Pattern): void; clear(): void; }
/** 有拓扑问题即抛出第一条中文 message。 */
export function assertValidPattern(pattern: Pattern): void;
/** 结构性编辑的基类：快照 → apply() → 校验 → 任一环节抛错就整片回滚。 */
export abstract class SnapshotCommand implements Command {
  abstract readonly label: string;
  protected abstract apply(pattern: Pattern, ctx: ProjectContext): void;
}

// core/command/compositeCommand.ts
/** 多条子命令合成一个撤销单位；任一子命令失败即回滚整片版型。 */
export class CompositeCommand implements Command { constructor(label: string, cmds: Command[]); }
```

- `SnapshotCommand` 的 `apply()` 只管改数据，撤销是整片 `Pattern` 还原，拓扑校验（05 §1.6）看不到半完成状态。
- 其余命令是普通 `Command`，自己记下改前的记录（点、边、片、材质或整份 `sizes`）逐条还原，不执行校验。
- `CompositeCommand` 用在两处：菜单的【删除选中】把 `DeleteSelectionCommand` 与 `DeleteElementsCommand` 合成一次撤销；2D 工具条【智能】的自动排位与【全部接受】把多条移动 / 缝合命令合成一条（§4.4）。

### 3.2 命令清单

`core/command/patternCommands.ts` 是一个 barrel，只再导出下面这些模块的类；命令按用途分文件。【类型】列 S 表示继承 `SnapshotCommand`（快照 + 校验 + 原子回滚），C 表示实现 `Command`（自备回滚数据）。

#### 3.2.1 移动与几何跟随

移动与几何跟随（`patternMoveCommands.ts`、`patternMoveGeometry.ts`）：

| 类型 | 构造签名 | `label` | 说明 |
| --- | --- | --- | --- |
| C | `MovePanelsCommand(panelIds: readonly string[], delta: Vec2)` | 移动版片 | 整片刚体平移：轮廓点（含控制柄）、省尖与省边、内部线顶点、弧的圆心一起走 |
| C | `MovePointsCommand(deltas: Map<string, Vec2>)` | 移动点 | 逐点平移，落在同片上的内部线顶点跟着走（`pointMoveGeometry`）；经过该点的弧边重挂到新端点 |

同一批几何工具供预览与提交共用：

- `panelMoveGeometry()` / `pointMoveGeometry()` 算出 `MoveGeometry{ pointIds, lineVertices }`；
- `translateGeometry()` 就地平移并返回 `MoveRecord`，`restoreGeometry()` 还原；
- `previewMove()` 返回 dry-run 副本给画布。

平移收尾调用 `refitArcs()`（同文件导出，05 §1.2）：

- 两端同走的弧只挪 `center`。
- 一端走的弧重解【两端 + 原弧中点】。
- 三点共线时该边退回直线。

`MoveRecord` 有第三种 `{ kind: 'arc'; edgeId; old: { type, arc? } }`，撤销原样写回类型与弧参数。同一函数也被 `SetEdgeLengthCommand`、`SetEdgeAngleCommand`、`ConnectPointsCommand` 与 `TransferDartCommand` 用来重挂被带动顶点的弧边。

#### 3.2.3 结构与缝合

结构（`patternStructureCommands.ts`，全部 S）：

| 构造签名 | `label` | 说明 |
| --- | --- | --- |
| `AddInternalLineCommand(panelId, points: Vec2[], kind?: 'fold' \| 'decor' \| 'split')` | 添加内部线 | `kind` 默认 `decor`；每个点都必须在轮廓内，否则【内部线必须在版片轮廓内】 |

| `RemoveHoleCommand(panelId, holeLoop: string[])` | 删除内孔 | 按边 id 序列匹配整环，删空后去掉 `holes` 字段 |
| `MergePanelsCommand(panelIds: [string, string])` | 合并版片 | 布尔并；不相交时【两个版片不相交，无法合并】 |
| `CreateDartCommand(panelId, edge1Id, t1, edge2Id, t2, intakeCm, tipPos?)` | 创建省道 | 只支持两条相邻直线省边（`edge1` 的终点是 `edge2` 的起点），省尖缺省取角点向质心 45% 处 |

| `TransferDartCommand(dartId, targetEdgeId, t: number)` | 转移省道 | 只把第一条省边的起点挪到目标边，轮廓不重排，面积守恒是近似的；该点上的弧边重挂 |
| `MirrorPanelCommand(sourcePanelId, axis: MirrorAxis)` | 镜像版片 | `MirrorAxis = 'x' \| 'y' \| 边 id`；新片名【X 镜像】，两片互写 `symmetry`，`mirroredPanelId` 供界面选中；命令自带 `skipMirrorSync` |

### 3.3 一次拖拽对应一个命令

`CompositeCommand` 可以把显式成组的命令合并为一个撤销单位（§3.1）。连续小修改靠预览加松手提交避免撤销历史无限增长：

| 场景 | 预览 | 提交 |
| --- | --- | --- |
| 2D 拖动 | 偏移只画进 `preview` 覆盖层，工程数据不动（`patternMoveGeometry.previewMove()`） | 松手时先冲掉方向键会话，再用总位移执行一个 `MovePanelsCommand` / `MovePointsCommand` |
| 2D 拖控制柄 | `withHandle()` 生成 dry-run 副本画进 `preview`，镜像规则与命令一致 | 松手执行一个 `SetPointHandleCommand` |
| 方向键微调 | `useNudgeSession` 用纯函数 `advanceNudge()` 把按键累加进 `NudgeSession.total` 并刷新预览 | **一次按住 = 一条命令**：松开方向键提交，换选中的片、指针按下、窗口失焦、组件卸载、别处改了工程也都先提交（`selfPatternChangeRef` 标记自己那次，避免自己把会话清掉）。没有空闲计时器 |
| 右键精确输入 | 无预览 | 面板或点选中时执行 `MovePanelsCommand` / `MovePointsCommand`（§4.3.3） |
| 3D 变换 | `previewTransform()` 只改引擎里的活对象（模特、参考物） | `commitTransform()` 写回工程并记成一条可撤销命令，因此撤销记录的是编辑前的值 |

## 4. 2D 制版视口

代码在 `ui/viewport2D/`，是 Canvas2D 整帧重绘：没有保留模式，也没有 rAF 循环，`render()` 的依赖（工程、选择、视图、悬停、预览、进行中的笔迹、吸附提示、图层开关、套叠轮廓）变化时由 `useEffect` 立刻重绘一次。工具条上的每个工具都有对应分支（§4.4）。

### 4.1 绘制

#### 4.1.1 绘制输入

#### 4.1.2 图层顺序

图层顺序固定：套叠轮廓在最底、片填充与轮廓、内孔、逐边高亮（黄色 4 px，只在选中了边或缝合笔迹进行中时）、片名、轮廓顶点与控制柄、内部线（`fold` 蓝虚线、`decor` 灰虚线、`split` 紫实线）、省道（橙色虚线连到省尖 + 省尖点）。

其后依次是刀口（V 形或钻孔圆）、布纹线（绿色双箭头）、注释文字、尺寸线（`measurementValue()` 读数，角度一位小数、长度两位小数）、缝合连线、拼接预览、元素选中高亮、笔迹预览线、吸附提示、hover、ghost、框选矩形。

缝合连线只在 `showSeams` 时画，画的是 `sampleEdgeInterval()` 给出的区间折线，乙边按 `flip` 取向，缝口 `stitchVisible` 为假时连线与它的选中高亮都不画。

### 4.2 取景

- `viewMath.ts` 是纯数学：`toScreen` / `toWorld` / `zoomAround` / `fitView` / `snapToGrid`，常量 `MIN_SCALE = 0.5`、`MAX_SCALE = 50`、`SNAP_STEP_CM = 0.5`。
- 另有两份纯表：`gridStepCm(scale)` 按缩放给出网格间距（>8 → 5、>3 → 10、否则 20 cm），间距不足 4 px 时继续加倍，背景网格没有开关；`rulerStepCm(scale)` + `rulerTicks()` / `rulerMinorTicks()` / `rulerLabel()` 给标尺的主次刻度与文字（主刻度间距至少 64 px，从 0.1 cm 的阶梯里取）。
- `useCanvasView.ts` 负责取景与事件：`getCanvasSize` / `eventWorld`（屏幕→世界）/ `fitToPattern`（`uiStore.fitToken` 递增即触发）、滚轮以光标为锚点缩放，以及一个只在尺寸变化时重绘一次的 `ResizeObserver`（不改取景）。
- 标尺由 `render.ts` 的 `drawRuler()` 固定在画面最上层（顶边与左边各 18 px 的带，主刻度 7 px、次刻度 4 px，数字居中在刻度上方 / 左侧，角落方块盖住交点）。

```typescript
const SNAP_RADIUS_PX = 8;  // 吸附半径，同样除以 view.scale
```

`MoveTarget` 是 `{ kind: 'panels'; panelIds }` 或 `{ kind: 'points'; pointIds }`；命中半径与吸附半径都换算成世界单位（`8 / view.scale`），因此屏幕上始终约为 8 px。

#### 4.3.1 指针分派

`pointerdown` 的分派顺序（不可调换）：

1. 先冲掉方向键会话，已有拖动则直接返回。
2. 判定平移（中键或按住 `空格`）。
3. 右键（`button === 2`）走精确输入（§4.3.3），不参与任何命中测试。
4. 按工具分派，笔迹与拖动类：`line` / `curve` 追加笔迹点（Shift 约束 45° 整数倍）；`rect` / `circle` / `ellipse` 起 `shape` 拖动；`internalLine` / `split` / `hole` 先 `pickPanel` 定宿主片再追加折线点；`seam` 起 `seamdrag`。
5. 按工具分派，点选类：`notch` 命中边即建刀口；`annotation` 命中片即建注释；`measure` 连点两处建尺寸线；`dart` 三次点击建省道；`point` 在已选片轮廓边（未选片时为全部边）上加点。
6. `select` 工具下依次尝试：控制柄 → 最近点 → 刀口或注释 → 边 → 生产标记 → 片 → 框选；每步命中后写入 `@kind:id` 行或整片 id，Ctrl/Shift 加选。
   - 生产标记是 `MARK_KINDS = ['seam', 'dart', 'internal', 'measurement']`，由 `hitTest.ts` 的 `pickElements(pattern, world, radius, kinds)` 取最近的一条。它们画在片内部，必须排在片实体之前。
   - 命中刀口且不是加选、所属片（含孔环上的边，`panelIdOfEdge` 会查 `holes`）没锁定时，同时起一次 `notch` 拖动：`pointermove` 把世界坐标投影回这条边（`nearestEdgeSegment` + `arcFraction`，弧边按弧长比例）夹到 `0~1`，用 `previewNotch()` 复制一份只改这一处 `t` 的干跑版型交给 `preview`，因此拖动期间工程数据不动。
   - `pointerup` 只在 `t` 真的变过时先结束方向键会话再提交一条 `MoveNotchCommand`。
7. 框选提交走 `elementsInRect(pattern, rect, uiStore.marqueeKinds)`：任一采样点落在框内即命中，版片返回整片 id、其余返回 `@kind:id` 行；`marqueeKinds` 缺省只有 `panel`。

`pointermove` 无拖动时只更新 `hoverPointId`，并为 `CURSOR_TOOLS`（`line` / `curve` / `internalLine` / `split` / `hole` / `dart` / `measure`）刷新笔迹的 `cursor` 与吸附提示。

- `pointerup` 位移非零才提交一个移动命令并清预览。
- `shape` 拖动按 `shapeFrame()` 的尺寸下限 0.5 cm 决定是否建片。
- `rect` 拖动小于 4 px 视为清空选择。

#### 4.3.2 吸附

- `snap.ts` 提供两份候选：
  - `collectSnapCandidates(pattern)` 的静态候选：每个点一条 `endpoint`、每条边中点一条 `midpoint`、两条直线边真正相交处一条 `intersection`（共用端点的相邻边不算）。
  - `collectCursorCandidates(pattern, world, tolerance)` 的跟随鼠标候选：任一边的垂足 `perpendicular`（取采样折线上最近点，须在容差内），以及直线边延长线上的投影 `extension`（投影落在段外但仍在容差内）。
  - `draftWorld` 调 `findSnapAtPattern` 合并两份取最近，同距离按 `KIND_RANK` 决定，顺序为 `endpoint` > `intersection` > `midpoint` > `perpendicular` > `extension` > `grid`；`grid` 在未命中候选时由 `snapToGrid` 生成，`Alt` 关闭捕捉。
  - 五种命中各有独立符号与颜色（`drawSnapHint`）。
- `index.tsx` 的 `draftWorld()`：Alt 为自由画（返回原值、清提示），否则吸附候选、再退回 0.5 cm 网格（`snapToGrid`）。
- 位移类操作（拖片、拖点）只吸附网格，锚点吸附目标作为 `ghost` 画出；按住 Alt 不吸附。
- `resolveDraftPoint()` 是同一段逻辑的纯函数版本，容差写死 `8 / 4`；当前无调用方，界面走 `index.tsx` 的 `draftWorld()`。
- 命中已有顶点由 `hitTest.ts` 的命中半径承担：`nearestPointWithinRadius` / `nearestEdgeSegment`（逐段投影取最近）/ `visiblePanelUnderPoint`（先轮廓内、再边）/ `panelsOfPoint`。
- 框选与生产标记共用同一份几何：私有 `elementGeometry(pattern, kind)` 给每类元素出采样折线（点取位、边取整条、内部线取折线、省道取省尖加两腿、缝合取两端区间、刀口与尺寸线取位置、注释取锚点；`stitchVisible` 为假的缝口不参与），`pickElements` 与 `elementsInRect` 都从它取值。

#### 4.3.3 精确输入与键盘

- 右键弹出 `prompt`：笔迹进行中（`pen` 且已有点）问【输入长度与角度(cm, °)】，默认值 `10, 0`，按极坐标追加一个笔迹点；否则问【输入位移 dx,dy(cm)】，默认值 `0, 0`，先冲掉方向键会话再对选中的片执行 `MovePanelsCommand`、只选中点时执行 `MovePointsCommand`；锁定片与非有限值都被忽略。
- 笔迹键位在 `index.tsx` 的 window `keydown` 里，先要求 `is2DFocus(layout, focus)`：`Enter` 提交、`Escape` 丢弃当前笔迹、`Backspace` 退一个点（只剩一个点时清空）。
- `Enter` 的提交目标：`pen` → `CreatePanelFromPointsCommand`；`polyline` → 按 `mode` 选 `AddInternalLineCommand` / `OutlineSplitCommand` / `OutlineHoleCommand`。
- 双击：`pen` 笔迹同样提交为多边形版片；否则点空白处等价于适应视图（`fitToPattern()`）。
- 空格平移与方向键微调在 `useNudgeSession.ts`：`Shift` 步长 1 cm、否则 0.5 cm；开了【齐码套叠】且只选中一个点、工程有 `activeSizeId` 时，方向键改的是该点在这一码的 `grading` 增量（`SetPointGradingCommand`），不动基码几何；其余情况走 `MovePanelsCommand` 的累加会话。
- 它先查 `is2DFocus(layout, focus)`，`menuOwnsKeyboard()` 为真时让位给菜单，Ctrl/Meta 组合不响应。
- `F` / `Delete` 由全局快捷键表处理（§7），不在 `useNudgeSession.ts` 内。

#### 4.3.4 笔迹状态机

`tools.ts` 的 `DraftState` 是一次输入的唯一状态，切工具时 `index.tsx` 把它清空：

```typescript
export type PolylineMode = 'line' | 'split' | 'hole';
export type DraftState =
  | null
  | { tool: 'pen'; points: Vec2[]; cursor: Vec2; smoothNext: boolean }
  | { tool: 'shape'; shape: 'rect' | 'circle' | 'ellipse'; start: Vec2; current: Vec2 }
  | { tool: 'polyline'; mode: PolylineMode; panelId: string; points: Vec2[]; cursor: Vec2 }
  | { tool: 'dart'; panelId; leg1; leg2; cursor }        // leg1 / leg2 是 { edgeId, t } | null
  | { tool: 'seam'; pickA; drag }                        // pickA 是 { edgeId, t0, t1 } | null
  | { tool: 'measure'; pointAId: string | null; cursor: Vec2 }
  | { tool: 'handleDrag'; pointId: string; which: 'in' | 'out'; cursor: Vec2 };
export function draftIsIdle(draft: DraftState): boolean;   // 工具是否还留着下一次输入
export function shapeFrame(start, current, shape, square): { min: Vec2; max: Vec2 };
export const DEFAULT_DART_INTAKE_CM = 2;                   // 点击建省用的省量，之后可在面板改
export function orderedDartLegs(pattern, first, second): { leg1; leg2 } | null;
```

- 折线的 `mode` 由工具决定：`internalLine` → `line`、`split` → `split`、`hole` → `hole`；宿主片变了或 `mode` 变了就重起一条折线。
- `shapeFrame` 的 `square` 参数当前两处调用都传 `false`：矩形与椭圆的 Shift 约束实际由 `constrainAngle`（拖动方向就近 45°）完成，`circle` 用拖动的半径，Shift 对方圆没有额外效果。
- `smoothNext` 与 `handleDrag` 变体界面未写入（控制柄拖动走 `Drag` 的 `handle`），`draftIsIdle()` 无调用方。
- 曲线工具画的笔迹也提交为 `CreatePanelFromPointsCommand`（全部直线边）。

### 4.4 工具条与工具

#### 4.4.1 工具与归属

`ui/paneToolbars.tsx` 的 `Toolbar2D` 排在 2D 窗格上方，从左到右是：9 个工具按钮、【结构】 / 【标记】 / 【检查】 / 【智能】四个下拉、【框选】 / 【图层】两个下拉、【适应】（即适应视图，`requestFit()`）。工具条在窗格变窄时横向滚动，右侧按钮不被裁掉。

#### 4.4.3 标记、检查与智能

【标记】下拉三项都只切工具：`刀口：单击轮廓边`（`notch`）、`文字注释：单击版片`（`annotation`）、`尺寸线：单击两个点`（`measure`）。

【检查】下拉在展开时才计算，合并三组结果：

- `validatePattern(pattern)` 的拓扑问题；
- `seamWarnings(pattern)` 的缝合提示（行首加【警告：】前缀，`severity === 'warning'`）；
- `validateGrading(pattern, sizes)` 的放码问题。

全部列成中文条目；无问题时显示【未发现问题】。点一条按 `targetId` 依次试 `edge` → 片 → `seam` → `dart`，转成对应的选中行。

【智能】下拉（tooltip【按布纹区域排位，并给出缝合建议】）有两个入口。**自动排位**调 `placePanelsAuto(pattern, { gapCm: 4 })` 并把每片的 `MovePanelsCommand` 合成一条 `CompositeCommand('自动排位')`。

**缝合建议**列 `seamCandidates(pattern, { skipExistingSeams: true })` 的建议行（标签为 `reason · 评分`）；单条接受执行 `CreateFreeSeamCommand`，多于一条时追加【全部接受（n 条）】，用 `CompositeCommand('自动缝合全部建议')` 一次落地。

### 5.1 引擎生命周期与订阅

`Viewport3D` 的初始化 effect 建立上下文与引擎（顺序见 01 §4.1、03 §1.1），引擎经 `onEngineReady` 交给 App 与工具条，随后 `new EngineSync(...)`（`viewport3D/engineSync.ts` 的构造函数），全部同步由它的 store 订阅完成：

| projectStore · 环境图键（`iblObjectKey/iblUrl/iblName` 拼成）变化 | 只在换了哪一张环境图时 `applyEnvironment`；改强度或开关走光源键 |
| projectStore · 光源键（规范化光源列表加 `iblEnabled` 加 `iblIntensity` 加 `toneMapping` 的 JSON）变化 | `applyLightConfig()` |
| projectStore · 光追键（`JSON(normalizeRayTracing(...))`）变化 | 更新 `ctx.rayConfig` 并 `setRayTracingConfig()`（03 §6.6） |
| projectStore · 参考物列表键（`referenceObjects` 的 JSON）变化 | `engine.reconcileReferences()` 同步场景网格，完成后 `bumpRefObjects()` 刷新场景树与面板 |

### 5.2 拾取、拖拽与 PIN

`useClothPicking(canvasRef, containerRef, engineRef)` 在容器上以捕获阶段注册 `pointerdown`，早于 `OrbitControls` 的 canvas 监听，只在需拦截的点击上 `stopPropagation()`。

交互由**悬停**决定（`classify()` 返回 `camera | drag | pin | unpin`），没有「拖拽工具」这一档。手势主体在 `core/engine/clothInteraction.ts` 的 `ClothInteraction`，`GarmentEngine` 只从 `ClothInteractionHost` 取粒子位置与求解器、再对外转发：

| 悬停位置 | 条件 | 光标 | 按下时 |
| --- | --- | --- | --- |
| 布料 | 求解器就绪且 `isPlaying` | 张开的夹子（按下后变闭合） | `beginClothDrag()` + `setPointerCapture`，拦截相机 |
| 布料 | 工具为 `pin`，或按住 `Alt` | 圆圈 + 中心红点 | 在最靠近的粒子上打 PIN，拦截相机 |
| 已有 PIN 标记 | 工具为 `unpin`，或 `Alt+Shift` | 红色叉号 | 拔掉该 PIN，拦截相机 |
| 其他任何位置 | — | 默认箭头 | 不拦截，交给 `OrbitControls` |

- 悬停判定：`hoverClothAtScreen(ndc)` 先取布料最近三角形的命中距离，再由 `bodyOccludesSegment()`（`core/engine/bodyOcclusion.ts`）从相机沿射线向该点做球迹步进，中途进入体内即判为被人体挡住，不算悬停在布料上。
- `hoverPinAtScreen(ndc, 14px)` 按屏幕距离取最近的 3 个 PIN（`pinsByScreenDistance()`、`PIN_HOVER_RADIUS_PX`），逐个剔除被身体挡住的，返回第一个可见的，并由 `setHoveredPin()` 换成红色放大版。叉号只在「看得见且拔得掉」时出现。
- 光标是 `ui/viewport3D/cursors.ts` 的内联 SVG data URL（张开夹子 / 闭合夹子 / 圆圈带红点 / 红叉），黑描边 + 彩色内描边，深浅色布料上都看得见；带填充点的字形由 `dots` 再套一圈黑边。
- 两个夹子由 `clampPaths(open)` 生成：每根臂是一条直杆（单个 `M…L…`），各绕弹簧圈上的点 (±1.2,-10) 转动。闭合态握把 ±9、夹口 ±0.6；张开态把每根杆转 22°，夹口到 ±4.0、握把到 ±5.1。弹簧圈（r=3.2）画在两杆之间，不是关节；两态共用 `transform` 与热点 (19,26)。
- `pointermove` 重算悬停；工具栏、播放状态、`pinsVersion` 变化时由两个 store 的 `subscribe` 重新判定（比较上一次的值，播放中的每帧变化不会触发重算）；`pointerleave` 复位为相机模式，`blur` 先结束拖拽再复位。
- 拖拽会显示抓取点（圆环内 8.5 / 外 11.5 mm、核心 2.5 mm；PIN 小黄点为 r 7 mm 球，悬停高亮放大 1.7 倍）：`beginDrag()` 里 `DragMarker.show()`，随每次回读 `syncMarker()` 跟随该粒子，`endDrag()` 时隐藏（见 [04-布料模拟](./04-布料模拟.md) §2.1）。
- 拖拽：`ClothInteraction.beginDrag(ndc)` 用 `pickClothParticleAtScreen` 取粒子，以它的位置为抓取中心、射线方向为法向过该点建面向相机的平面；`moveDrag(ndc)` 每帧求射线与平面的交点作为目标点；`pointerup` / `pointercancel` 结束拖拽。引擎只把状态交给 `ClothSimulator.setGrab()`，力的作用方式见 04 §2.1。
- 触摸没有悬停：`pointerdown` 时按落点即时判定一次，且**不启用拖拽**（否则轻点选片会被抢走），PIN 工具仍可单点打点/拔点。
- 双击（非 Alt）走 `pickPanelAtScreen` → `select([id])`；触摸轻点（位移 ≤ `TAP_MOVE_SLOP_PX`、时长 ≤ `TAP_MAX_MS`，未被 PIN 消费）走同一条选片路径 `selectPanelAt()`。
- 点落在被点击那片布料上、离点击处最近的网格粒子（球形查询限定同片，见 03 §7.3）。固定集里只有这些手打的点，没有自动固定点（04 §4.3）。
- 求解器侧的批量 PIN 语义在 [04-布料模拟](./04-布料模拟.md) §4。
- 轻点只对 `pointerType === 'touch'` 生效，判据是 `mobileUi.ts` 的纯函数 `isTapGesture`。

### 5.3 变换与重建的分界

`ui/sceneCommands.ts` 是场景对象编辑的统一入口：

| 编辑 | 路径 | 是否重建布料 |
| --- | --- | --- |
| 版片变换 | `commitTransform()` 改版型内容 → `clothSignature` 变化 | 重建网格并重置模拟 |
| 模特 / 参考物变换 | `previewTransform` 加 `commitTransform`；模特的 `transform` 不计入签名 | 只移动场景对象（命令执行时直接调用引擎方法） |
| 可见性、名称、透明度 | `patchValue` 就地改值；`visible` 等绘制字段被签名排除 | 不重建（可见性走分组重挂，03 §3.5） |
| 材质外观 | `patchValue` 改 `project.fabrics[id]` 记录 | 不重建，就地改材质（03 §3.3） |
| 模特体型参数 | 走 `clothSignature`（成型字段计入） | 重建模特、布料与模拟 |
| 场景设置 | 光源 / 环境图 / 光追各走 §5.1 比较键 | 只重算对应子系统 |
| 导入（模特 / 参考物 / 环境图） | `ui/modelImport.ts` 把 blob 写入 `oc-objects`，再经 `sceneCommands.ts` 的 `commit*` 命令记录 key | 模特重建布料；参考物走 `reconcileReferences`；环境图只换贴图 |

> **注**：模特变换与外观不计入 `clothSignature`；通道归类见 §2。

编辑预览改变拖动期间的同步范围：2D 拖动期间工程数据不变（§4.3.1），3D 默认也不动，`uiStore.editPreview` 三档决定要不要让布料跟着拖：

| 档位 | 分辨率 | 拖动中 | 松手后 |
| --- | --- | --- | --- |
| 【关闭】（缺省） | — | 不调引擎，零 GPU 开销 | 正常提交重建 |
| 【低精度】 | `PREVIEW_COARSE_RESOLUTION_CM = 6` | 每片都按粗网格重 triangulate，粒子数变了，带不回垂坠 | 走 `clothSignature` 通道重建并重新垂坠 |
| 【全精度】 | 工程自己的 `meshResolutionCm` | 只有签名变了的片重新生成网格，其余借用已提交网格；粒子数不变，`carryParticleRanges` 带上活的位置并 `rebaseGeometry` | 同上，但因为布局没变通常不触发求解器重建 |

通道与纪律：

- 2D 侧一个 `useEffect` 把 `preview.pattern` 写进 `uiStore.editPreviewPattern`（会话内通道，不写入本地存储），拖动结束、切到【关闭】、窗格卸载都写回 `null`。
- `EngineSync` 只把它存成 `pendingPreviewPattern`，重建在 `loop()` 里每帧最多一次（多个 pointermove 合并），`rebuildsInFlight > 0` 时不打断进行中的重建；`clothSignature` 一变就丢弃队列，提交优先于预览。
- `GarmentEngine.previewEditPattern(project, tier)` **不写** `appliedGeometry`、也不写 `simulatorLayout`：预览借用提交用的片网格合并一次，`finally` 里把 `panelMeshes` 换回，拖完的提交仍走完整增量重建；它也不碰求解器生命周期（不 `initSimulator`、不 `resetSimulation`）。
- 拖完回到提交版型时，若每片都借到了自己的网格且粒子数与求解器一致，就把活的位置整体贴回，未改动的拖动不会把粗网格留在屏幕上。
- `stepSimulation` 的回读做了一次长度检查：预览网格的粒子数与求解器不同时跳过这帧的读写回，避免细网格结果写进粗网格。
- 档位中文名 `关闭 / 低精度 / 全精度` 在 `optionTables.EDIT_PREVIEW_TIERS`，入口是 `Toolbar3D` 最右的下拉【编辑预览】。

### 5.4 时间轴与性能读数

`panels/timeline.tsx` 的排布分三段：

- 居中一排：重置 / 播放暂停 / 单步三个按钮、帧读数与模拟时长、速度档位（0.25x / 0.5x / 1x / 2x；`EngineSync` 的 `stepAccumulator` 跨帧累加 `speed` 后取整，所以 0.25x 每四帧一步、0.5x 每两帧一步、1x 每帧一步、2x 每帧两步，见 01 §4.2）。
- 右端：`isDressing` / `isDressed` / `isPlaying` 组合出的状态提示。
- 左端：`perfStore` 读数。光栅化显示 `FPS(3D): n`（每秒实际绘制次数，隐藏窗格为 0），光追显示 `SPP: n/maxSamples` + `Cost: x.xs`（累计采样数 / 最大采样数，本轮采样已用时间，03 §6.5）。分子为 0 时再追一段状态码：【光追内核加载中】 / 【布料每帧在变】 / 【视角未静止】 / 【光栅过渡中】 / 【本机不支持】（03 §6.5）。

帧读数后面是**模拟时长**：`currentFrame × project.scene.simulation.dt`，用与 `Cost` 相同的 `costLabel` 格式化；它只描述累计模拟时间，与速度档位和播放时长无关。

`perfStore` 的计数用模块级变量，不放进 store state：

- 绘制路径每帧只调 `noteDrawnFrame(pane, now)`、`noteRayTracingSamples(count, isAccumulating, now)`（`now` 与 `sampleFps` 同为 `performance.now()` 域）与 `noteRayTraceState(state)`。
- App 挂载时开一个 `FPS_SAMPLE_MS = 500` 的 `setInterval` 调 `sampleFps()`，窗口不足或几个值都没变时不 `set`。停止绘制的窗格回落到 0，store 更新频率压到 2 Hz。
- 耗时在采样期间随发布时刻增长，`isAccumulating` 转假（达到 `maxSamples`）的那一帧就冻结，之后的空闲帧不再计入。
- 探测被拒是一次性的事件，`noteRayTracingUnsupported(capability)` 直接 `set` 进 `rayUnsupported3D`，不等窗口。

> **说明**：手机外壳没有 `Timeline`，同一批读数落在顶栏；播放与重置在底部动作坞，单步与速度档位在菜单抽屉（§7.4）。

### 6.2 场景树

`ui/sceneTree.ts` 的 `buildSceneTree(project)` 产出层级树：

```
├── @collection:garment  服装 (n)      每个版片一行，行 id = pattern.panels 的键
│   ├── @edge:<edgeId>                按 outlineEdgeIds 顺序，行名取语义或类型
│   ├── @point:<pointId>              轮廓顶点，按轮廓顺序去重，行名【点】
│   ├── @internal:<lineId>            内部线，行名【内部线】
│   ├── @dart:<dartId>                省道，行名【省道】
│   ├── @hole:<panelId>:<i>           镂空 N，子行为该环的边
│   ├── @notch:<notchId>              刀口，只收外轮廓边上的
│   ├── @annotation:<annotationId>    注释
│   └── @measurement:<measurementId>  尺寸线
├── @collection:seam     缝纫线 (n)    每个缝口一行，id = `@seam:<seamId>`，行名是它连接的两张片
├── @collection:print    印花 (n)      每件生产物件一行 id = `@kind:id`，行尾注记所属版片
├── @collection:topstitch 明线 (n)
├── @collection:trim     辅料 (n)
├── @avatar              模特
├── @collection:reference 参考物 (n)   id = `@ref:<id>`
├── @collection:light    光源          每盏灯一行 id = `@light:<genId>`，末尾挂 @env 环境光
└── @camera              相机
```

#### 6.2.1 层级与 id

- 片下的元素子行由 `patternElementChildren(project, panelId)` 生成，id 即 §1.3 的 `@kind:id`，点它与在 2D 点同一处得到同一选中行。
- `ELEMENT_NODE_KINDS` 是 `PATTERN_ELEMENT_KINDS` 去掉 `panel` 的十一类，`SCENE_KIND_LABELS` 给所有行种类配中文名（【点】、【边】、【内部线】、【省道】、【刀口】等）。
- 行名统一走 `elementLabel(project, kind, id)`：先取记录上的自定义 `name`，没有时版片取片名、边取语义名、缝口取【甲片 ⇄ 乙片】、注释取文字，其余取 `SCENE_KIND_LABELS`；场景树与属性面板的标题、名称行读同一个函数。
- 名称的读写对称：`storedSceneName(project, nodeId)` 取落库的名称（元素记录、缝口、模特、光源、环境光、相机、参考物都能存），`writeSceneName(project, nodeId, name)` 写回；空串清掉可选的覆盖名，行名退回默认标签。属性面板的【名称】行对每种行都可编辑，改完写入一条 `重命名<种类>` 命令。
- 边的行名先看 `semantic`（`EDGE_SEMANTIC_LABELS`：脚口 / 领口 / 袖窿 / 侧缝 / 肩线 / 袖山 / 腰节 / 省道 / 内部 / 自由边），没有语义时退回类型（直线边 / 曲线边 / 圆弧边）；`edgeLabel()` 是这两张表的入口。
- 刀口、注释与尺寸线也挂在所属片下：刀口按所属边归片（只认外轮廓边，镂空环上的刀口不进树），注释与尺寸线按 `panelId`；2D 拾取（§4.3.1）与【检查】菜单选中的是同一批 `@kind:id` 行。
- 元素子行的 `hideable` 是 `false`，因此右端不画眼睛；它们也不进 `readTransform` / `writeTransform`（`isSceneNodeId` 为真直接返回 null）。
- 前缀 id 不影响【按选中项找版片】：消费方都先查 `pattern.panels[id]`，带 `@` 的 id 自然落空。
- 合集行单击展开或收起；对象行单击选中。有子节点的对象行用行首箭头或双击展开，标题栏可一键折叠或展开全部。
- 光源集合行内联【类型下拉 + ＋】，`addLight(type)` 加一盏并立刻选中。
- 印花、明线、辅料各自成一级集合（`productionCollection()`），行 id 仍是 `@kind:id`，`note` 写所属版片名；集合行眼睛由子节点聚合。印花集合行内联 ＋：取当前选中的唯一版片，`AddPrintCommand` 把图案放在该片轮廓中心。
- 相机行只显示名称。

#### 6.2.2 眼睛写入的字段

集合行右端的眼睛由子节点聚合（`isCollectionVisible`），叶子行的眼睛按类型分派到不同字段：

| 行 | 眼睛写什么 |
| --- | --- |
| 版片 | `Panel.visible` |
| 模特 | `Avatar.display`（`visible` 与 `hidden` 互换） |
| 参考物 | 引擎显隐加 `ReferenceObjectRef.visible` |
| 光源 | `SceneLight.enabled`（`setLightsEnabled`） |
| 环境光 | `LightConfig.iblEnabled`（`setEnvironmentEnabled`） |
| 缝纫线 | `Seam.stitchVisible`（`setSeamsStitchVisible`，纯显示，04 §5.3） |
| 印花 / 明线 / 辅料 | 各自的 `visible`（`setProductionVisible`），集合行一次写全部子行 |

### 6.3 属性标签与可用性

左缘一条竖排图标标签（只显示图标，名称走 tooltip 与 `aria-label`），可用性由选中对象决定（`panels/properties/constants.ts` 的 `tabsForKind`）：

| 标签 | 内容 | 适用对象 |
| --- | --- | --- |
| 对象 | 身份三项（名称 / 类型 / 可见性·启用）与该类型的数据分区 | 除场景与集合外的所有行 |
| 材质 | 材质槽三行加外观参数 | 版片 |
| 模拟 | 版片的面料物理六项、布料网格（网格密度）与碰撞（碰撞层），或模特的碰撞开关 | 版片、模特 |
| 变换 | 对象的位姿：位置(m)/ 旋转(°)/ 缩放与【复位变换】；光源为方向或位置与目标；版片另有【环绕】分区 | 版片、模特、参考物、光源 |
| 渲染 | 显示模式（光栅化、光追、线框、UV 检查、法线可视化，以及合身热图 / 应变热图）与色调映射；两种热图各自展开同名的【合身热图】【应变热图】区块（阈值或色标、读数与 CSV）；光追时追加三组 | 恒可用 |
| 工程 | 工程名称（可编辑，写 `meta.name`）与统计、【网格生成】（生成方式与网格边长）、全局模拟六项、尺码表 | 恒可用 |

- `propTab` 存上次用的标签，若对新选中对象不适用则当帧回落到第一个可用标签（不需要额外 effect）；未选中任何行时回落到【工程】。
- `usePropsTarget()`（`panels/propertiesEditor.tsx`）把唯一一条选中行解析成编辑对象：元素行按 `parseElementNodeId()` 的 kind 合成节点（不必是场景树里存在的行），标题与名称行取 `elementLabel()`；其余行用 `findSceneNode(buildSceneTree(project), id)` 查。
- `bodyKey` 由 `nodeId + tab + refObjectsVersion` 组成，切换对象或参考物列表变化时让面板重建。

### 6.4 对象标签

#### 6.4.1 身份块

`objectTab.tsx` 先渲染所有对象共有的身份块：

- **名称**：可编辑，值取 `storedSceneName() ?? 行名`。
- **类型**：`SCENE_KIND_LABELS` 加行注记。
- **可见性 / 启用**：版片、参考物、模特、缝纫线写各自的显隐字段，光源与环境光写启用；点、边等元素行没有显隐状态，只有前两项。
- **外观**：只有模特行有，实体 / 半透明两项，写 `Avatar.display`（`visible` / `translucent`）。

- 身份块之后按 kind 分派到 `objectDataSections.tsx` 的数据分区。
- 各分区的【类型】行改名成具体类型（【点类型】 / 【边类型】 / 【光源类型】 / 【相机类型】 / 【尺寸线类型】），与身份块的【类型】区分。

#### 6.4.2 各对象的数据分区

| kind | 数据分区 |
| --- | --- |
| 版片 | 身份块的锁定与分组（`PanelManageRows`）；【版型】：轮廓边、省道、内部线计数，缝份量 0–2 cm，对称轴与镂空环数；【尺寸】：轮廓读数（`panelSizeCm`，不含缝份）+【目标尺寸】两个 `NumberField`（宽 / 高，步长 0.5、两位小数）+ 勾选【等比缩放】，提交 `ScalePanelCommand`；【倒圆角】：半径 `NumberField` 与同名按钮，提交 `FilletCornersCommand`；【生产】：布纹线角度 −180°~180°、布纹线位置（相对轮廓包围盒中心的 X / Y 两个 `NumberField`）、布纹线长度（`NumberField`，填 0 回到自动），三行都提交同一条 `SetPanelGrainCommand`。模拟页为面料物理、独立成块的【布料网格】（网格密度 `NumberField` 0.5–10 cm，步长 0.5，提交 `SetPanelMeshResolutionCommand`，只重建该片；网格边长是批量设置，见 05 §3）与【碰撞】（碰撞层 0–9） |

#### 6.4.3 变换标签

- **变换**：位置(m)、旋转(°)、缩放（0.01–20）三个 `Vec3Field`，位置保留两位小数，加【复位变换】写回单位变换。模特的矩阵与参考物走即时直改，版片的改动随 `clothSignature` 重建布料（§6.5）。

### 6.5 编辑到同步通道的纪律

| 编辑类别 | 走哪个通道 | 原因 |
| --- | --- | --- |
| 片几何（变换、缝份量、网格边长） | 重建档：`clothSignature` | 网格要重建，模拟回到初始 |
| 名称、可见性 | 绘制档：每次提交整体重读 | 模拟继续进行，3D 只重挂分组 |
| 面料外观与物理 | 绘制档内的签名分支 | 材质签名与物理签名要变（03 §3.3） |
| 场景设置 | 光源 / 环境图 / 光追比较键 | 值变了才重算对应子系统 |
| 模特变换与外观 | 即时直改档：命令执行时调用引擎方法 | 不计入重建档，否则整副布料重建 |
| 模特体型参数 | 重建档 | 碰撞体与环绕基准要重算 |

> **注**：属性面板的单值编辑都经 `patchValue(label, read, write, value)`，每条因此可撤销、都会刷新 `meta.modifiedAt`（02 §10.1）。绕过它直接修改已提交工程不会产生新提交：状态引用未变，组件与订阅收不到通知，也没有撤销路径。

> **说明**：结构性编辑不走这条通道，加点、删除、缝合、镜像、放码等走 §3.2 的命令类。

### 6.6 材质标签

材质标签分三行（`materialTab.tsx`）：

| 行 / 控件 | 作用 |
| --- | --- |
| 名称 | `InlineText` 就地改名（`uniqueFabricName` 防撞名）；改的是记录本身，共用者一起变名。下拉用 `PopupSelect` 在记录之间换槽位，减号按钮解除指定（`fabricId = ''`） |

- 预设只作为新建起点，已有材质的参数不会被预设覆盖。

### 6.7 尺码表

工程标签底部是【尺码】一段（`SizeChart`，定义在 `objectDataSections.tsx`、由 `sceneRenderTabs.tsx` 的 `ProjectTab` 挂载）：

| 行 / 按钮 | 作用 |
| --- | --- |
| 未建立 | 没有 `project.sizes` 时的唯一读数 |
| 基码 | `FlexSelect` 选一格，提交 `SetBaseSizeCommand(sizeId)`，`isBase` 全表唯一真 |
| 当前码 | `FlexSelect`，值取 `activeSizeId ?? 基码`（未设当前码时几何仍在基码上）；选中另一码时执行 `ApplySizeCommand(sizeId)`，随后直接调用 `engine.resetSimulation()` 与 `simStore.reset()`，让新尺寸重新垂坠，选中与当前相同则跳过 |
| 每码一行 | 行首【名称】标签后是 `InlineText`（tooltip【尺码名，回车或失焦提交】）改 `SizeDef.label`（`RenameSizeCommand`，空值与改名相同都跳过），行尾按钮依次是 ↑ ↓ − |
| ↑ / ↓ | `ReorderSizesCommand(sizeId, ±1)`；越界时报【该尺码已在首尾，无法再移动】，由 `reportActionError` 弹出提示 |
| − | `RemoveSizeCommand(sizeId)`；删掉基码时把最小 seq 提为基码，当前码被删则 `activeSizeId` 落到 `sizes[0]` |
| 添加尺码 | `AddSizeCommand(labelName)`，新码 label 取 `A`+序号（26 循环），首码自动为基，`seq` 接在最大值之后 |

- 这一段全部走 `patternProductionCommands.ts` 的尺码命令（§3.2）；`patchValue` 不参与尺码。
- `ReorderSizesCommand` 只重排 `seq`（重编成 0..n-1），不动几何与放缩量；`orderedSizes()` 按 `seq` 排序，所以齐码套叠、各码数值表与放码检查的档差方向随排序变。
- 【当前码】换码改写几何，命中 `clothSignature` 并显式重置模拟（§5.1）。
- 点的每码档差行（§6.4）只在有非基码时才出现。

### 6.8 档差剪贴板

`uiStore` 里 `gradingClipboard: Vec2 | null`（配套 `setGradingClipboard`）存【复制】拿走的那一档 X/Y 放缩量，只在本次会话有效、不进工程文件也不进撤销历史。

- 【复制】把当前行的 `{x, y}` 写入剪贴板，不产生命令，不改变撤销栈。
- 【粘贴】的目标点由 `gradingPasteTargets(pattern, 选中点, 当前行点)` 决定：选择集的点按存在性过滤，全空时退回当前行那一个点；`gradingPasteMap()`（`pattern/grading/grading.ts`）产出映射，交给 `SetPointsGradingCommand`，一次粘贴一条撤销记录。
- 剪贴板为空时【粘贴】按钮置灰。

### 7.1 快捷键注册表

`SHORTCUTS` 共 37 条，作用域取值 `'全局' | '3D 视口' | '2D 制版' | '菜单栏'`：

分布为全局 18、3D 视口 13、菜单栏 5、`2D 制版` 1 条（`F` 适应视图）。

2D 的空格平移与方向键由 `useNudgeSession` 处理，笔迹的 `Enter` / `Escape` / `Backspace` 由 `viewport2D/index.tsx` 的 window 监听处理（§4.3.3）。

别名只有两个：重做的 `Ctrl+Y`、删除的 `Backspace`，别名不进总览。

`app.tsx` 的全局 `keydown` 依次做七道判断：

```
1 事件目标是 INPUT / TEXTAREA / SELECT → 返回
2 menuOwnsKeyboard() → 返回（模态框或展开中的菜单自己处理）
3 matchShortcut(e) 无 id → 返回
4 scope === '菜单栏' → 返回（由菜单自己处理）
5 scope === '3D 视口' 要求 is3DFocus(layout, focus)；scope === '2D 制版' 要求 layout !== '3d'
6 shortcutActions[id] 不存在 → 返回
7 preventDefault() 后执行
```

### 7.2 布局、工具条与焦点

四种主页布局（`ViewLayout`）与窗格顺序：

- `split3d2d`（3 键，默认）、`split2d3d`（4 键）、`2d`（2 键）、`3d`（1 键）。
- `leftPaneOf(layout)` 决定哪一格占左半，两种分屏共用同一组 DOM，只把容器改成 `row-reverse`。
- `viewportLayout.ts` 是纯函数层：`paneFlex` / `isPaneShown` / 三个 `…FromPointer` 比例换算（窗格、左右面板宽度），常量 `MIN_PANEL_WIDTH = 160`、`MAX_PANEL_WIDTH = 560`、`MAX_PANEL_SHARE = 0.4`。

窗格状态与分隔条：

- 两个视口始终挂载，切换布局只改 flex 与 `display`：WebGPU 上下文与布料网格都不重建（隐藏期间物理继续推进的规则见 01 §4.2）。
- 四类分隔条共用 `PaneDivider`（`axis: 'x' | 'y'`）：分屏中缝限 0.15–0.85、右侧上下限 0.18–0.6、左右两栏外侧限 160–560 px 且不超过窗口宽度的 40%。
- 焦点窗格描 1 px 蓝色；App 用捕获阶段的 `pointerdown` 早于视口内部可能 `stopPropagation` 的监听器设焦点。空格在 3D 窗格是播放与暂停、在 2D 窗格是平移，靠 `is3DFocus` / `is2DFocus` 区分。
- 窗格被隐藏时 `clientWidth/Height` 为 0：`resizeRenderer` 直接返回，2D 跳过绘制，3D 跳过出图；重新可见时 2D 自动适应版型范围。

### 7.3 菜单交互细节

- 悬停即切换到相邻菜单；菜单外 `pointerdown`（捕获阶段）关闭；方向键、回车、Esc 逐层导航；`Alt+助记符` 打开。
- 子菜单渲染在父项右侧（`left: 100%`），`useLayoutEffect` 量到超出屏幕右缘时改 `right: 100%`；末两个下拉用 `dropdownFlipped` 向右对齐避免溢出。
- 菜单栏右端显示自动保存间隔与最近快照时间，当前工程名绝对居中且不响应指针事件。

### 7.4 两种外壳与手机菜单

`App` 只做一次分支：`ui/mobile/mobileUi.ts` 的 `uiMode()` 决定渲染 `DesktopShell` 还是 `ui/mobile/mobileShell.tsx`，两个外壳共用同一批 `MenuActions`、同一份 stores 与同一个 `Viewport3D`。

- 判据是主指针为触摸且屏幕短边不超过 `PHONE_SHORT_SIDE_MAX = 560` CSS px。
- 结果在首次读取后缓存，分辨率变化与旋转都不重挂视口，WebGPU 上下文与布料网格不重建；`?ui=mobile` / `?ui=desktop` 覆盖判据，用于在桌面检查手机布局。
- `main.tsx` 把模式写进 `<html data-ui-mode>`，`index.css` 的 `--oc-*` 变量随之切换控件字号与高度（桌面 11 px / 20 px，手机 14 px / 34 px）。
- 手机外壳的三处入口：顶栏（【菜单】、工程名、`FPS n` 或 `SPP n/N` 读数、`帧 n`、状态与选中片名）、视口右下角浮动按钮（【视角】 / 【显示】 / 【适应】）、底部动作坞（【自动着装】 / 【播放】·【暂停】 / 【重置】 / `nx 速度` / 【参数】）。抽屉由 `ui/mobile/mobileSheets.tsx` 渲染，一次只开一个。
- 手机不挂 `Viewport2D`，也不渲染 `Toolbar3D` 与 `Timeline`：2D 制版、模板库、PIN 打点、分屏与窗格焦点都不出现在手机上；抽屉只调用触摸流程里成立的动作。
- 抽屉的取值表与桌面同源：`CAMERA_PRESETS` / `CAMERA_PROJECTIONS` / `DISPLAY_MODES` / `PROP_TAB_OPTIONS` / `AUTO_SAVE_ITEMS`，参数抽屉与 `PropertiesEditor` 共用 `usePropsTarget` 的解析结果（§6.3），只把竖排图标栏换成横排标签。
- 路径追踪探测被拒时，三处显示模式入口（工具条【显示】下拉、渲染标签【显示模式】、`DisplaySheet`）都按 `perfStore.rayUnsupported3D` 把【光线追踪】置灰并附原因（03 §5.4）；`DisplaySheet` 从同一份列表里去掉【应变热图】。
- 全局 `keydown` 与外壳无关，接上蓝牙键盘时 §7.1 的注册表照旧生效；手机只有一个 3D 视口，可用的是工程、选择、模拟类条目与全部 `3D 视口` 条目，布局与 2D 制版相关快捷键没有作用视图。

> **注**：手机外壳挂载时只把 `focus` 置为 `3d`（§7.1 作用域判断需要），不改写持久化的 `layout`；同一浏览器 Profile 也可能打开电脑端外壳。

- 枚举走白名单（`shadedWireframe` 在白名单里但不在下拉里，见 03 §5.2）；`editPreview` 只接受 `off / low / full`。
- `splitRatio` 夹 0.15–0.85、`sceneRatio` 夹 0.18–0.6、栏宽夹 160–560，`autoSaveSeconds` 只接受 0 / 30 / 60 / 300（默认 60），坏值退回默认。
- 写入由 `useUIStore.subscribe` 触发，`pickPrefs` 决定写入本地存储的字段；存储不可用（隐私模式、禁用 DOM）时读写都静默降级。

### 8.2 工程档案（IndexedDB）

`io/projectArchive.ts` 用库 `oc-projects`，两个 store。`recent` 的 keyPath 是 `id`，上限 8 条，`sortRecents` 加 `pruneRecents` 保证同 id 覆盖、按时间倒序。

`autosave` 的 key 是快照写入时间，上限 `AUTOSAVE_LIMIT = 5` 条，`sortAutosaves` 加 `pruneAutosaves` 保证按时间倒序、超出即删最旧。

`saveAutosave` 返回刚写入的快照，`listAutosaves` 列出全部快照摘要，`readAutosave(id?)` 按 id 取指定一份，不传则取最新。库与 store 的划分见 02 §10.2.2。

模型二进制在另一个库 `oc-objects`（`io/objectStore.ts`，store `blobs`），工程只记 key（02 §10.2）。

所有入口先过 `storageAvailable()` 再 `try/catch`，浏览器拒绝存储时保存与自动保存照常工作，只是不留档。

## 9. 一次交互走过的路径

以【在 2D 里拖动一张已选中的版片】为例：

1. `pointerdown` 命中版片或轮廓顶点 → `ui/viewport2D/index.tsx` 建立 `move` 状态，工程数据不动（§4.3）。
2. `pointermove` 刷新预览偏移，画布重绘 `previewMove()` 的 dry-run 副本（§4.1）；【编辑预览】开启时副本经 `uiStore.editPreviewPattern` 交给 3D，每帧最多重画一次网格（§5.3）。
3. `pointerup` 按总位移提交一条 `MovePanelsCommand`，克隆草稿后提交不可变工程，刷新 `meta.modifiedAt` 与 `clothSignature`（§3.1、§3.3）。
4. `clothSignature` 触发 `EngineSync` 重建网格与求解器，模拟回到未着装（§5.1、§6.5）。
5. 2D 视口的 `render` 依赖变化，整帧重绘新轮廓（§4.1）。
6. `Ctrl+Z` 走 `CommandHistory.undo()`，订阅再执行一次，画面回到编辑前（§3.1）。

同一条路径换个起点：3D 打 PIN 见 §5.2 与 04 §4.2，属性面板拖滑条经 `patchValue()`（§6.4），模板【替换版型】见 §7 与 05 §4.2。
