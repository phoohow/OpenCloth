# 开发指南

这篇是仓库的操作手册：如何运行项目、如何修改、如何确认改动可用。

文档各篇覆盖范围见 [README](../../README.md) 的文档索引。章节顺序依次为：环境（§1）、命令与门禁（§2）、文件摆放（§3）、代码规范（§4）、文档规范（§5）、提交（§6）、测试与调试（§7）。

## 1. 环境与启动

### 1.1 需求

| 工具    | 要求                 | 说明                                          |
| ------- | -------------------- | --------------------------------------------- |
| Node.js | 20 以上              | 开发机为 v24；Vite 6 与 vitest 5 均满足       |
| npm     | 10 以上              | 随 Node.js 安装                               |
| Git     | 无版本要求           | 只用于克隆与提交                              |
| 浏览器  | Chrome / Edge 最新版 | 必须支持 WebGPU；Safari 与 Firefox 支持不完整 |

依赖清单中的版本约束：

- `three` 与 `@types/three` 同为 `^0.185.1`；`three-gpu-pathtracer@^0.0.27` 要求 r185 以上。
- `oidn-webgpu` 仅在启用降噪时动态导入，三个 `.tza` 权重随 `assets/weights` 打包，见 [03-渲染管线](./03-渲染管线.md) §6.7。
- `@types/node` 供 `vite.config.ts` 的 `path` / `__dirname` 使用（`tsconfig.node.json` 只收录该文件）。
- `test:coverage` 需要现场安装 `@vitest/coverage-v8`，仓库未声明该依赖。

> **注**：`three` 的裸导入由 `vite.config.ts` 精确别名到 `three/webgpu`，两类导入混用会加载两份 three 构建，表现为灯光或材质失效。

### 1.2 启动

```bash
git clone https://github.com/phoohow/OpenCloth.git opencloth
cd opencloth
npm install
npm run dev
```

- 服务地址 `http://localhost:5173`；`vite.config.ts` 中 `server.open: true`，启动即打开浏览器并启用 HMR。
- 首屏出现 `#webgpu-error`（`index.html` 的整屏提示层）说明 `navigator.gpu.requestAdapter()` 未取得适配器，需更新浏览器与显卡驱动，或在 `chrome://gpu` 检查状态。
- 出现 3D 视口与人体模型即为启动成功。首次进入载入起步工程：女性人体与环绕在体外的四片 T 恤。

> **注**：WebGPU 检测不通过时应用不再降级到其他后端，整屏提示是唯一的兜底——没有第二套渲染后端。

## 2. 命令与验证门禁

### 2.1 npm 脚本

| 命令                            | 行为                                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run dev`                   | 开发服务器（HMR）                                                                                                                     |
| `npm run build`                 | `tsc -b` 类型检查（含 `test/`）+ 生产构建到 `dist/`                                                                                   |
| `npm run build:site`            | 站点构建到 `dist/site/`：`publicDir` 不进包，内置资源改由站点 Storage 经 Function 提供，产物交给 `scripts/check-site-bundle.mjs` 校验 |
| `npm run preview`               | 本地预览生产构建                                                                                                                      |
| `npm test` / `npm run test:run` | vitest watch / 单次运行                                                                                                               |
| `npm run test:coverage`         | `vitest run --coverage`，需要现场安装 `@vitest/coverage-v8`（§1.1）                                                                    |
| `npm run typecheck`             | `tsc --noEmit`                                                                                                                        |
| `npm run lint`                  | 缺少 `eslint.config.js`，当前不可用（§4.5）                                                                                           |

### 2.2 门禁

日常验证只有三条命令，全部通过即视为改动可交付：

```bash
npm run typecheck   # 0 error
npm run test:run    # 42 files / 395 tests 全部通过
npm run build       # 构建成功（chunk >500kB 警告为已知项）
```

- `npm run build:site` 仅在改动构建链、内置资源或 `functions/` 时执行。
- vitest 运行在 Node 环境，不含 WebGPU。

> **注**：改动 WGSL、渲染路径或模拟数值后必须在浏览器中确认实际画面与回读数据（§7.3），三条命令全绿并不能说明渲染结果正确。

## 3. 目录与文件

```
opencloth/
├── assets/          # publicDir：内置人体 GLB、HDR 环境、OIDN 权重、各类 ATTRIBUTION.md
├── docs/            # user/（含 user/images/）与 dev/
├── functions/       # 站点 Function：index.ts 入口 + handler.ts 资源路由
├── scripts/         # Node 侧构建校验与本地预览脚本
├── src/             # 应用代码（分层见 01 §1）
├── test/            # vitest 用例
├── index.html       # Vite 入口与 #webgpu-error 提示层
├── vite.config.ts   # publicDir / define / three 别名 / outDir
└── tsconfig.json    # src+test；引用 tsconfig.node.json（vite.config.ts）
```

- 生产代码只进 `src/`。用例统一放 `test/`，按被测文件的相对路径镜像（`src/pattern/geom/offset.ts` → `test/pattern/geom/offset.test.ts`），引用被测文件用 `../../../src/...`。vitest 默认收集 `test/**/*.test.ts`，无需配置。
- `src/tools/` 是 Node 侧产出工具，应用代码不导入它。
- 静态资源目录为 `assets/`：`vite.config.ts` 中 `publicDir: 'assets'`，代码内使用站内根路径引用，例如 `/models/human-body-f.glb`。
- 新增或改名内置资源：同步修改 `functions/handler.ts` 的 allowlist 与对象键，`test/core/assets/bundledAssetUrls.test.ts` 校验两边一致。
- 修改已上线资源的内容：递增 `bundledAssetUrls.ts` 的 `BUNDLED_ASSET_REVISION`。

> **注**：不递增 `BUNDLED_ASSET_REVISION` 时 `?v=` 不变，`immutable` 缓存不会失效，线上仍会读到旧资源。资源路由链路见 [01-架构总览](./01-架构总览.md) §5。

## 4. 代码规范

### 4.1 TypeScript

`tsconfig.json` 配置：

- `strict: true`，并启用 `noUnusedLocals` / `noUnusedParameters` / `noFallthroughCasesInSwitch`。
- `moduleResolution: "bundler"`，`lib` 为 ES2022 + DOM，`types` 为 `vite/client` 与 `@webgpu/types`。
- `src` 与 `test` 在同一份 `include` 内。

> **注**：测试代码的类型错误同样阻止 `npm run build`，用例与生产代码共用一套类型门禁。

- 禁用 `any`。跨形态桥接使用具体联合类型或可选字段，例如截图函数接收 `HTMLCanvasElement`，而不是接收 renderer 再强制转换。
- 对象类型用 `interface`，联合与工具类型用 `type`；对外类型写 `export type` / `export interface`。
- 命名：类型与组件 `PascalCase`，变量与函数 `camelCase`，常量 `UPPER_SNAKE_CASE`，文件与目录一律 `camelCase`。
- `paths` 中的 `@/* → src/*` 已配置但代码全部使用相对导入。引入别名前先确认它能减少跨层相对路径。

### 4.2 React

函数组件加 Hooks，不使用 class 组件。约定：

- 一个文件一个主组件；Props 类型写 `interface XxxProps`。
- 全局状态走 zustand（[06-UI与状态管理](./06-UI与状态管理.md) §1），局部 UI 状态用 `useState`，副作用用 `useEffect`。

`// eslint-disable-next-line react-hooks/exhaustive-deps` 标记的是仅在挂载时建立一次的 effect（WebGPU 视口初始化、画布取景）。

> **注**：配置 ESLint 后这些标记要保持有效——补全依赖数组会触发上下文或监听器重建，正是这些 effect 要避免的行为。

### 4.3 WGSL

没有独立的 `.wgsl` 文件，全部为 TypeScript 模板字符串常量：

- 命名 `XXX_WGSL`，集中在 `src/sim/shaders/shaders.ts`；`src/sim/gpuPipelines.ts` 与 `src/avatar/sdf/avatarSDF.ts` 各持有自己的片段。
- 常量前保留 `/* wgsl */` 标记供编辑器高亮。

由此产生三条约束：

- `tsc` 不校验 WGSL 语法。非法 WGSL（例如三元表达式，必须写成 `select(c, b, cond)`）不抛错，只使 pipeline 失效并丢弃整次 `submit`，表现为版型片在模拟启动后消失。修改 shader 后需在浏览器中确认回读位置非零。
- 结构体字段按 16 字节对齐，隐式 padding 会造成读数错位。
- 每个 pass 只声明并绑定自己用到的数组，没有共享的粒子结构体。

> **注**：WGSL 语法错误不会出现在 `typecheck` 结果或控制台里，唯一的表现是画面缺片或回读全零。

### 4.4 注释

以 [AGENTS.md](../../AGENTS.md) 为准。要点：

- 注释只用英文。
- 只描述代码在做什么，不记录修改过程、不使用"之前/现在"对照、不复述代码。
- 导出的类、函数、接口字段用 1–2 句 `/** ... */`，代码块用一行 `//`。
- WGSL 源码与中文界面字面量属于代码，不翻译也不改写。

> **注**：界面字面量不参与"英文注释"这条规则——产品界面一律中文，改写或翻译它们属于改动用户可见文案。

### 4.5 ESLint

`package.json` 已安装 `eslint`、`@typescript-eslint/*`、`eslint-plugin-react`、`eslint-plugin-react-hooks` 并声明 `lint` 脚本，但状态是：

- 仓库没有配置文件，`npm run lint` 直接报错退出。
- 实际约束由 `tsc` 严格模式承担。

启用时新建 flat config，规则至少包含：

- `@typescript-eslint/no-explicit-any: error`
- `no-console: ['warn', { allow: ['warn', 'error'] }]`
- `react/react-in-jsx-scope: off`
- 覆盖 `src/**` 与 `test/**`

> **注**：加入 `import/no-cycle` 前先确认插件版本与 flat config 兼容；循环依赖目前由 `tsc -b` 与测试间接把关。

## 5. 文档规范

以下规则仅针对开发文档。

### 5.1 格式规范

- **标题等级**：最深四级。`#` 篇名、`##` 编号章节、`###` 小节、`####` 小节内的并列子主题（编号 `x.y.z`）。四级只在一个小节确实有两三块各自成篇的内容时使用，不为单句话设标题，也不用于强调语气。
- **列表**：并列事项用分点描述——一段里写满三件及以上同类事项时改为列表，枚举三件以上取值或落点时同样改为列表或表格；一项列表只承载一个语义单位，不塞进整段说明，也不为单项设列表。
- **强调与备注**：易错点、后果、约束与待补项用引用块单独成条，标签只用 `> **注**：…`（提示会出错的地方）与 `> **说明**：…`（中性补充）两种；不加 emoji，不把提醒埋进正文句子中间，一条引用块不超过两句。
- **引用**：一律指向编号章节（例：03 §6.3），改标题编号时同步重指所有引用。各篇覆盖范围只在 [README](../../README.md) 的文档索引里列一次。

### 5.2 内容规范

- **结构**：每篇按总-分结构进行组织，开头给出系统或模块的整体轮廓与各章顺序，正文按照顺序描述。每个章节同样按照该结构进行描述。
- **引用**：不写"本节汇总了前文"一类的自指句，跨篇指引直接写在需要它的那句话里。
- **语义**：描述要简洁直观。文档只描述系统现在的行为与选择理由。审阅意见、修改过程、"为什么这样改"的说明都不进正文；一处改动若影响文档所述内容，直接把相应句子改成新的描述。
- **语域**：使用专业书面语，不要使用不常见的表述，使用陈述句、无人称、不用口语转折。
- **文档与代码同步**：改动影响文档所述行为时（字段、章节里写到的测试数、快捷键条数、方法数），在同一次改动里更新相应篇目，并把引用的数字与代码核对；注释规范见 §4.4，它只约束代码注释。

## 6. Git 工作流

- 仓库有 `origin`（`https://github.com/phoohow/OpenCloth.git`），当前只有 `main` 一条分支，提交直接落在 `main`。
- 提交信息用 Conventional Commits：

```
<type>(<scope>): <subject>

type: feat | fix | docs | style | refactor | perf | test | chore
scope: core | pattern | sim | render | ui | store | io | avatar | docs
```

示例：`feat(sim): implement XPBD constraint solver with graph coloring`。

## 7. 测试与调试

### 7.1 单元测试范围

vitest 运行在 Node 环境，无 jsdom，只覆盖不依赖 WebGPU 的纯逻辑。用例关注点按目录分组：

| 目录                | 覆盖                                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------- |
| `test/pattern/`     | 偏移与自交回退、三角化与细化、模板几何与模板命令、环绕摆放 / 炸开 / 缝合折叠                             |
| `test/core/`        | 命令执行与撤销、版片剪贴板、合并布料拓扑、着装阶段编排、材质同步、对象变换、相机取景与拾取、默认值与灯光 |
| `test/io/`          | 工程编解码往返、模型解析、工程压缩包                                                                     |
| `test/sim/`         | 求解器 CPU 位置缓存与运行时固定点、射线拾取                                                              |
| `test/render/`      | 灯光配置重建、光追渐进采样与读数、渲染模式生命周期                                                       |
| `test/store/`       | 偏好持久化、性能读数                                                                                     |
| `test/ui/`          | 2D 命中测试、菜单模型 / 快捷键 / 导航、场景树、视口布局、选项表                                          |
| `test/avatar/`      | 胶囊碰撞体拟合与采样                                                                                     |
| `test/core/assets/` | 内置资源 URL 映射与 Function allowlist 一致                                                              |

### 7.2 集成与性能

- 仓库没有 Playwright、没有任何 E2E 依赖，也没有 CI 配置，三条门禁只能在本地执行。
- 完整流程（初始化 → 载入模板 → 着装 → 模拟 → 导出）只能在浏览器中手动执行。
- 目视比对可用 `src/tools/clothPreview.ts`：Node CLI，用软件渲染器把版型片的解析姿态输出成 PNG，不运行 GPU 模拟。
- 没有 GPU timestamp query，性能判断依据是浏览器 Performance 面板与时间轴的 FPS / Samples 读数；模拟的目标量级见 [04-布料模拟](./04-布料模拟.md) §6.1。

### 7.3 调试入口

按症状定位篇目：

| 症状                                   | 篇目                                                 |
| -------------------------------------- | ---------------------------------------------------- |
| 版型片消失、布料发散、固定点行为异常   | [04-布料模拟](./04-布料模拟.md) §6.2、§6.3           |
| 画面发黑、光追不收敛、噪点、降噪失效   | [03-渲染管线](./03-渲染管线.md) §6                   |
| 材质、灯光、环境贴图不生效             | [03-渲染管线](./03-渲染管线.md) §3、§4               |
| 面板不刷新、撤销行为异常、快捷键不响应 | [06-UI与状态管理](./06-UI与状态管理.md) §1、§3、§7.1 |
| 2D 画布命中或取景                      | [06-UI与状态管理](./06-UI与状态管理.md) §4           |

通用手段：

- Chrome DevTools 的 WebGPU 面板查看 command buffer 与资源；RenderDoc / PIX 可抓取 WebGPU 帧。
- GPU 数据只能经 `mapAsync` 回读后读取。求解器每帧把位置与法线拷贝进 `MAP_READ` 缓冲，`ClothSimulator.getReadbackPositions()` 返回最新一帧（见 04 §3.1）。
- 控制台用 `useProjectStore.getState()` 等导出读取当前 store 快照。zustand 未接 devtools 中间件，状态变化不进入 Redux DevTools。
- React DevTools 查看组件树。界面偏好存于 localStorage 键 `oc-ui-prefs-v2`，清除该键即回到默认布局（见 06 §8.1）。

## 8. 一次改动的完整流程

一次改动从上到下要过的步骤：

1. `npm install` 后 `npm run dev`，在浏览器里确认 WebGPU 可用、起步工程正常（§1）。
2. 生产代码落在 `src/` 对应层，用例同步到 `test/` 的镜像路径（§3）。
3. `npm run typecheck` → `npm run test:run` → `npm run build`，三条全绿（§2.2）。
4. 动过 WGSL、渲染路径或模拟数值时，在浏览器里看画面并回读数值；按症状找篇目（§7.3）。
5. 动过构建链、内置资源或 `functions/` 时补跑 `npm run build:site`，产物由 `scripts/check-site-bundle.mjs` 校验（§2.1、§3）。
6. 按 Conventional Commits 提交到 `main`（§6）。
