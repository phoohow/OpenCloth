# 开发指南

文档各篇覆盖范围见 [README](../../README.md) 的文档索引。章节顺序依次为：环境（§1）、命令与门禁（§2）、目录与文件（§3）、代码规范（§4）、Git 工作流（§5）、测试与调试（§6）、一次改动（§7）。

## 1. 环境与启动

### 1.1 需求

| 工具    | 要求                 | 说明                                          |
| ------- | -------------------- | --------------------------------------------- |
| Node.js | 20 以上              | 开发机为 v24                                  |
| npm     | 10 以上              | 随 Node.js 安装                               |
| Git     | 无版本要求           | 只用于克隆与提交                              |
| 浏览器  | Chrome / Edge 最新版 | 必须支持 WebGPU；Safari 与 Firefox 支持不完整 |

依赖清单中的版本约束：

- `three` 与 `@types/three` 同为 `^0.185.1`；`three-gpu-pathtracer@^0.0.27` 要求 r185 以上。
- `oidn-webgpu` 仅在启用降噪时动态导入，三个 `.tza` 权重随 `assets/weights` 打包，见 [03-渲染管线](./03-渲染管线.md) §6.7。
- `@types/node` 供 `vite.config.ts` 的 `path` / `__dirname` 使用。
- 仓库未声明 `@vitest/coverage-v8`，`test:coverage` 需现场安装。

> **注**：`three` 的裸导入由 `vite.config.ts` 精确别名到 `three/webgpu`，两类导入混用会加载两份 three 构建，表现为光源或材质失效。

### 1.2 启动

```bash
git clone https://github.com/phoohow/OpenCloth.git opencloth
cd opencloth
npm install
npm run dev
```

- 服务地址 `http://localhost:5173`；`vite.config.ts` 中 `server.open: true`，启动即打开浏览器并启用 HMR。
- 首屏出现 `#webgpu-error`（`index.html` 的整屏提示层）说明 `navigator.gpu.requestAdapter()` 未取得适配器，需更新浏览器与显卡驱动，或在 `chrome://gpu` 检查状态。
- 出现 3D 视口与模特模型即为启动成功。首次进入载入起步工程：女性模特与环绕在体外的四片 T 恤。

> **注**：WebGPU 检测不通过时应用不做任何降级处理。

## 2. 命令与验证门禁

### 2.1 npm 脚本

| 命令                            | 行为                                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run dev`                   | 开发服务器                                                                                                                            |
| `npm run build`                 | `tsc -b` 类型检查（含 `test/`）+ 生产构建到 `dist/`                                                                                   |
| `npm run build:site`            | 站点构建到 `dist/site/`：`publicDir` 不进包，内置资源改由站点 Storage 经 Function 提供，产物交给 `scripts/check-site-bundle.mjs` 校验 |
| `npm run preview`               | 本地预览生产构建                                                                                                                      |
| `npm test` / `npm run test:run` | vitest watch / 单次运行                                                                                                               |
| `npm run test:e2e`              | `playwright test`：浏览器冒烟（`e2e/smoke.e2e.ts`）                                                                                   |
| `npm run test:coverage`         | `vitest run --coverage`，需要现场安装 `@vitest/coverage-v8`（§1.1）                                                                    |
| `npm run typecheck`             | `tsc --noEmit`                                                                                                                        |
| `npm run lint`                  | `eslint src --ext .ts,.tsx`：ESLint 9 flat config（`eslint.config.mjs`），规则与层间边界见 §4.5                                              |
| `npm run docs:audit`            | `node scripts/doc-audit.mjs`：校验 `docs/` 的交叉引用、标题层级与长段落                                                               |
| `npm run perf:baseline`         | `node scripts/selfcollision-baseline.mjs`：打印 CPU 自碰撞在 2k/5k/10k 粒子下的基线，不含 GPU |

### 2.2 门禁

日常验证是四条命令，全部通过即视为可交付：

```bash
npm run lint        # 0 error
npm run typecheck   # 0 error
npm run test:run    # 52 files / 469 tests 全部通过
npm run build       # 构建成功（chunk >500kB 警告为已知项）
```

- `npm run build:site` 仅在改动构建链、内置资源或 `functions/` 时执行。
- vitest 运行在 Node 环境，不含 WebGPU。
- `npm run test:e2e` 是浏览器冒烟：构建并在 4183 端口预览，用本机 Chrome（`channel: 'chrome'`，无需下载 Playwright 浏览器）跑打开 → 自动着装 → 导出截图一条路径，产物在 `test-results/`。依赖 WebGPU，不计入上面四条常规门禁；改动初始化、着装或截图导出时执行。

> **注**：改动 WGSL、渲染路径或模拟数值后必须在浏览器中确认实际画面与回读数据（§6.3），四条命令全绿不代表渲染结果正确。

## 3. 目录与文件

### 3.1 目录结构

```
opencloth/
├── assets/          # 内置模特 GLB、HDR 环境、OIDN 权重、各类 ATTRIBUTION.md
├── docs/            # user/（含 user/images/）与 dev/
├── functions/       # 站点 Function：index.ts 入口 + handler.ts 资源路由
├── scripts/         # Node 侧构建校验与本地预览脚本
├── src/             # 应用代码（分层见 01 §1）
├── test/            # vitest 用例
├── index.html       # Vite 入口与 #webgpu-error 提示层
├── vite.config.ts   # publicDir / define / three 别名 / outDir
└── tsconfig.json    # src+test；引用 tsconfig.node.json（vite.config.ts）
```

### 3.2 代码、用例与工具

生产代码只进 `src/`。用例统一放 `test/`，按被测文件的相对路径镜像（`src/pattern/geom/offset.ts` → `test/pattern/geom/offset.test.ts`），引用被测文件用 `../../../src/...`。

vitest 默认收集 `test/**/*.test.ts`，无需配置，哪些改动值得写用例见 §6.1。`src/tools/` 只供离线脚本，应用代码不导入。

### 3.3 静态资源

- 静态资源放 `assets/`（`publicDir: 'assets'`），代码内用站内根路径引用，例如 `/models/human-body-f.glb`。
- 新增或改名内置资源：同步修改 `functions/handler.ts` 的 allowlist 与对象键。两边都在代码里由 `BUNDLED_ASSETS` / `BUNDLED_NOTES` 派生（`handler.ts` 的 `ASSET_KEYS`）。
- 修改已上线资源的内容：递增 `bundledAssetUrls.ts` 的 `BUNDLED_ASSET_REVISION`。

> **注**：已上传到 Storage 的对象键是否齐全需要手工核对；不递增 `BUNDLED_ASSET_REVISION` 时 `?v=` 不变，`immutable` 缓存不会失效，线上仍会读到旧资源。资源路由链路见 [01-架构总览](./01-架构总览.md) §5。

## 4. 代码规范

### 4.1 TypeScript

`tsconfig.json` 配置：

- `strict: true`，并启用 `noUnusedLocals` / `noUnusedParameters` / `noFallthroughCasesInSwitch`。
- `moduleResolution: "bundler"`，`lib` 为 ES2022 + DOM，`types` 为 `vite/client` 与 `@webgpu/types`。
- `src` 与 `test` 在同一份 `include` 内。

> **注**：测试代码的类型错误同样阻止 `npm run build`。

- 禁用 `any`；跨形态桥接使用具体联合类型或可选字段。
- 对象类型用 `interface`，联合与工具类型用 `type`；对外类型写 `export type` / `export interface`。
- 命名：类型与组件 `PascalCase`，变量与函数 `camelCase`，常量 `UPPER_SNAKE_CASE`，文件与目录一律 `camelCase`。
- `paths` 中的 `@/* → src/*` 已配置但代码全部使用相对导入。

### 4.2 React

函数组件加 Hooks，不使用 class 组件。

一个文件一个主组件，Props 类型写 `interface XxxProps`。状态与副作用的归属：

- 全局状态走 zustand（[06-UI与状态管理](./06-UI与状态管理.md) §1）。
- 局部 UI 状态用 `useState`。
- 副作用用 `useEffect`。

`// eslint-disable-next-line react-hooks/exhaustive-deps` 标记的是仅在挂载时建立一次的 effect（WebGPU 视口初始化、画布取景）。

> **注**：补全依赖数组会触发上下文或监听器重建，这些标记要保持有效。

### 4.3 WGSL

没有独立的 `.wgsl` 文件，全部为 TypeScript 模板字符串常量，命名与位置固定：

- 常量名 `XXX_WGSL`，集中在 `src/sim/shaders/shaders.ts`。
- `src/sim/gpuPipelines.ts` 与 `src/avatar/collider/avatarCollider.ts` 各持有自己的片段。
- 常量前保留 `/* wgsl */` 标记供编辑器高亮。

三条约束：

- `tsc` 不校验 WGSL 语法。非法 WGSL（例如三元表达式，必须写成 `select(c, b, cond)`）不抛错，只使 pipeline 失效并丢弃整次 `submit`，表现为版片在模拟启动后消失。
- 结构体字段按 16 字节对齐，隐式 padding 会造成读数错位。
- 每个 pass 只声明并绑定自己用到的数组，没有共享的粒子结构体。

> **注**：WGSL 语法错误不会出现在 `typecheck` 结果或控制台里；修改 shader 后需在浏览器中确认回读位置非零。

### 4.4 注释

以 [AGENTS.md](../../AGENTS.md) 为准：

- 注释只用英文。
- 只描述代码在做什么，不记录修改过程、不使用"之前/现在"对照、不复述代码。
- 导出的类、函数、接口字段用 1–2 句 `/** ... */`，代码块用一行 `//`。
- WGSL 源码与中文界面字面量属于代码，不翻译也不改写。

### 4.5 ESLint

规则只守住 §4.1 与 §4.2 的既有约定，不加入风格检查：

- `@typescript-eslint/no-unused-vars` 报错：未使用的变量、参数与导入；`_` 前缀的参数与解构占位除外。
- `@typescript-eslint/no-explicit-any` 报错，对应 §4.1 的禁用 `any`。
- `no-debugger` 报错；`no-console` 只允许 `warn` / `error`，其余为警告（`src/tools/` 与 `engineTiming.ts` 例外）。
- `react-hooks/rules-of-hooks` 报错、`react-hooks/exhaustive-deps` 警告。

层间 import 由 `no-restricted-imports` 强制，patterns 按相对导入路径匹配：

| 层 | 禁止导入 |
| --- | --- |
| `core/model` | `pattern`、`ui`、`render`、`sim`、`io` |
| `pattern` | `ui` |
| `sim` | `ui` |

> **注**：规则不豁免 `import type`；模板卡片的图标键在 `pattern/template/garmentTemplate.ts` 用字面量联合 `TemplateIcon` 声明，UI 侧按 `IconName` 的子集使用。

> **说明**：`import/no-cycle` 未启用，循环依赖仍由 `tsc -b` 与测试间接把关。

## 5. Git 工作流

## 6. 测试与调试

### 6.2 集成与性能

- 仓库没有 CI 配置，四条常规门禁与 `test:e2e` 都只在本地执行。
- 完整流程（初始化 → 载入模板 → 着装 → 模拟 → 导出）的其余组合以浏览器手动验证为准。
- 目视比对用 `src/tools/clothPreview.ts`：Node CLI，用软件渲染器把版片的解析姿态输出成 PNG，不运行 GPU 模拟。
- 没有 GPU timestamp query，性能判断依据是浏览器 Performance 面板与时间轴的 FPS / Samples 读数；模拟的目标量级见 [04-布料模拟](./04-布料模拟.md) §6.1。

### 6.3 调试入口

| 症状                                   | 篇目                                                 |
| -------------------------------------- | ---------------------------------------------------- |
| 版片消失、布料发散、固定点行为异常   | [04-布料模拟](./04-布料模拟.md) §6.2、§6.3           |
| 画面发黑、光追不收敛、噪点、降噪失效   | [03-渲染管线](./03-渲染管线.md) §6                   |
| 材质、光源、环境贴图不生效             | [03-渲染管线](./03-渲染管线.md) §3、§4               |
| 面板不刷新、撤销行为异常、快捷键不响应 | [06-UI与状态管理](./06-UI与状态管理.md) §1、§3、§7 |
| 2D 画布命中或取景                      | [06-UI与状态管理](./06-UI与状态管理.md) §4           |

通用手段：

- Chrome DevTools 的 WebGPU 面板查看 command buffer 与资源；RenderDoc / PIX 可抓取 WebGPU 帧。
- GPU 数据只能经 `mapAsync` 回读。求解器每帧把位置与法线拷贝进 `MAP_READ` 缓冲，`ClothSimulator.getReadbackPositions()` 返回最新一帧（04 §3.1）。
- 控制台用 `useProjectStore.getState()` 等导出读取当前 store 快照。zustand 未接 devtools 中间件。
- 界面偏好存于 localStorage 键 `oc-ui-prefs-v2`，清除该键即回到默认布局（见 06 §8.1）。

## 7. 一次改动的完整流程

1. `npm install` 后 `npm run dev`，确认 WebGPU 可用、起步工程正常（§1）。
2. 生产代码落在 `src/` 对应层，用例同步到 `test/` 的镜像路径（§3）。
3. `npm run lint` → `npm run typecheck` → `npm run test:run` → `npm run build` 全通过（§2.2）。
4. 动过 WGSL、渲染路径或模拟数值时在浏览器确认画面与回读值（§6.3）。
5. 动过构建链、内置资源或 `functions/` 时执行 `npm run build:site`（§2.1、§3）。
6. 按 Conventional Commits 提交到 `main`（§5）。
