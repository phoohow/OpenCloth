# 布料模拟

这篇讲求解器：粒子与约束如何在 CPU 侧建好、每个子步在 GPU 上执行哪些 compute pass、固定点与面料参数如何决定哪些粒子真的动，以及发散时系统的行为。代码在 `src/sim/`，跨片合并与帧编排在 `src/core/engine/`。

布料是 GPU 上的逐帧约束求解：粒子与约束一次建好并按图着色分批，每个子步依次做积分、求解、碰撞与速度更新，所有子步完成后求一遍法线，再把位置与法线拷进回读缓冲交给主线程；主线程回读后做非有限值检查、缝纫线刷新与拾取。约束柔度、子步数与迭代次数决定布料的软硬与开销。

章节顺序依次为：数据布局（§1）、compute pass 划分（§2）、CPU 端编排（§3）、固定点（§4）、引擎侧编排（§5）、性能与稳定性（§6）。

## 1. 数据布局

模拟数据分两侧：GPU 上的粒子与胶囊缓冲，CPU 生成并按批次组织的约束，两者打包成一份模拟输入交给求解器。

### 1.1 GPU 缓冲

`ClothSimulator.setup()`（`sim/clothSimulator.ts`）一次建齐所有资源。粒子一律按 4 个 f32（16 字节）一档：

| 缓冲 | 内容 | 写入方 |
| --- | --- | --- |
| `posInvMassBuf` | 当前位置 xyz + 逆质量 w | UPDATE、SET_PIN |
| `prevPosBuf` | 子步起始位置 xyz 与逆质量（INTEGRATE 整档拷贝） | INTEGRATE |
| `velocityBuf` | 速度 xyz（w 恒 0） | UPDATE |
| `predictedBuf` | 求解器就地修改的预测位置 | 全部 pass |
| `normalsBuf` | 逐粒子法线（w 恒 0） | 法线三段 |
| `indicesBuf` | 三角形索引，u32 独立缓冲（不进 vec4 打包） | setup 一次 |
| `capsuleBuf` | 碰撞胶囊，布局由 `avatar/sdf/avatarSDF.ts` 的 `packCapsules()` 定义 | setup 一次 |
| `pinIndicesBuf` / `pinInvMassBuf` | SET_PIN 的索引清单与逐项逆质量（容量 = 粒子数） | SET_PIN 前 |
| `readbackBuf` / `readbackNormalsBuf` | `MAP_READ` 回读，各 `particleCount × 16` 字节 | 帧末拷贝 |
| 七份 uniform | integrate 64B、collide 32B、update 32B、solve 每批 32B、pin 16B 由 `simUniforms.ts` 打包；normals 16B 与 particleCount 16B 直接在 `clothSimulator.ts` 里建缓冲并写值 | `simUniforms.ts`、`clothSimulator.ts` |

WGSL 侧没有统一的粒子结构体，每个 pass 只声明并绑定自己用到的数组；`createStorageBuffer` / `createUniformBuffer` 与全部管线在 `sim/gpuPipelines.ts`。

### 1.2 约束与批次

约束元素固定 16 字节：`(p0: u32, p1: u32, restLength: f32, compliance: f32)`。结构、剪切、弯曲、缝合四类各持有一份 `BatchedConstraints`（`simTypes.ts`）：

```typescript
interface BatchedConstraints {
  batches: Constraint[][];   // 图着色后的批次，顺序与 buffers 一致
  buffers: GPUBuffer[];      // 每批一个 STORAGE 缓冲
  count: number;             // 合计条数
}
```

`createBindGroups()` 为每一批建一个 SOLVE bind group 与一份记录该批条数的 uniform。数组按 structural → shear → bending → seam 的类型顺序、批内按着色顺序排列，与 `solveBatchCounts` 一一对应（`clothSimulator.ts`）。

### 1.3 CPU 侧生成

```typescript
// sim/buffers/constraintBuilder.ts
/** 逐片生成结构/剪切/弯曲约束，静止长度从 positions 量出。 */
buildMeshConstraints(positions, mesh, fabric, dt) → { structural, shear, bending }
/** 贪心图着色：同批次内任意两条约束不共享粒子。 */
colorConstraints(constraints, particleCount) → Constraint[][]
packConstraints(constraints) → { data: ArrayBuffer; count: number }

// sim/constraintBatches.ts
buildPanelConstraints(input, physics, dt)      // 逐片生成并把 p0/p1 加上 vertexOffset
createBatchedConstraints(device, constraints, particleCount)
rewriteBatches(device, set, constraints, particleCount)  // 拓扑不变时就地覆盖，布局对不上返回 false
```

#### 1.3.1 拓扑约束

| 类型 | 粒子对 | 条数 |
| --- | --- | --- |
| 结构 | 三角形的去重边 | = 边数 |
| 剪切 | 共边两三角形的对顶连线 | = 共享边数 |
| 弯曲 | `buildAdjacency` 给出的相邻三角形对顶（跨两跳） | = 共享边数 |

静止长度一律从该片自己的 3D 位形量出（`panel.positions3D`），柔度由该片材质的对应刚度换算（§5.4）。

#### 1.3.2 柔度换算

`stiffnessToCompliance`（`constraintBuilder.ts`）：

```
softness = 1e-3 + (1 − s)² × 2          （s = 刚度，1 刚性、0 自由）
compliance = softness / (frameDt² × 60²)
```

- 分母把柔度归一化到固定的 60 Hz 帧步长，SOLVE 着色器直接把 compliance 当 α 用（`packSolveParams` 把 dt 写成 0）。
- 因此子步只增加求解遍数，不改变已构建约束集的刚度。
- 换算所用的 `frameDt` 在 setup 时记为 `constraintDt`，运行中换材质时复用同一个值。

#### 1.3.3 缝合与收省约束

闭合类约束不走 `buildMeshConstraints()` 这条流水线：`MergedCloth.buildClosingConstraints()`（`core/engine/mergedCloth.ts`）生成后作为 `ClothSimInput.seamConstraints` 传入，同时按同一顺序填 `seamPairs`（缝纫线叠画与着装动画复用）。

```
建 edgeId → { panelId, 边界顶点序列 } 与每片 vertexOffset
for 每条 Seam:
  A 侧取 seam.a 区间内的边界顶点（intervalVertices 按弧长参数 t0~t1 截取）
  B 侧同样取区间，flip 为真时反向
  两侧都给了 anchorT → 沿锚点各切成两段，分别配对（锚点两侧独立分布吃势）
  compliance = 1 / (max(strength, 0.01) × 3600)
  restLength = 建批时的实际开口距离（gather 且给了 gatherRatio 时乘以该比例）
  n = max(顶点数A, 顶点数B)，按归一化位置配对 → 长短边均匀吃势
for 每片每个 closing 的 Dart:
  两条省边各自按网格间距取样成 run，B 侧反向后配对（省尖对省尖、省根对省根）
  restLength = 0，compliance 用 DART_STITCH_STRENGTH = 1
```

- `strength` 同时决定柔度与断裂阈值：柔度 `1 / (max(strength, 0.01) × 3600)`；每条缝合对的初始开敞距离乘 `seamBreakStretch(strength)`（`sim/seamStrength.ts`）作为 `Constraint.tearLength`，当前间距超过它即判为断裂。断裂在回读后的 CPU 遍里把该约束的静止长度改成当前间距（不再拉合，也不反向推开），且只在前一帧已开启 `seamTearing`（`SimulationConfig`，默认关闭）时执行。收省仍带 `DART_STITCH_STRENGTH = 1`，不参与断裂。
- `seamPairs` 里既可能是缝合对也可能是省边对，后者带 `dartId`；`sewnTargets.ts` 把已闭合的对折叠到同一目标点，着装滑行与闭合结果一致。
- 原始开口长度记在 `ClothSimulator.seamOpenLengths`，供 §3.3 的收缩使用。
- 粒子编号按各片 `vertexOffset` 平移，省边两腿都在同一片内。

> **注**：缝合约束的静止长度等于建批时的实际开口距离，因此初始无应力；着装阶段靠 `setSeamProgress()` 改写静止长度收拢，而不是靠约束力把两片拉合。收省则直接把静止长度写成 0，两条省边被拉到贴合。

#### 1.3.4 折痕约束（fold 内部线）

片内 `InternalLine.kind === 'fold'` 的折线在网格上留下折痕：`panelCreaseEdges()`（`pattern/panel/panelBuilder.ts`）找出折线与三角形边的交叠段，作为该片的 `creaseEdges`（顶点对数组）进入 `ClothSimInput.panels[i].creaseEdges`。

求解器把这些顶点对当作额外弯曲约束，刚度取材质的 `creaseStiffness`（`FabricPhysics.creaseStiffness`，缺省 0.85，0 即不加强）。

折痕只改变已有约束的刚度分组，不新增粒子，也不改变布局指纹；只改 `creaseStiffness` 数值时走 `updateMaterialPhysics()` 的就地重建，增删折线本身会改约束签名、走 `setCreaseEdges()` 换批，两者都不重建几何、不重启模拟。

## 2. Compute pass 划分

八个管线（`sim/gpuPipelines.ts`）全部 `@workgroup_size(256)`，一次帧步按子步重复前四个、在所有子步之后执行法线三段，固定点切换时才执行 SET_PIN：

| pass | 每个 invocation 处理 | 每次帧步执行 |
| --- | --- | --- |
| `INTEGRATE` | 一个粒子 | 每个子步一次 |
| `SOLVE` | 一条约束 | 每个子步：迭代次数 × 批次总数 |
| `COLLIDE` | 一个粒子 | 每个子步一次（恒定提交） |
| `UPDATE` | 一个粒子 | 每个子步一次 |
| `CLEAR_NORMALS` / `NORMALS` / `NORMALIZE` | 一个粒子 / 一个三角形 / 一个粒子 | 所有子步之后一次 |
| `SET_PIN` | 一个清单条目 | 切换固定点时一次 |

### 2.1 积分

```wgsl
// 每个粒子
prevPos[i] = posInvMass[i];                     // 连逆质量一起存，UPDATE 用它判固定
if (invMass == 0.0) { predicted[i] = pos; return; }
accel = gravity + windDir * windSpeed * (1 + 0.3 * sin(time * 2 + i * 0.013));
predicted[i] = pos.xyz + velocity[i].xyz * dt + accel * dt * dt;   // x̃ = x + v·dt + a·dt²
```

`time` 是子步时刻 `frameStart + (sub + 1) × subDt`，风扰动因此在帧内连续，逐粒子的相位偏移 `i × 0.013` 让布面各处起伏不同步；`maxSpeed` 是 `simUniforms.ts` 的常量 6 m/s。

### 2.2 求解

四种约束共用同一求解核，区别只在绑定的批次：

```wgsl
let wSum = posInvMass[c.p0].w + posInvMass[c.p1].w;
if (wSum == 0.0) { return; }                       // 两端均固定
let diff = (length(delta) - c.restLength) / (length(delta) * (wSum + c.compliance));
predicted[c.p0] = p0 + delta * diff * w0;
predicted[c.p1] = p1 - delta * diff * w1;
```

并发写依靠图着色而不是原子操作：同批内任意两条约束不共享粒子，可直接并行写；批次之间在同一 encoder 里按顺序 dispatch，后一批读到的是前一批修正过的位置。

> **注**：改动约束时若与同批粒子重叠就会引入写冲突，图着色是这套无原子操作写法的前提。

### 2.3 碰撞

碰撞体是解析胶囊与一个地面平面，逐粒子做距离投影（§2.3.1）；模特碰撞开关不改 dispatch（§2.3.2）。

#### 2.3.1 胶囊与穿透修正

```wgsl
struct Capsule {
  a: vec4<f32>,   // xyz = 线段起点, w = 半宽 rx
  b: vec4<f32>,   // xyz = 线段终点, w = 半深 rz（为 0 时回退到 rx）
};
```

- 程序化模特按测量参数分段摆胶囊（躯干四段、颈、头、双腿、双臂加肩球，合计约 16 根）；导入模型由 `avatar/sdf/meshCapsuleFitter.ts` 从网格拟合，默认最多 300 根，贴合度受这个数量限制。
- 粒子遍历全部胶囊，`pointSegmentClosest` 求到线段的最近点，再取穿透最深的一根。
- 截面是椭圆（身体前后薄、左右宽）：方向半径按 `t = atan2(off.z, off.x)` 在 rx 与 rz 之间插值，`r = rx·rz / √((cos t·rz)² + (sin t·rx)²)`。
- 实际间隙是 `SURFACE_OFFSET + clothThickness`：`clothThickness` 由 `packCollideParams()` 从 `SimulationConfig.clothThicknessCm` 换成米写进 uniform，`d = |off| − r` 小于该间隙时把粒子推到 `最近点 + 法向 × (r + 间隙)`。
- 随后做摩擦：把切向位移拉向子步起始位置（`CONTACT_FRICTION = 0.5`），法向分量不动。
- 体素 SDF 与 3D 纹理方案待完成。

> **注**：穿透排查先看线框模式下胶囊是否贴身——导入模特的碰撞精度上限由胶囊数量决定，不是网格精度。

#### 2.3.2 地面与碰撞开关

同一段代码接着处理地面：`y < floorY + SURFACE_OFFSET + clothThickness` 的粒子钳到平面上，同样带切向摩擦。

地面始终生效，`floorY` 是 `ClothSimulator` 的私有字段，当前恒为 0，既没有写入方也没有界面入口；模特碰撞开关不改变 dispatch，`packCollideParams()` 在 `avatarCollision` 为假或没有胶囊时把 `capsuleCount` 写成 0，着色器的胶囊循环自然跳过。

> **注**：布料之间的碰撞不在 GPU 上，而是回读之后的一次 CPU 近邻投影（§2.6）；`selfCollision` 为假时这一遍完全跳过。

### 2.4 速度更新

```wgsl
if (prev.w == 0.0) { return; }                     // 固定粒子
var vel = (predicted[i].xyz - prev.xyz) / dt;       // v = (x̃ − x_prev) / dt
vel *= (1 - particleDamping[i]);                     // 阻尼（逐粒子，取自各片材质）
if (length(vel) > maxSpeed) vel = normalize(vel) * maxSpeed;   // 限幅
velocity[i] = vec4(vel, 0);
posInvMass[i] = vec4(predicted[i].xyz, prev.w);     // 位置回写，保留逆质量
```

### 2.5 法线

三段式，只在所有子步之后执行一次：

```
CLEAR_NORMALS  逐粒子清零
NORMALS        每个三角形一个 invocation：n = cross(p1 − p0, p2 − p0)（未归一化 = 2 倍面积）
               三个顶点各自累加 → 面积加权顶点法线
NORMALIZE      逐粒子归一化，长度 ≤ 1e-7 时回退 (0, 1, 0)
```

- 累加是非原子的读-改-写：共享同一粒子的两个三角形 invocation 并发写入时，其中一次的贡献会丢失。
- 丢失的是完整的一次读回值而不是撕裂数据（每个槽位是 4 个连续 f32），影响仅限顶点法线权重略有偏差，不会产生 NaN，因此没有改用原子操作或按粒子分批。
- 朝向取决于三角形绕序，制版时轮廓保持逆时针（05 §1.1）。

### 2.6 自碰撞（CPU 后处理）

布料之间的碰撞不在 GPU 子步里，而是回读之后的一次 CPU 近邻投影：`readback()` 把位置拷进 `readPositions` 之后、返回之前调用 `sim/selfCollision.ts` 的 `SelfCollisionSolver.resolve()`。该模块是纯逻辑、可单测，不依赖 GPU。

```
cellSize   = max(clothThickness, 1 cm)          // 哈希格边长
tableSize  = 不小于粒子数 × 2 的 2 的幂
期望间距   = clothThickness + |layerA − layerB| × layerSpacing
每轮：重建空间哈希 → 遍历邻格收集接触对 → 按逆质量推开 → 累加结果写回位置（默认 2 轮）
```

- 哈希是均匀网格 + 计数 / 前缀和 / 填表三遍，槽位由 `Math.imul` 混合整数格坐标；查邻居时核对候选粒子自己的格坐标，槽位冲突不会误判。
- 逆质量 0（固定点）不移动，只把另一端推开；两端都固定时整对跳过。粒子与自身、重复方向的对都因 `j > i` 只处理一次。
- 同层只用布料厚度；层差越大期望间距越大，外层衣物因此被推开得更远（§2.6.1）。
- 搜索半径由最大层差换算、封顶 2 圈；期望间距同时封顶在「圈数 × 格边长」，超过这个距离的层差不再继续拉远。
- 每帧候选对上限 160 000，计数跨迭代累计；超限时跳过剩余对并只打一次开发日志。
- 修正后的位置写回 `posInvMassBuf`（保留逐粒子逆质量），同一份数据同步进 `readPositions`；`prevPosBuf` 不写回，速度沿用 UPDATE 的结果，下一子步从修正位置起算，避免速度尖峰。
- 法线仍是 GPU 在修正之前算的，只比位置滞后一次修正量；不为此重算法线。
- 修正结果出现 NaN/Inf 时丢弃该粒子的这次修正并只警告一次；输入位置本身非有限的粒子不进入哈希。
- scratch 缓冲（格计数、前缀和、条目表、逐粒子位移）按粒子数在构造时分配一次，每帧复用。

#### 2.6.1 碰撞层与层间距

`Panel.collisionLayer`（0–9，缺省 0）在 `MergedCloth.build()` 写进 `ClothSimInput.panels[i].collisionLayer`，`computeParticleLayers()` 展开成逐粒子 `Uint8Array`。期望间距是两粒子所属片层差的函数：

```
spacing = clothThickness + |layerA − layerB| × layerSpacing
```

同层片之间只剩布料厚度，层差每加 1 就多分开一个层间距（默认 0.4 cm）。0 是最内层，外层片设更大的值即可让外层包住内层。碰撞层参与 `panelGeometrySignature()`，改动会让该片走一次增量重建并 `rebaseGeometry()`，求解器因此立刻拿到新的层表。

碰撞层可自动识别：`pattern/auto/autoLayer.ts` 的 `inferCollisionLayers()` 按缝合连通性把版片分组（被缝合连在一起的片属同一件衣物），再按各组平均环绕松量从内到外排层；`AutoAssignCollisionLayersCommand` 把它批量写回各片，作为可微调的初始层。

### 2.7 合身分析

合身热图复用模特碰撞体的 CPU SDF，不经过 GPU：

- `render/analysis/fit.ts` 的 `computeFitField(positions, sdf, options)` 逐顶点调用 `evalSDF()`；`positions` 是模拟的米制坐标，结果乘 100 后以厘米返回。负值表示在胶囊内部。
- `fitStats(field)` 按 `tightCm` 与 `looseCm` 分四类并给出最小 / 平均 / 最大间隙；`fitColor()` 是红→橙→绿→蓝的纯函数，供桌面与手机共用。
- `FitOverlay` 与布料共用同一个 `BufferGeometry`，只额外挂一条顶点色属性；材质按版片槽位重复同一份 `MeshBasicMaterial`，因此隐藏版片的 geometry group 仍然生效。开启时主布料网格隐藏，关闭即恢复。
- `GarmentEngine.setFitCheck()` 负责切换，`refreshFit()` 每 6 帧在最近一次回读位置上重算一次；`EngineSync` 把 `FitStats` 写进 `simStore`，UI 只读。CSV 在 `render/analysis/fitReport.ts`，由渲染标签的按钮下载。
- 阈值只影响配色和分类，不参与求解；热图法线沿用当前回读法线，不额外重算。

### 2.8 应变分析

应变换算在 CPU 上完成，同样不经过 GPU：

- `render/analysis/strain.ts` 的 `computeVertexStrain(rest, current, indices)` 逐顶点累加每条相邻边的相对长度变化，`rest` 是各片 `positions2D` 换算米制后的平坦合并位置（引擎侧 `mergedRestPositions()` 拼接），`current` 是最近一次回读位置；`strainStats()` 给最小 / 最大 / 平均绝对值，`strainColor()` 是蓝（压缩）→ 白（零）→ 红（拉伸）的纯函数。
- 应变热图与合身热图共用同一个 `FitOverlay` 的顶点色属性（一次只显示其一）：`FitOverlay.updateStrain(strain, min, max)` 把应变按色标范围上色，`GarmentEngine.setStrainCheck()` 切换、`refreshStrain()` 每 6 帧重算，结果经 `simStore.strainStats` 交给渲染标签。
- 色标上下限（缺省 −0.25 / 0.25）只影响配色，不参与求解；CSV 在 `render/analysis/strainReport.ts`，由渲染标签的按钮下载。它与合身热图在 UI 层互斥（`uiStore.setDisplayMode()` 只保留一个热图开关）。

## 3. CPU 端编排

GPU 侧的 pass 由 CPU 的一次 `step()` 驱动；位置改写与拾取查询都基于同一份 CPU 位置缓存。

### 3.1 接口

```typescript
// sim/clothSimulator.ts —— device 由构造参数提供（与视口渲染器同一块 GPU 设备），destroy() 统一释放
class ClothSimulator {
  constructor(device: GPUDevice)
  setup(input: ClothSimInput, avatarSDF: AvatarSDF | null, config: SimulationConfig): Promise<void>
  step(config: SimulationConfig, fabric: FabricPhysics): void
  readback(): Promise<{ positions: Float32Array; normals: Float32Array }>
  getReadbackPositions(): Float32Array
  getPinnedParticles(): readonly number[]
  updateMaterialPhysics(physicsByPanel: FabricPhysics[], positions: Float32Array): boolean
  setSeamConstraints(constraints: Constraint[]): void
  setCreaseEdges(creaseEdgesByPanel: readonly number[][]): boolean
  rebaseGeometry(input: ClothSimInput, initialPositions: Float32Array, livePositions: Float32Array): void
  reset(initialPositions: Float32Array): void
  setPositions(positions: Float32Array): void
  setSeamProgress(progress: number): void
  setParticlePin(index, pinned) / setParticlePins(indices, pinned): Promise<boolean>
  pickNearestParticle(origin, dir, maxDistance) / pickNearestAtPoint(point, maxDistance, panelSlot)
  destroy(): void    // 释放自己创建的全部 GPUBuffer（含约束批次与 solve uniform），设备生命周期由渲染器管理
}
```

### 3.2 一次帧步的编码

```
substeps = max(1, round(config.substeps));  subDt = config.dt / substeps
每个子步（一个 encoder + 一次 submit）：
  writeBuffer(integrateParams, packIntegrateParams(subConfig, fabric, pc, subTime))
  writeBuffer(updateParams,    packUpdateParams(subConfig, pc))
  dispatch integrate(pc)
  repeat config.constraintIterations 次：逐批 dispatch solve(solveBatchCounts[s])
  writeBuffer(collideParams,   packCollideParams(subConfig, pc, capsuleCount, floorY))
  dispatch collide(pc); dispatch update(pc)
所有子步之后（第二个 encoder）：
  dispatch clearNormals → normals(triangles) → normalize
  copyBufferToBuffer(posInvMassBuf → readbackBuf)
  copyBufferToBuffer(normalsBuf → readbackNormalsBuf)
readback()：
  map 两份缓冲 → 填 readPositions / readNormals → unmap
  selfCollision 为真时执行 CPU 近邻投影（§2.6），修正结果 writeBuffer 回 posInvMassBuf
  返回 readPositions / readNormals
```

- 每个子步单独提交是必需的：`queue.writeBuffer` 只保证相对于 submit 的顺序，全写在一个 encoder 里会让后面的子步读到同一份 uniform。
- `step(config, fabric)` 的 `fabric` 只写入 `INTEGRATE` 的 SimParams；阻尼不再来自它，`setup()`、`updateMaterialPhysics()` 与 `rebaseGeometry()` 把逐粒子阻尼写进 `dampingBuf`（§2.4）。逐片的刚度与克重已经固化在约束柔度和逆质量里（§1.3.2、§5.4），不需要每帧传。
- `step()` 每帧把 `selfCollision`、`clothThicknessCm`、`layerSpacingCm` 换成米记进求解器，`readback()` 的后处理读这一份；改滑条不需要重建。
- 帧末回读与主线程消费见 03 §2.2。

### 3.3 位置改写

| 方法 | 行为 |
| --- | --- |
| `reset(initialPositions)` | 位置回初始值，逆质量取自 `initialPosInvMass`（镜像了实时 PIN），速度清零，`time` 归零，缝合进度回 0 |
| `setPositions(positions)` | 覆盖位置、清零速度、保留 `initialPosInvMass` 里的逆质量 |
| `setSeamProgress(p)` | 每条缝合约束的静止长度按 `open × (1 − p)` 重写，图着色不变，直接 `writeBuffer` 覆盖原批次缓冲 |

三者都调 `cachePositions()`：把新位置写进 CPU 缓存 `readPositions` 并递增 `positionsVersion`，让拾取网格失效重建。

CPU 缓存因此在任何位置写入后都是可用的拾取数据源，而不只在模拟执行过之后；默认状态是暂停的，若缓存只由 `readback()` 填充，第一次打 PIN 就没有数据可查。

`updateMaterialPhysics(physicsByPanel, positions)` 是运行中换材质的路径：

1. 以 setup 时记下的 `constraintDt` 重建约束。
2. 逐类型 `rewriteBatches()` 就地覆盖（条数、批数或批长对不上返回 false，由调用方回退到完整 `setup()`）。
3. 重算 `baseInvMass` 并把未固定粒子的逆质量镜像进 `initialPosInvMass`。
4. `setPositions()` 保留当前形态。

> **注**：该路径不重建布料、不重置模拟。

### 3.4 拾取

`sim/picking.ts` 在 CPU 缓存的位置上做两种查询：

`pickNearest` 用射线垂距加深度容差，`pickNearestToPoint` 用球形查询并可用 `panelSlot` 限定所属片。

`ParticleGrid` 是均匀网格索引，`positionsVersion` 变化时重建。视口侧的三步拾取顺序（表面射线优先）见 [03-渲染管线](./03-渲染管线.md) §7.3。

## 4. 固定点（Pinning）

固定即逆质量归零，粒子被积分与更新跳过（§4.1）；改固定集用一次批量 dispatch 完成（§4.2），界面侧的小黄点另有真值来源（§4.3）。

### 4.1 表示

- 逆质量 `w = 0` 即固定：INTEGRATE 与 UPDATE 跳过这些粒子，SOLVE 里两端都固定的约束直接返回。
- 未固定粒子的逆质量来自所属片的克重（§5.4）。
- 初始固定点由 `ClothSimInput.pinnedIndices` 在 setup 时写入；`initialPosInvMass` 镜像实时固定集，因此 `reset()` 后当前 PIN 仍在。

### 4.2 批量 SET_PIN

```typescript
// clothSimulator.ts
async setParticlePins(particleIndices: readonly number[], pinned: boolean): Promise<boolean> {
  if (!initialized) return false;
  if (indices.length > particleCount) return false;
  if (任一索引非整数或越界) return false;          // 校验先于任何改动 → 不会留下半改状态
  for each index: invMasses[k] = pinned ? 0 : baseInvMass[index];
                  initialPosInvMass[index*4+3] = invMasses[k];
                  pinnedSet add / delete
  dispatchSetPin(indices, invMasses);              // 一次 writeBuffer × 2 + 一次 submit + await onSubmittedWorkDone
  return true;
}
```

- 一次提交覆盖整份清单：拔掉的粒子各自回到所属片的克重而不是同一个常量，因此一批点仍能只提交一次。
- 批量入口是必须的：逐个提交时每个点都要 `await onSubmittedWorkDone()`，而模拟播放时队列每帧都被重新填满，N 个固定点至少等 N 个帧周期，顶部假缝带通常是上千个点。
- 「清除PIN」因此走 `GarmentEngine.clearPins()`：一次 `setParticlePins(全部固定点, false)` 加一次 `pinMarkers.clear()`，不做逐点循环。

### 4.3 与标记球的关系

`pinMarkers`（`core/engine/pinMarkers.ts`）是小黄点的真值。

- 手动打点以它为准：点已经假缝住的粒子时（逆质量本来就是 0）也会落下小黄点，不会因为已经固定而被当作重复操作丢弃。
- `simStore.pinsVersion` 在打点、拔点、清除与重建时递增，3D 工具条的 `PIN 徽标：手动 n · 固定 m` 由此重读——前者是小黄点数，后者是求解器里的固定点总数（含假缝带）。
- 重建求解器（工具条「重建网格」）时 `initSimulator()` 用 `carriedPinIndices()` 把当前有小黄点的粒子并入新的 `pinnedIndices`，超出新粒子数的标记一并删除。

## 5. 引擎侧编排

引擎把工程数据变成一次可执行的模拟：构建链产出三份位形，着装动画分三阶段推进，缝纫线、面料参数与发散处理各自独立。

### 5.1 从工程到一次模拟

#### 5.1.1 构建链与初始位形

```
buildFromProject(project)                                    // garmentEngine.ts
  resolutionCm = scene.simulation.meshResolutionCm ?? DEFAULT_MESH_RESOLUTION_CM
  逐片 buildPanelMesh(pattern, panelId, resolutionCm)        // 05 §3
  MergedCloth.build(project, panelMeshes, landmarks)         // core/engine/mergedCloth.ts
  createRenderMesh(project)                                  // 布料网格 + 材质槽 + 缝纫线叠画
```

- `MergedCloth.build()` 逐片取位形：`InitialPose.posedPositions3D()`（`drape` 环绕或 `placement` 平铺，再叠 `panel.transform`）→ `initialPositions3D()`。
- 只有环绕摆放的片再过 `explodeOffBody()`（`pattern/drape/explodedLayout.ts`），沿该片中心的模特径向刚性推出 `EXPLODE_OFFSET_M = 0.07`；带 `placement` 的平铺片原样返回。
- 刚性位移不改变片内任何距离，因此结构/剪切/弯曲约束在这个位形下无应力，只有缝合对被拉开。
- 于是各片已经围合成衣、彼此却仍明显分开，缝纫线连的是哪两条边一眼可辨；这就是着装动画的起点形态（§5.2）。

> **注**：换初始位形时只能用刚性变换。把版片压到别的位形（例如 2D 排样的共面平铺）会留下巨大初始应变，模拟启动即飞出画面。

#### 5.1.2 三份位形

| 位形 | 来源 | 用途 |
| --- | --- | --- |
| `positions` | 上面的初始位形（合并后） | 模拟起点、渲染网格初值、`reset()` 的目标 |
| `dressPositions` | 环绕姿态（未推出）经 `collapseSeamPairs()`，每对缝合顶点折到中点、默认 8 轮 | 着装第二阶段（glide）的滑动目标 |
| `pinnedIndices` | `InitialPose.topBandParticles()`：取该片 2D 高度顶部 12% 的粒子 | 假缝带；袖子（`pinTop` 为 false）与平铺片返回空数组 |

#### 5.1.3 增量重建的三项检查

改一次版型不应该付一次全量重建的代价。`GarmentEngine.syncFromProject(project)`（`core/engine/garmentEngine.ts`）按三份签名决定做到哪一层：

| 签名（`core/engine/clothSignatures.ts`） | 变了意味着 | 走的路径 |
| --- | --- | --- |
| `panelGeometrySignature(project, panelId)` / `geometrySignatures(project)` | 某片的轮廓、缝份、网格边长、碰撞层变了 | 只重 build 变化的片，删掉已不存在的片，再合并 |
| `clothLayoutFingerprint(input, seamPairCount)` | 粒子总数或缝合对总数变了 | 必须换 `ClothSimInput`：`needsSimulatorRebuild()` 为真时视口重建求解器（`initSimulator()`） |
| `constraintSignature(project)` | 缝合区间/锚点/缩缝/`closing` 省道/折痕线变了，但粒子布局不变 | `setSeamConstraints()` 与 `setCreaseEdges()` 就地换批，`rebaseGeometry()` 把当前形态搬到新几何上 |
| `physicsSignature(panelIds, project)` | 只有材质刚度/克重变了 | `updateMaterialPhysics()` 就地重写约束批次，不重建几何 |

- 粒子状态（位置、前一帧、预测、逆质量）由 `ClothSimulator.rebaseGeometry(input, initialPositions, livePositions)` 保留，所以拖动一个顶点不会让布料回弹到初始平铺形态。
- 判定全在签名比较上，没有任何防抖定时器或延迟重启：一次命令的改动在同一帧内就生效（同 §5.5 与 06 §5.3）。
- 换码（`ApplySizeCommand`）改的是几何签名而通常不改布局指纹，因此走增量重建；属性面板的「用此码」额外调用 `resetSimulation()`，让新尺寸重新垂坠。

#### 5.1.4 编辑预览（`previewEditPattern`）

2D 拖动期间工程还没提交，但 3D 可以先跟着动。`GarmentEngine.previewEditPattern(project, tier)` 用干跑版型重 build 网格并重画，规则与增量重建的三项检查不同：

- **不写** `appliedGeometry`、**不写** `simulatorLayout`，也不调 `initSimulator()` / `resetSimulation()`——预览只是借一遍已提交的片网格（`panelMeshes` 在 `finally` 里换回去），因此松手后那次真提交仍按 §5.1.3 完整走一遍。
- 档位换成分辨率：`低精度` 用 `clothConstants.ts` 的 `PREVIEW_COARSE_RESOLUTION_CM = 6` 重 build 每一片，粒子总数变了，带不回垂坠，松手后重新垂坠；`全精度` 用工程自己的 `meshResolutionCm`，且只重 build 几何签名与已提交不同的片，其余借用已有网格，所以一帧只三角化被拖的那片。
- 位置搬运按粒子数对齐：`lastGoodPositions` 的长度等于新布局的 `particleCount * 3` 时才搬——`全精度` 走 `carryParticleRanges()` 并在布局指纹未变时 `rebaseGeometry()`，求解器跟着几何走；拖完回到提交版型时（每个片都借到了自己的网格）把活的位置整体贴回，因此一次没有净改动的拖动不会把粗网格留在屏幕上。
- `stepSimulation()` 的回读做了一次长度检查：回读长度与当前绘制位置数不一致（预览网格更粗）就跳过这一帧，避免把细网格的结果写进粗网格；求解器本身照常推进。
- 每帧最多提交一次预览（`EngineSync` 在帧循环里消费队列），拖动中的多次 pointermove 合并为一次；提交一旦到达就丢弃预览队列。通道与档位 UI 见 06 §5.3.1。

### 5.2 三阶段着装

参数全在 `core/engine/dressingStages.ts`，帧编排全在 `core/engine/dressingController.ts` 的 `DressingController`（引擎只提供求解器步进与位置读写接口）；视口每帧只推进一帧，画面是连续动画而不是瞬间围合。

```
beginDrape(project)          // resetSimulation() + drapeRun = { physics: primaryPhysics, base: scene.simulation, stage:'sew', frame:0 }
每个阶段共用 stageConfig()：gravity = 0、dt = 1/60、avatarCollision = true，只换 constraintIterations

stage 'sew'    setSeamProgress((frame+1)/SEW_FRAMES=26)，迭代 SEW_ITERATIONS=8
stage 'glide'  setPositions(glideTowards(lastGood, dressPositions))，DRESS_GLIDE=0.16，DRESS_FRAMES=34 帧，GLIDE_ITERATIONS=6
stage 'settle' 零重力松弛，SETTLE_ITERATIONS=15，RELAX_FRAMES=12 帧 → dressed = true

stepFrame(project)           // EngineSync 每帧调一次：动画未完→动画帧；已着装→常规物理；未着装→先 beginDrape()
```

- sew 阶段靠约束收缩把两片拉到一起；glide 阶段每帧覆盖位置，把已缝合的整体沿 16% 的剩余距离推向 `dressPositions`，模特碰撞负责把它压到体表；settle 阶段不再动位置，只做高迭代松弛。
- glide 期间若位置数组长度与目标不符（拓扑已变），动画直接中止而不是画出一帧错位。
- UI 侧的 `isDraping` / `isDraped` 是引擎同名状态的镜像，由渲染循环每帧同步（01 §4.2），因此「播放」从未着装状态按下也会先走着装动画。

### 5.3 缝纫线叠画

`MergedCloth.seamPairs` 记录每对闭合粒子、初始敞开距离与所属记录 id；`SeamThreads.update()`（`core/engine/seamThreads.ts`）每帧用回读位置刷新一个加色混合的 `THREE.LineSegments`：

- 段色取该缝口的 `threadColor`；
- 亮度按 `gap / (open × 0.3)` 衰减，合拢后为黑色即不可见；
- `stitchVisible` 为假的缝口直接把两段顶点色写成黑色，加法混合下同样不出现；
- 收省产生的对带的是 `dartId`，`seams` 里查不到记录，因此走 `THREAD_FALLBACK` 颜色、始终显示，并且配对集合增删时几何体会按 `pairs.length` 重建而不是越界写入。

对象标签 · 对象块的「可见性」开关因此只改一个显示字段：3D 调 `GarmentEngine.applySeamStitchVisibility()` 重刷叠加层，2D 随工程提交重绘时跳过这条缝口，不重建布料、不重置模拟。

### 5.4 面料参数生效路径

```
MergedCloth.build() 给每片写上 fabricForPanel(project, panelId)?.physics ?? FALLBACK_PHYSICS
  → ClothSimInput.panels[i].physics
  → buildPanelConstraints() 用该片刚度换算逐约束柔度（§1.3）
  → computeBaseInvMass() 把该片克重换算成逐粒子逆质量（simTypes.ts）：
        invMass = 1 / max(massPerArea, 1) × 100
        落在所有片之外的粒子用 180 g/m² 的默认值，避免被误判为固定
模拟运行中改材质 → GarmentEngine.applyFabrics() 比物理签名 → refreshClothPhysics()
  → ClothSimulator.updateMaterialPhysics()（§3.3）
  折痕刚度 creaseStiffness 也在这条路上：它只改折痕约束的柔度分组，不新增粒子
版型标记变了（缝合区间、锚点、缩缝、省道 closing、折痕线增删）
  → GarmentEngine.refreshConstraintSets() 比 constraintSignature()
  → MergedCloth.refreshConstraintSets() 重算约束与 seamPairs
  → installConstraintSets() 下发 setSeamConstraints() / setCreaseEdges()（§5.1.3）
```

> **注**：阻尼逐片生效——`computeParticleDamping()` 按 `vertexOffset + vertexCount` 把每片的 `damping` 写进逐粒子 buffer，落在所有片之外的粒子用第一份材质的值，没有材质时用棉预设 0.02。刚度与克重同样逐片。

### 5.5 步进与非有限帧

```
GarmentEngine.stepSimulation(config, fabric)        // garmentEngine.ts
  若 stepping 已在进行中 → 直接返回（一帧不会套一帧）
  simulator.step() → await simulator.readback()
  firstNonFinite(positions) >= 0 → 打一次 console 警告并 return（保留上一帧绘制）
  ClothMeshManager.updateFromSim(positions, normals)
  lastGoodPositions ← positions
  seamThreads.update() / pinMarkers.sync()
```

控制台出现该警告说明数值发散，不是渲染问题；`lastGoodPositions` 是后续所有「用当前形态」操作的依据，材质换物理、glide、缝纫线刷新都读它。

> **注**：出现 NaN/Inf 时求解继续推进，只是丢弃这一帧的绘制结果；界面上表现为布料停住不动，而不是报错停止。

## 6. 性能与稳定性

一次帧步的成本由 dispatch 数与粒子数决定（§6.1），不飞散依靠纯几何断言与坏帧丢弃（§6.2），界面只暴露其中一部分旋钮（§6.3）。

### 6.1 成本模型

- 一次帧步的 dispatch 数 = `substeps × (1 + constraintIterations × 批次数 + 2)` + 3（法线）。
- 粒子相关的三个 pass 都是 `ceil(pc / 256)` 组，SOLVE 按批条数，法线累加按三角形数。
- 自碰撞不增加 dispatch：它是回读后的 CPU 遍历，默认 2 轮投影、每帧最多 16 万候选对，关掉即整段跳过（§2.6）。
- 常见工程在数千到一万粒子量级（T 恤在全局网格边长 1.5 cm 下约万级）。
- 默认 `substeps: 4` 加 `constraintIterations: 5` 意味着每帧 20 遍约束求解；增加子步比增加迭代次数更划算——子步缩短 dt 从而降低单步形变量，迭代只是把同一批约束多解几遍。

> **注**：下表是目标值而不是实测结果——仓库没有 GPU timestamp query；CPU 自碰撞遍有单独的基线脚本 `npm run perf:baseline`（`scripts/selfcollision-baseline.mjs`）与 `test:run` 里的宽松性能回归门禁（`test/sim/selfCollisionPerf.test.ts`），GPU 侧的自动化基准仍未建立（见 00 §7）。

| 粒子数 | 配置 | 目标 |
| --- | --- | --- |
| 5,000 | 5 迭代 | 60 fps |
| 10,000 | 5 迭代 × 4 子步 | 60 fps |
| 20,000 | 3 迭代 | 30 fps |

### 6.2 稳定性策略

| 手段 | 位置 | 作用 |
| --- | --- | --- |
| 速度限幅 | UPDATE，`maxSpeed = 6 m/s` | 裁掉超速分量，防止粒子飞散 |
| 非有限帧丢弃 | `stepSimulation()` 的 `firstNonFinite()` | 单个 NaN 会让整件服装瞬间消失，丢弃该帧并保留上一帧有限数据继续绘制 |
| 子步切分 | `step()` 把 `config.dt` 除以 `substeps` | dt 本身不在运行时限幅，默认固定 1/60 |
| 柔度参数化 | XPBD compliance | 刚度与 dt 解耦（§1.3.2） |
| 静止长度与初始位形同源 | `buildMeshConstraints(panel.positions3D)` | 初始位形只能是该位形的刚性变换，否则整套约束带上巨大初始应变（§5.1.1 的注） |
| 碰撞表面偏移 | `SURFACE_OFFSET = 0.005` 加布料厚度 | 粒子始终留在胶囊与地面外侧至少一个厚度 |
| 自碰撞候选对上限 | `SelfCollisionSolver`，160 000 对/帧 | 密集褶皱时截断后处理而不是拖垮帧率，只打一次日志 |
| 自碰撞非有限保护 | 同上 | 修正结果非有限就丢弃该粒子的修正，位置保持原样 |
| 退化法线处理 | `NORMALIZE` | 长度 ≤ 1e-7 时给 (0,1,0)，避免零除法线影响光照 |

> **注**：稳定性靠静止长度与位形不飞散这类纯几何断言，加上人工观察；WebGPU 求解器本体不能在 Node 测试里运行（00 §2.2、§6.1）。

### 6.3 调参入口

| 参数 | 界面 | 生效方式 |
| --- | --- | --- |
| 拉伸/弯曲/剪切刚度、克重 | 模拟器标签 | 就地改写约束柔度与逆质量，不重建、不重置（§5.4） |
| 折痕刚度 | 模拟器标签（0–1，缺省 0.85） | 只改折痕约束那一批的柔度，不重建、不重置（§1.3.4） |
| 缝合区间、对位点、缝型、强度、乙边反向 | 对象标签 · 缝合 | 重排缝合约束（`setSeamConstraints`），粒子布局不变时不重建、不重置（§5.1.3） |
| 收省（省道勾选） | 对象标签 · 省道 | 给省边生成静止长度为 0 的缝合对，同样只走约束签名这条就地路径（§1.3.3） |
| 阻尼 | 模拟器标签 | 逐片写进粒子阻尼 buffer，就地生效（§2.4） |
| 重力 y、风速、迭代次数 | 工程标签 · 全局模拟 | 实时 |
| 全局网格边长 | 工程标签 · 全局模拟 | 批量写入全部版片的网格密度，松手重建布料并重置模拟 |
| 布料与模特碰撞 | 模拟器标签（模特行） | 实时（胶囊数写 0） |
| 布料自碰撞、布料厚度、层间距 | 工程标签 · 全局模拟 | 实时；厚度同时改模特与地面碰撞距离，自碰撞是 CPU 后处理（§2.6） |
| 碰撞层 | 模拟器标签 · 布料网格（选中版片，0–9） | 改动该片的几何签名，走一次增量重建后生效（§2.6.1） |
| `dt` / `substeps` | 无 | 常量 1/60 与 4 |
